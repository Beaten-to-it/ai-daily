## TL;DR

- Microsoft Research가 IDEAS Lab(중국 런민대)과 함께 만든 **Flint**는, AI 에이전트가 스케일·축·간격·레이아웃 같은 저수준 파라미터를 손대지 않고 **간단하고 사람이 고치기 쉬운 스펙**만으로 보기 좋은 차트를 안정적으로 만들게 하는 "시각화 중간 언어(intermediate language)"다.
- 컴파일러가 **데이터 + 시맨틱 타입 + 차트 스펙(차트 유형·인코딩)**만 받아 나머지 저수준 설정을 자동 도출하며, **46종 차트 유형**을 **Vega-Lite·ECharts·Chart.js** 세 백엔드로 렌더링한다(갤러리에 83개 예제).
- npm(TS/JS)로 설치하고 **에이전트 워크플로용 MCP 서버**를 제공하는 **오픈소스** 프로젝트로, 차트 디자인 변경이 "차트 유형 바꾸고 인코딩 다시 묶기"만으로 끝나 LLM이 생성·수정하기 쉽게 설계됐다.

## 무엇인가

차트를 코드로 그려본 사람은 안다. 막상 데이터를 붙이면 축 포맷이 깨지고, 날짜 파싱이 어긋나고, 범례가 캔버스를 뚫고, 색 스킴이 의미와 안 맞는다. Vega-Lite·ECharts 같은 라이브러리는 강력하지만 그만큼 손봐야 할 저수준 파라미터(scale, axis, spacing, layout)가 많다. LLM 에이전트에게 "차트 만들어줘"를 시키면 바로 이 지점에서 무너진다 — 장황한 설정을 다 채워야 하고, 하나만 틀려도 결과가 흉해진다.

Flint는 그 사이에 **중간 언어**를 하나 끼워 넣는 방식으로 문제를 접근한다. 에이전트(또는 사람)는 아래처럼 **콤팩트한 스펙**만 쓴다.

```json
{
  "data": {...},
  "semantic_types": {
    "period": "YearMonth",
    "totalUsers": "Quantity",
    "gameType": "Category",
    "region": "Category"
  },
  "chart_spec": {
    "chartType": "Line Chart",
    "encodings": { "column": "region", "x": "period", "y": "totalUsers", "color": "gameType" }
  }
}
```

이 스펙에는 축 눈금도, 날짜 파서도, 색 팔레트도 없다. Flint 컴파일러가 **데이터·시맨틱 타입·차트 유형·인코딩**을 근거로 필요한 저수준 설정을 채워 **백엔드 네이티브 스펙**(예: 완성된 Vega-Lite JSON)을 만들고 렌더링한다. 위 예시는 지역별 월간 활성 사용자를 시간축 위 small multiples(패싯 라인 차트)로 배치한 결과로 컴파일된다.

핵심을 네 가지로 정리하면:

**1) 시맨틱 타입으로 의미를 지정한다.** Flint는 필드의 "의미"를 `Rank`, `YearMonth`, `Delta`, `Temperature` 같은 시맨틱 타입으로 잡고, 이걸로 파싱·스케일·축·포맷·색 스킴 같은 저수준 설정을 추론한다. 예를 들어 순증가 사용자를 `Profit` 타입으로 두면 시간 파서, 축 포맷, 그리고 **0을 중심으로 하는 발산형(diverging) 색 스킴과 중간값**을 알아서 정한다.

**2) 레이아웃을 자동 최적화한다.** "탄성 레이아웃 모델(elastic layout model)"과 banking 원리에 기반해 크기·간격·배치를 동적으로 조정한다. 그룹 막대 수가 늘어나면 캔버스를 늘리고 밴드 폭을 줄여 밀도가 높아져도 캔버스에 깔끔히 맞춘다 — 스프링이 늘어나는 용기 안에서 안정점을 찾는 것에 비유한다.

**3) 생성·수정이 쉽다.** 깨지기 쉬운 저수준 파라미터가 없으니, 차트 디자인을 바꾸려면 **차트 유형을 바꾸고 시각 인코딩을 다시 묶기만** 하면 된다. 나머지는 컴파일러가 저수준 설정까지 연쇄적으로 반영한다. 원문 예시에선 2000년 미국 인구 분포의 패싯 막대 차트를 차트 유형만 바꿔 피라미드 차트로 전환한다.

**4) 백엔드를 바꿔 낀다.** 46종 차트 유형을 Vega-Lite·ECharts·Chart.js 위에서 지원하며(백엔드별 예제 83개), API·프로그래밍 모델이 제각각인 세 라이브러리를 **하나의 통합 인터페이스** 뒤로 숨긴다. 가령 Vega-Lite에는 네이티브 sunburst가 없는데, 백엔드를 ECharts로 바꾸면 region × gameType × game 계층을 sunburst로 그릴 수 있다.

## 왜 중요한가

제목의 "AI Era"가 마케팅 수사가 아니라 설계 의도다. 지금 에이전트가 차트를 만들 때의 실패는 대부분 "저수준 설정을 정확히 다 채우지 못해서" 생긴다. 자유도가 높은 라이브러리 API는 사람에겐 표현력이지만 LLM에겐 오류 표면이다. Flint의 베팅은 **에이전트가 다뤄야 할 표면을 작고 안정적인 중간 언어로 좁히고**, 오류가 나기 쉬운 나머지는 결정론적 컴파일러에 넘기자는 것이다. "작고 사람이 검수 가능한 스펙"이라는 점도 중요하다 — 에이전트 출력이 장황한 백엔드 JSON이 아니라 사람이 눈으로 읽고 고칠 수 있는 스펙이면, 검토·수정 루프가 훨씬 값싸진다.

백엔드 추상화도 실용적 가치가 크다. 프로덕션에서 시각화 라이브러리를 바꾸는 일은 보통 재작성인데, Flint 스펙을 유지한 채 렌더 대상만 바꿀 수 있다면 라이브러리 종속을 낮추면서 각 백엔드의 고유 기능(예: ECharts의 sunburst)까지 취사선택할 수 있다.

## 어떻게 써먹나

- **에이전트 워크플로**: MCP 서버가 제공되므로, 차트 생성 도구가 필요한 에이전트 파이프라인에 Flint를 MCP로 물려 "데이터 + 의미 + 차트 유형"만 넘기고 렌더는 위임하는 구조를 시도할 수 있다.
- **앱 통합**: TS/JS 프로젝트라면 npm으로 설치해 콤팩트 스펙 → 백엔드 네이티브 스펙 컴파일 단계로 쓴다. 이미 Vega-Lite/ECharts/Chart.js 중 하나를 쓰고 있다면 그대로 렌더 백엔드로 지정.
- **LLM 출력 검증 관점**: Flint 스펙은 필드가 몇 개 안 되고 시맨틱 타입이 명시적이라, 에이전트가 뱉은 스펙을 스키마로 검증·거부하기 쉽다. 자유형 차트 코드보다 grounding·검증 친화적이다.
- 먼저 만져볼 곳: 46종 차트와 83개 예제가 있는 갤러리, 그리고 스펙을 즉석에서 편집·컴파일해볼 수 있는 온라인 에디터. 오픈소스이며 GitHub에서 시작할 수 있다.

한 가지 유의점: 원문에 등장하는 컴파일 결과의 구체 수치(막대 폭 47, step 29, 색 도메인 −84108~84108 등)는 특정 예제 데이터로부터 나온 **출력값**이지 제품 사양이 아니다. 벤치마크·라이선스명·성능 수치는 원문에 없어 확인된 사실로 다루지 않는다.
