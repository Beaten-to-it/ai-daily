중국 AI 랩 Moonshot AI가 7월 16일 아침 **Kimi K3**를 공개했다. 자기네 표현으로는 "2.8조(2.8T) 파라미터의, 지금까지 가장 강력한 모델"이다. Simon Willison이 이 릴리스를 자신의 트레이드마크인 '자전거 탄 펠리컨 SVG' 테스트로 돌려보면서, 릴리스 팩트와 함께 **"이 벤치마크가 이제 무엇을 말해주고 무엇을 못 말해주나"**를 정리한 글이다.

## TL;DR
- Kimi K3는 2.8T 파라미터 "오픈 3T급" 모델이지만 **가중치는 아직 미공개**(7월 27일까지 공개 약속), 지금은 웹/API로만 접근 가능하다. 진짜 뉴스는 성능보다 **가격**: $3/$15(입력/출력 M토큰)로 Claude Sonnet 급, 중국 랩 역대 최고가다.
- 자체 보고 벤치마크는 Opus 4.8 max·GPT-5.5 high는 이기지만 **Fable 5·GPT-5.6 Sol에는 진다** — "1등"이 아니다. Artificial Analysis 기준 Elo 1547(K2.6 대비 +732), 태스크당 $0.94.
- Simon의 결론: 펠리컨 테스트는 이제 **모델 실력 순위와의 상관이 대부분 끊겼다**(에이전트 툴콜을 전혀 안 건드리므로). 그래도 "hello world" 스모크·비용/추론 감·유효 SVG 확인용으로는 여전히 쓸모 있다 — **모델 비교엔 쓰지 마라.**

## 무슨 일이 있었나

Moonshot은 K3를 "첫 **오픈 3T급 모델**"이라 부른다(2.8조를 3조로 반올림한 셈). 이 타이틀은 직전까지 DeepSeek의 1.6T v4 Pro가 갖고 있었다. 파라미터 규모 2.8T는 이전 1T급 모델의 두 배가 넘는다.

**자체 보고 벤치마크**는 K3가 Claude Opus 4.8 max와 GPT-5.5 high를 대체로 앞서지만, Claude Fable 5와 GPT-5.6 Sol에는 밀리는 그림이다. 여기서 "자체 보고"라는 단서를 놓치면 안 된다 — 랩이 자기 모델을 발표할 때 고른 숫자다. 서드파티 Artificial Analysis 리포트의 하이라이트는 이렇다:

- 비공개 롱-호라이즌 지식노동 평가에서 K3의 종합 Elo는 **1547**로, K2.6 대비 **+732점**이며 순위상으론 Claude Fable 5 바로 아래.
- 태스크당 비용 **$0.94**로 GPT-5.6 Sol($1.04)과 비슷하고 Opus 4.8($1.80)의 약 절반. 다만 오픈웨이트 동급들보다는 비싸다.
- Intelligence Index에서 출력 토큰 사용량이 크게 줄어 K2.6보다 **21% 적은 출력 토큰**을 썼다. 또한 Arena.ai Frontend Code 아레나에서는 Fable 5마저 제치고 선두라고 한다.

하지만 이 글에서 가장 실질적인 뉴스는 성능이 아니라 **가격**이다. K3는 입력 **$3/M**, 출력 **$15/M**로, Anthropic Claude Sonnet 라인과 같은 티어이며 **중국 AI 랩이 낸 모델 중 역대 최고가**다. 직전 Kimi K2.6이 $0.95/$4였던 걸 생각하면 상당한 인상이다. "중국 오픈웨이트 = 싸다"는 통념이 흔들리는 지점이다.

## 그래서 펠리컨은 어땠나

Simon은 Moonshot API 키를 새로 파기 싫어서 OpenRouter + `llm-openrouter` 플러그인으로 "자전거 탄 펠리컨 SVG를 그려라"를 돌렸다. 결과 SVG를 그가 직접 판단한 게 아니라, 숫자가 곧 이 모델의 성격을 드러낸다:

- **95 입력 / 16,658 출력 토큰**(그중 13,241이 추론 토큰), 총 **25센트**. 펠리컨 한 마리 그리는 데 25센트다.
- K3는 현재 추론 강도가 **"max" 하나뿐**이고, 그게 티가 난다. 응답 3,417 토큰을 뽑으려고 추론 토큰 13,241개를 태웠다 — 비싸다.
- K3는 이미지 입력을 받으므로, 그렇게 렌더된 SVG를 다시 넣어 alt 텍스트를 생성시켰더니(0.6센트) 상당히 정확한 묘사가 나왔다. **비전은 잘 작동한다.**

토큰 카운팅에서 흥미로운 단서도 나왔다. "Generate an SVG of a pelican riding a bicycle"가 K3에선 **95 입력 토큰**으로 잡혔다 — OpenAI 토크나이저는 10, Anthropic은 Opus 4.6에서 10 정도로 세는 프롬프트다. "hi"만 넣어도 86 토큰이 잡히는 걸로 봐서, **약 85 토큰짜리 숨은 시스템 프롬프트**가 있는 것으로 추정된다(모델은 유출을 거부했다).

## 펠리컨에서 이제 무엇을 배울 수 있나 (핵심)

이 글의 진짜 반쪽은 릴리스 소식이 아니라 **자기 벤치마크에 대한 반성**이다. Simon은 21개월 된 이 펠리컨 테스트에 대해 솔직하다:

> 원래 "이 모델들 비교하는 게 얼마나 터무니없이 어려운지"에 대한 농담으로 시작했다.

그런데 첫 1년쯤은 놀랍게도 모델 실제 실력과 상관이 있었다. **지금은 그 연결이 대부분 끊겼다.** GPT-5.6·Fable 5의 펠리컨이 GLM-5.2에게 밀리는데, 그가 GLM을 좋아하긴 해도 그게 Fable급이라고는 보지 않는다. (그는 랩들이 이 벤치마크를 겨냥해 학습한다고는 여전히 안 믿는다 — 그랬다면 결과가 훨씬 좋았을 것이라고.)

가장 큰 한계는 명확하다: **펠리컨은 오늘날 모델에서 가장 중요한 것, 즉 에이전트 툴 콜링과 대화가 길어져도 툴을 안정적으로 굴리는 능력을 전혀 건드리지 않는다.** 그래서 그의 경고는 단호하다 — **펠리컨으로 모델을 비교하지 마라.**

그럼에도 그가 이 테스트를 계속 돌리는 이유가 남는다. 이 절반을 빼먹으면 글의 요지를 놓친다:

- **모델을 실제로 한 번 돌려보게 만드는 강제 장치.** 펠리컨을 보여준다는 건 그 모델에 프롬프트를 실제로 통과시켰다는 뜻이다(공식 API·OpenRouter·로컬 llama.cpp/LM Studio/Ollama 중 하나로).
- **단일 프롬프트만으로도 모델 성격이 드러난다.** 위 K3 사례처럼 "max 하나뿐인 추론 강도", 비싼 토큰 소모, 숨은 시스템 프롬프트 정황이 프롬프트 한 방에 나왔다.
- 정리하면 펠리컨이 주는 것은 ① 모델 프롬프팅의 "hello world" 연습, ② 간단 작업의 대략적 비용·추론량 추정, ③ **유효한 SVG를 뽑아내고 기하·공간 감각이 있는지** 확인(노트북에서 돌리는 소형 모델일수록 이게 중요하다). 같은 모델 패밀리 내 릴리스 간 비교(K3 펠리컨은 Kimi 2.5보다 확연히 개선)와, "내가 이 모델 써봤다"는 증거 공유용으로도 유효하다.

## 왜 중요한가

- **"중국 = 저가 오픈웨이트" 프레임의 균열.** K3 $3/$15는 Sonnet 티어이고 중국 랩 역대 최고가다. 오픈웨이트 릴리스가 곧 나온다 해도(7/27), 호스티드 API 가격 정책 자체가 가치 프로포지션이 바뀌었음을 보여준다.
- **자기가 만든 지표를 은퇴시킬 줄 아는 규율.** 21개월간 유명해진 벤치마크의 상관이 끊겼음을 공개적으로 인정하고, "비교엔 쓰지 말라"고 못박는 태도는 평가 방법론을 다루는 사람이라면 새겨둘 만하다. 지표는 세상이 바뀌면(에이전트 시대) 수명이 끝난다.
- **단일 프롬프트의 진단력.** 잘 고른 프롬프트 하나가 추론 강도 옵션, 토큰 이코노미, 숨은 시스템 프롬프트까지 노출시킨다는 실증. 무거운 벤치 스위트 전에 값싼 스모크가 먼저다.

## 어떻게 써먹나

- **새 모델이 나오면 '나만의 펠리컨'을 하나 정해 스모크로 돌려라.** 목적은 리더보드 순위가 아니라 ① 실제로 한 번 굴려보기, ② 비용·추론 토큰 감 잡기, ③ 출력 포맷(유효 JSON/SVG/코드)과 기본 능력 확인. Simon처럼 OpenRouter를 쓰면 새 API 키 없이 대부분의 공식 API에 프록시로 붙을 수 있다.
- **비용 감을 토큰으로 환산해 두라.** K3는 추론 강도가 max 하나뿐이라 간단 작업도 추론 토큰을 크게 태운다(펠리컨 25센트). 추론 강도 옵션이 여러 개인 모델이라면 같은 프롬프트를 강도별로 돌려 비용/품질 트레이드오프 매트릭스를 만들어 두면, 프로덕션에서 어느 강도를 기본값으로 둘지 근거가 생긴다.
- **하지만 모델 선택/비교의 실제 기준은 에이전트 툴콜과 롱-컨텍스트 안정성에 두라.** 펠리컨류 단발 프롬프트는 진단용이지 순위용이 아니다. 실제 워크로드(긴 대화에서 툴 반복 호출)로 평가셋을 짜야 한다.
