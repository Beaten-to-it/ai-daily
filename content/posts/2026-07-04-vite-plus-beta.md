VoidZero가 **Vite+**를 베타로 공개했다. 한 줄로 요약하면, 프로젝트마다 손으로 조립하던 프론트엔드 도구들(런타임·패키지 매니저·빌드·테스트·린트·포맷)을 **하나의 진입점과 일관된 명령 체계**로 묶은 통합 툴체인이다. MIT 라이선스 오픈소스이고 특정 프레임워크에 종속되지 않는다.

## TL;DR

- `vp dev / check / test / build / pack / run` 여섯 개 명령이 Vite 8·Vitest·Rolldown·tsdown·Oxlint·Oxfmt를 하나의 체계로 감싼다 — 저장소마다 도구 조합·명령을 새로 익힐 필요를 없앤다.
- 알파 이후 12개 이상 버전·500개 이상 PR을 거쳤고, 공개 저장소 기준 1,300개 이상이 `vite-plus`에 의존한다(Dify·BlockNote·îles·npmx 등).
- 아직 1.0 전 단계 — 원격 캐싱, GitLab CI/CD 지원, 프레임워크·플러그인 호환성, 마이그레이션 범위, 배포 채널이 남은 과제다.

## Vite+가 실제로 하는 일

Vite+의 핵심 발상은 "새 번들러를 하나 더 만든다"가 아니라, **이미 검증된 도구들을 한 스택으로 묶어 같은 명령으로 다룬다**는 데 있다. 진입점은 `vp` 하나이고, 명령마다 뒤에 붙는 도구가 정해져 있다.

- `vp dev` — Vite 8 기반 개발 서버(HMR 포함)
- `vp check` — Oxfmt 포맷 + Oxlint 린트 + 타입 검사를 한 번에
- `vp test` — Vitest 단위 테스트
- `vp build` — Vite 8 프로덕션 빌드
- `vp pack` — tsdown으로 라이브러리 번들링(모범 사례 내장)
- `vp run` — 모노레포를 인식하는 작업 실행기. npm 스크립트나 임의 작업을 지능형 캐싱과 함께 실행

여기서 짚을 지점은 **Vite+가 Vite 생태계를 대체하지 않는다**는 선긋기다. Vite 플러그인은 그대로 Vite 플러그인으로 남고, 프로젝트는 내부적으로 원하던 패키지 매니저를 계속 쓸 수 있다. Vite+는 이 조각들이 "하나의 툴체인처럼" 맞물리게 하는 통합 계층을 얹을 뿐이다. 시작은 새 프로젝트면 `vp create`, 기존 프로젝트면 `vp migrate`다.

## 알파 → 베타 사이에 바뀐 것

원문이 강조하는 개선점은 팀·CI 관점에 몰려 있다.

- **더 똑똑한 캐싱**: `vp run`이 자동 데이터 추적과 Vite가 보고하는 메타데이터를 결합한다. 입력·출력·환경 변수를 수동으로 나열하지 않아도 빌드 캐시가 올바르게 동작한다. 손으로 캐시 키를 관리해 본 사람이라면 이게 가장 실무적인 개선이다.
- **마이그레이션**: `vp migrate`가 더 다양한 앱 설정을 처리하고, **에이전트용 마이그레이션 프롬프트**까지 제공한다.
- **엔터프라이즈**: 조직 템플릿으로 팀 간 설정을 표준화하고, 프록시·커스텀 CA 인식 HTTP로 기업 방화벽 뒤에서도 `vp`가 돈다.
- **크로스 플랫폼**: 주요 OS·셸 대응 강화, `vite-plus` 자체에 180개 이상의 수정.

기반 도구들도 같은 기간에 함께 굴렀다 — Vite 8.1(실험적 전체 번들 모드), Vitest ARIA 스냅샷, Rolldown 1.0(새 플러그인 시스템), tsdown CSS modules, Oxlint 네이티브 React Compiler 규칙, Oxfmt Svelte 포맷.

## 왜 중요한가

프론트엔드 도구 체인은 오랫동안 "각자 다른 프로젝트, 각자 다른 설정, 각자 다른 업데이트 주기"의 조합 지옥이었다. Gulp·Grunt·webpack이 뒤섞인 오래된 저장소를 열어 본 개발자라면 감이 올 것이다. Vite+가 노리는 값어치는 성능 자체보다 **정렬(alignment)**이다.

- 도구 버전이 서로 맞춰진다.
- 설정 공유가 쉬워진다.
- 신규 기여자의 셋업 단계가 줄어든다.
- **CI가 로컬과 똑같은 명령을 돈다** — "내 로컬에선 되는데" 계열 버그의 큰 원인 하나가 사라진다.

이 이점은 팀·코드베이스가 커질수록 복리로 붙는다. 즉 1인 토이 프로젝트보다는, 여러 저장소에 일관된 설정을 강제하고 싶은 팀에게 가치가 크다. npmx의 Daniel Roe는 Vite+가 개발 경험뿐 아니라 CI·리뷰 과정도 빠르게 유지해 준다고 밝혔다.

**커뮤니티 반응(HN 댓글) 참고** — 확정 사실은 아니고 반응 층이다. 댓글에선 이 스택을 "지루하지만 잘 작동하는(boring but works)" 방향의 정석으로 보는 호평(eslint→oxlint, prettier→oxfmt를 Rust로 재작성해 빠르게, jest→vitest로 Vite와 정합)과, 반대편의 회의(이름이 헷갈린다 / "+"가 구독 서비스를 연상시킨다 / Vite의 잦은 메이저 버전 churn을 툴체인 전체로 끌고 오기 싫다)가 갈렸다. VoidZero의 Cloudflare 인수설도 댓글에서 언급됐으나 이는 코멘터 주장 수준이라 여기서는 확정 사실로 다루지 않는다.

## 어떻게 써먹나

전역 `vp` 설치(원문 명령 그대로):

```bash
# macOS / Linux
curl -fsSL https://vite.plus | bash
```

```powershell
# Windows (PowerShell)
irm https://vite.plus/ps1 | iex
```

- 새 프로젝트: `vp create`
- 기존 Vite 프로젝트에서 시도: `vp migrate` — 변경 계획을 먼저 보여주지만, 복잡한 프로젝트는 수동 후속 작업이 필요할 수 있다. **프로덕션 도입 전 마이그레이션 가이드를 먼저 읽어라.**

실무 판단: 지금은 아직 1.0 전이고 원격 캐싱·GitLab CI/CD·일부 프레임워크 호환성이 미완이다. 신규 프로젝트나 도구 조합을 새로 짜기 싫은 팀이라면 지금 붙어 볼 값어치가 있지만, 마이그레이션이 복잡한 대형 프로덕션 저장소라면 1.0의 호환성 격차 정리를 기다리는 쪽이 안전하다. VoidZero 측도 마이그레이션 개발자·프레임워크 저자·대규모 저장소 유지팀의 피드백을 특히 원한다고 밝혔다.
