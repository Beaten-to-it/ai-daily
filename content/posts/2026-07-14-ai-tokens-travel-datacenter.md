## TL;DR

- 2026년 추론(inference)은 전체 AI 컴퓨팅의 약 **2/3**, 배포된 모델 생애 컴퓨팅 비용의 **80~90%**를 차지한다. AI 경제의 무게중심은 학습이 아니라 "목표 지연시간에서의 토큰당 비용"으로 넘어갔다.
- 요청 하나는 토큰화 → API 게이트웨이 → 인증·과금 → 라우팅·스케줄링 → KV 캐시 → GPU/HBM → NVLink·스위치·NIC·Ethernet을 지나 되돌아오는 **15단계** 경로를 통과한다. 이 경로는 연산에 묶인 **프리필**과 메모리 대역폭에 묶인 **디코드**라는 상반된 병목으로 갈린다.
- 고정 품질 기준 토큰 값은 연 중앙값 **약 200배** 싸졌지만(제본스 역설로 총사용량은 폭증), 마진은 HBM 대역폭·NVLink 도메인·광학 부품·전력 같은 **물리적 병목**을 고객 고착으로 전환한 플랫폼에 집중된다.

## 왜 지금 추론이 AI 경제의 본체인가

챗봇, 코딩 에이전트, 검색 요약, 이미지 캡션은 겉모습만 다를 뿐 전부 같은 작업이다. 학습된 모델을 순전파해 다음 토큰을 반복 예측하는 것 — 이게 추론이다. 규모 감각을 잡아주는 숫자가 있다. Google은 2026년 5월 자사 서비스 전반에서 **월 3.2천조(3.2 quadrillion) 개 토큰**을 처리한다고 공개했다. 연환산하면 약 3.8경 개다. 1년 전이 월 480조, 2024년 초가 월 9.7조였으니 1년 만에 7배가 늘었다. 이건 학습 비용이 아니라 "사용자 요청에 응답하는 비용"이다.

추론이 AI 컴퓨팅에서 차지하는 비중은 2023년 약 1/3 → 2025년 절반 → 2026년 약 2/3로 올라왔다. 배포된 모델에서 추론은 요청마다 반복되는 **매출원가(COGS)**이고, 생애 컴퓨팅 비용의 80~90%를 차지한다는 게 업계 경험칙이다. 4대 하이퍼스케일러가 제시한 2026년 자본지출은 약 **7,250억 달러**(전년比 +77%)인데, 이 중 60% 이상이 칩이 아니라 전력·냉각·건물에 들어간다. 추론 전용 실리콘 시장만 2026년 500억 달러를 넘을 전망이다.

수요를 밀어올리는 두 힘이 있다. **추론 시간 확장(test-time scaling)**과 **에이전트 시스템**은 질의당 10~100배 많은 토큰을 태운다. 에이전트 워크플로는 재시도·도구 호출·컨텍스트 재로딩 탓에 단일 요청보다 작업당 5~25배 비싸다. 토큰이 200배 싸졌는데도 총비용이 줄지 않는 이유가 여기 있다 — 싸진 토큰이 더 많은 작업을 열어 사용량 자체를 키우는 **제본스 역설**이다.

## 15단계: 텍스트 한 줄이 GPU를 통과해 돌아오기까지

### 1~4단계 — 텍스트를 "배치 가능한 작업"으로 변환

모델은 텍스트가 아니라 정수 ID를 먹는다. 바이트 수준 BPE 토크나이저가 문자열을 하위 단어로 쪼개 약 10만~20만 항목의 어휘에서 ID를 매긴다. 예시의 12,000토큰 RFP+질문은 12,022개 정수의 평면 시퀀스가 된다. 토큰화 자체는 CPU에서 결정론적이고 거의 공짜지만, **입력·출력 토큰 수가 곧 청구 금액**이라는 점이 핵심이다. 2026년 프런티어 모델의 20만~100만 토큰 컨텍스트 창이 한 번에 넣을 수 있는 문서의 상한이다.

이어 **API 게이트웨이**(2단계)가 TLS 종료·스키마 검증·거친 요청 제한·추적 ID 부여를 1ms 미만 예산으로 처리하며, 형식 오류·할당량 초과·공격성 트래픽 약 5%를 고가 자원 도달 전에 쳐낸다. **인증·과금 등급**(3단계)은 API 키/OAuth를 조직에 묶어 적용할 토큰당 가격, 캐시 할인, 우선 경로, 일괄 처리 자격을 정한다. **부하 분산**(4단계)에서 LLM 특유의 함정이 나온다 — 단순 라운드로빈은 같은 시스템 프롬프트·문서 접두사를 가진 요청을 서로 다른 복제본으로 흩뿌려 캐시 재사용 기회를 날린다. 그래서 최신 부하 분산은 "같은 접두사의 KV 캐시가 있는 복제본"을 고르는 **캐시 인식(cache-aware)** 방식으로 진화했다.

### 5~8단계 — 어디서 실행하고, 메모리를 어떻게 나눌 것인가

**추론 라우터**(5단계)는 수 밀리초 안에 모델·실리콘·복제본을 고른다. 8B로 충분한 요청을 70B로 처리하면 마진을 그냥 태우는 셈이다. 연산 중심 프리필엔 FLOPS가, 메모리 중심 디코드엔 HBM 대역폭이 중요해서 한 요청 안에서도 적합한 GPU가 달라진다. Together AI·Fireworks·Baseten·Modular가 이 계층에서 커널·칩·정밀도 선택을 제품화한다.

**스케줄러**(6단계)의 핵심은 지속 배치(continuous batching)다. 배치 크기 1에서 H100은 연산보다 메모리에 묶여 SM 활용률이 30~40%에 머문다. 지속 배치는 순전파마다 새 요청을 끼워 넣고 완료 시퀀스를 빼내 GPU를 끊김 없이 채운다. vLLM이 이 방식으로 이전 서빙 대비 2~4배, 단순 PyTorch 루프 대비 3~5배 처리량을 낸다.

**KV 캐시**(7단계)는 서빙 중 GPU 메모리를 가장 크고 동적으로 잡아먹는다. 어텐션이 매 토큰 K/V를 다시 계산하면 O(n²)이 되니, 프리필이 12,022개 위치의 K/V를 한 번 계산해 캐시에 넣고 디코드는 하나씩 추가·재사용한다. 문제는 시퀀스 길이를 예측하기 어려워 연속 메모리 할당이 60~80%를 낭비할 수 있다는 것 — **PagedAttention**은 OS 가상 메모리처럼 KV 캐시를 고정 크기 페이지로 쪼개 이 단편화를 없앤다. 여기에 **프롬프트/접두사 캐싱**이 얹힌다. Anthropic은 캐시 읽기를 일반 입력의 0.1배(100만 토큰당 $0.30 vs $3), OpenAI GPT-5.x도 캐시 입력 $0.50 vs $5로 90% 할인한다. 긴 프롬프트는 지연시간도 약 85% 줄어든다.

**GPU 메모리**(8단계)는 고정된 가중치 + 증가하는 KV 캐시 + 일시적 활성값 셋으로 나뉜다. 가중치 적재 후 남는 공간이 KV 캐시 예산이라, 동시 사용자 수를 제한하는 건 연산이 아니라 메모리인 경우가 많다. 70B는 FP16에서 ~140GB(80GB H100 두 대)지만 FP8에선 ~70GB로 줄어 한 대에 KV 여유까지 남는다 — 양자화로 아낀 메모리가 곧 동시 사용자 수다.

### 9~14단계 — HBM 병목, 커널, 그리고 모델 안으로 들어온 네트워크

**프리필 vs 디코드**(9단계)의 병목은 정반대다. 프리필은 입력 토큰을 병렬 처리하는 대규모 행렬곱으로 텐서 코어를 포화시키고 TTFT에 묶인다. 디코드는 토큰 하나마다 전체 가중치+KV 캐시를 HBM에서 읽어야 한다. 배치 1에서 디코드의 연산 집약도는 바이트당 약 1 FLOP으로, 루프라인 경계(410~590 FLOP/byte)보다 훨씬 낮다 — 텐서 코어가 계산보다 메모리를 기다린다. 그래서 **HBM 대역폭이 생성 속도와 비용의 상한**이다. FP16→FP8→FP4로 정밀도를 낮추면 토큰당 읽는 바이트가 줄어 디코드 처리량이 오른다. NVIDIA NVFP4(Blackwell 5세대)는 FP8 대비 2~3배 산술 처리량, 1.8배 메모리 절감, 정확도 차 1% 이내로 Hopper 대비 종단 간 최대 5배 가속에 기여한다.

**CUDA 커널·융합**(10단계): 트랜스포머를 수백 개 개별 커널로 돌리면 매번 HBM을 읽고 쓴다. 커널 융합은 중간 데이터를 온칩 SRAM에 유지해 HBM 접근을 줄인다. FlashAttention은 타일 어텐션+온라인 softmax로 HBM 접근을 제곱→선형으로 낮춰 2~4배 가속하고, FA-3는 H100에서 840 TFLOPS(최대 성능 ~85%)에 도달한다. **추측 디코딩**은 디코드가 어차피 전체 가중치를 읽으니 후보 여러 개를 병렬 검증하는 추가 비용이 작다는 점을 파고든다 — 작은 초안 모델이 K개를 제안하면 큰 목표 모델이 한 번에 검증해 2~4배 빨라진다(EAGLE-3는 초안 채택률 75%+).

11~14단계는 **네트워크가 디코드 루프 바깥의 보조장치가 아니라 루프 내부에서 도는** 지점이다. 조 단위 모델과 MoE는 여러 GPU에 쪼개지므로 모든 계층·모든 토큰에서 GPU 간 통신이 발생한다. **NVLink 5**는 GPU당 1.8TB/s(PCIe Gen5의 약 14배), **GB200 NVL72**는 72 Blackwell + 36 Grace를 하나의 NVLink 도메인으로 묶어 130TB/s·13.4TB 통합 메모리·약 120kW로 조 단위 모델에서 H100 클러스터 대비 최대 30배 처리량을 낸다. 텐서 병렬화는 all-reduce를, MoE는 all-to-all을 유발하는데 이게 주 병목이 되곤 한다(DeepSeek은 노드당 400Gbps NIC 8개 + DeepEP로 통신·계산을 겹친다). **NVSwitch**(144 포트·14.4TB/s 비차단), 랙 밖의 Quantum-X800 InfiniBand·Spectrum-X800 Ethernet·Broadcom Tomahawk 6(102.4Tbps), 레일 최적화 토폴로지와 SHARP 인패브릭 축약이 여기 붙는다. 패킷은 BlueField 같은 SmartNIC/DPU를 지나며(RoCE/InfiniBand verbs로 CPU를 우회해 원격 GPU 메모리 직접 읽기, 400→800Gb/s 표준화 중), Ethernet 계층에서는 2025년 6월 **UEC 1.0**이 나왔고 Dell'Oro는 AI 백엔드에서 Ethernet이 2027년 InfiniBand를 추월한다고 본다.

여기서 비용의 숨은 주인공이 **광학 부품**이다. 광 트랜시버는 네트워크 비용의 약 60%, 전력의 약 45%를 차지한다. 네트워크가 클러스터 비용의 15~18%니 광학만 전체의 약 10%다. 800G 플러거블 모듈은 스위치 하나에서 500W+를 먹어 스위칭 ASIC보다 전력을 더 쓸 수 있다. AI 광 트랜시버 시장은 2025년 ~165억 달러 → 2026년 ~260억 달러(+57%) 전망이며, **공동 패키지 광학(CPO)**은 1.6T 링크 전력을 30W→9W로 낮춘다(NVIDIA 포토닉스 스위치, 2026 하반기, 5배 전력효율·10배 복원력).

### 15단계 — 스트리밍과 정산

마지막 토큰이 나오면 역토큰화가 정수를 텍스트로 되돌리고, 응답은 왔던 길을 거슬러 SSE로 토큰마다 스트리밍된다. 사용자는 약 0.3초부터 읽기 시작하니 **TTFT가 체감 속도를 좌우**한다. 마지막으로 일반/캐시 입력과 (약 4~5배 비싼) 출력 토큰을 등급에 맞춰 계산해 청구를 닫는다.

## 왜 중요한가 — "분리형 서빙"이라는 추론 운영체제

배치·KV 페이징·프리필/디코드 분리·하드웨어 선택·집합 통신은 결국 하나의 문제다: **이질적인 작업을 메모리·네트워크 계층에서 스케줄링해 고가 실리콘의 활용률을 올리는 것.** 2026년의 **분리형 서빙(disaggregated serving)**은 연산 중심 프리필과 대역폭 중심 디코드를 별도 GPU 풀로 나누고 그 사이로 KV 캐시를 스트리밍한다(NVIDIA Dynamo, vLLM, SGLang, llm-d, Mooncake).

이 구조 변화가 산업 지형을 다시 그린다. 컴파일러·커널·자동 튜너 기업이 기술을 라이선스하는 대신 **자체 인프라에서 토큰을 팔아 효율 차이를 총마진으로 바꾸는** 쪽으로 옮겨갔다. 커널·배치·양자화·추측 디코딩에서 2배를 개선하면 GPU당 팔 수 있는 토큰도 2배다. Baseten의 연환산 매출은 2025년 12월 ~2억 달러 → 2026년 3월 ~6억 달러(전년比 ~1,900%), 기업가치 110~130억 달러로 15억 달러를 조달했다(5개월 전 50억 달러). Qualcomm의 Modular 약 39억 달러 인수는 칩 기업이 하드웨어 독립적 컴파일러로 NVIDIA에 대응하려는 신호다.

창업자·엔지니어에게 이 글의 결론은 냉정하다. **토큰 경제가 커진다고 마진이 자동으로 따라오지 않는다.** 원시 속도만 내세우는 사업은 컴파일러 계층과 NVIDIA 무료 도구가 같은 성능을 범용화하는 순간 방어력이 증발한다. 가치는 (1) HBM 대역폭이 정하는 디코드 상한, (2) 독점적인 NVLink 규모 확장 도메인, (3) 희소 입력이 된 광학·전력에 쌓인다. 네트워크 시장은 둘로 갈라진다 — 랙 안 규모 확장(scale-up)은 폐쇄적·방어 가능 영역으로 남고, 랙 밖 규모 확장(scale-out)은 Ethernet·UEC로 개방·범용화된다. 그리고 7,250억 달러 자본지출의 60%+가 전력·건물에 들어가는 이상, 장기 최종 지표는 **와트당 토큰 수(tokens/watt)**다.

## 어떻게 써먹나 — 추론 제공업체 고르는 실전 기준

1. **지연시간을 쪼개 본다.** 답변 시작을 정하는 TTFT와 완료 속도를 정하는 토큰 간 지연시간을 분리하고, 중앙값이 아니라 **p99 꼬리 지연시간**을 본다. 일반 GPU 추론은 TTFT ~400~600ms지만 Groq·Cerebras는 Llama-70B급에서 <100~150ms TTFT, 초당 1,600~2,100+ 토큰(~4~6배)을 낸다.
2. **비용은 게시 단가가 아니라 혼합 비용으로.** 입력·출력 비율(출력이 4~5배 비쌈), 캐시 적중률(입력 50~90%↓), 일괄 처리(~50%↓)를 반영한다. 2026년 중반 실효 단가는 비용 최적화 공개 엔드포인트의 100만 토큰당 $0.04~0.20(예: Groq 입력 $0.15/출력 $0.60)부터 프런티어 수 달러까지 두 자릿수 배율로 벌어진다.
3. **신뢰성은 가동시간 너머 기능적 가용성까지.** Azure OpenAI는 99.9% SLA를 주지만, 거부율 급증·자동 모델 버전 교체·부하 시 할당량 제한은 공식 SLA를 지키면서도 제품을 망가뜨린다. 모델 버전을 고정하고 용량을 협상하며 직접 감시하라. 기업은 흔히 "99.99%에서 TTFT <200ms" 같은 지연 SLA를 요구한다.
4. **프로덕션 적합성 7기준을 체크리스트로:** ① 처리량·요청 제한(분당 토큰 한도) ② 보안·규정 준수(SOC 2 Type II·HIPAA·ISO 27001·GDPR — 나중에 붙이기 어렵다) ③ 데이터 지역성·비공개 배포(무보존·VPC/BYOC·온프레미스) ④ 결정성·버전 제어(고정 시드·체크포인트로 평가 드리프트 방지) ⑤ 모델 범위·최신성(신규 가중치 출시 당일 지원·LoRA 호스팅) ⑥ 배포 유연성(서버리스/전용/자체 호스팅) ⑦ 이식성(OpenAI 호환 API·다중 제공업체 라우팅으로 장애·가격·모델 변경 대응).
