## TL;DR

- Mindwalk는 Claude Code·Codex 세션 로그를 읽어, 저장소를 어두운 "야간 지도"로 그린 뒤 에이전트가 **검색·읽기·수정한 위치만 빛나게** 재생하는 로컬 시각화 도구다.
- 원본 JSONL 로그로는 알 수 없는 **"에이전트가 작업을 어떻게 이해했는가"**(탐색 위치·작업 범위·방황 여부)를 한눈에 보여주는 게 목표다.
- 싱글 Go 바이너리 + React/Three.js, 뷰잉은 완전 로컬, MIT 라이선스. 세션 평가를 돌릴 때만 요약이 본인 CLI 뒤 모델로 전송된다.

## 무엇을 하는 도구인가

에이전트에게 코딩을 시켜본 사람이라면 익숙한 답답함이 있다. 세션 로그(JSONL)는 에이전트가 **무엇을** 했는지는 빠짐없이 기록하지만, **어떻게 이해하고 움직였는지**는 담지 못한다. 어느 영역을 관련 있다고 판단했는지, 어디를 뒤졌는지, 실제 작업 범위와 지시한 범위가 맞았는지 — 이런 "판단의 궤적"은 원본 로그를 아무리 읽어도 재구성하기 어렵다.

Mindwalk(제작자 cosmtrek)는 이 간극을 시각화로 메운다. 핵심 은유는 **야간 지도(night map)**다. 저장소 전체를 어둡게 깔아 놓고, 세션이 검색·읽기·수정으로 건드린 위치만 빛나게 유지한다. 나머지는 계속 어둠 속에 남으므로, 에이전트가 실제로 "본" 영역과 손대지 않은 영역이 밝기 대비로 곧장 드러난다.

기술 스택은 단순하다. **싱글 Go 바이너리**가 Claude Code와 Codex의 세션 로그를 읽고, 로컬 Go 서버가 데이터를 결합해 React/Three.js 프론트엔드로 서빙한다. 뷰잉 과정은 전부 로컬에서 돈다.

### 지도와 색: 어디를, 얼마나 건드렸나

- **Tree / Terrain 뷰**: 저장소를 방사형 트리 또는 트리맵 평면으로 표현한다. 파일이 깊은 곳에 있고 자주 터치될수록 빛의 강도가 세진다.
- **파일별 터치 상태 색 구분**: seen(녹색) → read(파랑) → edited(호박색) → unvisited(어두움). 파일이 어느 단계까지 "소비"됐는지 색으로 즉시 읽힌다.
- **유령 파일**: 세션이 건드렸지만 지금은 저장소에서 사라진 파일은 **와이어프레임 유령**으로 남는다. 지웠거나 이동시킨 흔적이 지도에 잔상으로 보인다는 뜻이다.
- **HUD 마찰 신호**: 오류율, churn(잦은 변경)된 파일, 마지막 verify 이후의 수정 등 "삐걱대는 지점"을 묶어서 표시한다.

### 시간축 재생: 관찰은 차갑게, 수정은 따뜻하게

**Playback deck**은 버킷 단위로 묶은 히스토그램 위에서 세션을 스크럽·재생하게 해준다. 여기서 색 온도를 활용한 설계가 눈에 띈다 — 관찰 성격의 행위(검색·읽기·실행)는 **차가운 색**으로, 실제 변경 성격의 행위(수정·verify)는 **따뜻한 색**으로 배치한다. 그래서 타임라인에서 "실제로 편집이 몰린 구간"이 시각적으로 튀어나온다. 재생 화면은 클라이언트 측에서 전부 **.webm**으로 내보낼 수 있다.

**Timeline marks**로 세 가지 이벤트를 표기한다: 컨텍스트 압축(◇), 서브에이전트 실행(○), 사용자 턴(›). 클릭하면 해당 지점으로 점프한다. **Agent lenses**는 세션이 띄운 서브에이전트의 트레이스를 같은 지도 위에서 재생하고, 다시 메인 트레이스로 복귀하게 해준다. 멀티 에이전트 실행의 하위 궤적까지 같은 좌표계에서 따라갈 수 있다는 점이 특징이다.

### 세션 평가와 프라이버시 경계

Mindwalk는 세션을 자동으로 채점하는 기능도 갖는다. 로컬 CLI에 **탐색/범위/방황/검증** 판정을 요청하고, 모든 발견은 클릭 가능한 타임라인 이벤트에 앵커링된다 — 지적이 추상적 잔소리로 끝나지 않고 "이 시점 이 이벤트" 로 되짚어진다.

프라이버시 경계도 명시돼 있다. **평가를 실행할 때만** 세션 요약(메시지 문구, 파일 경로, 한 줄 이벤트 요약)이 사용자 계정의 claude/codex CLI 뒤 모델로 전송되며, 다른 세션은 포함되지 않는다. 순수 뷰잉만 하면 데이터가 로컬을 벗어나지 않는다.

### 설계상의 관심사 분리

내부적으로 세 아티팩트를 **의도적으로 분리**한 점이 아키텍처적으로 인상적이다.

- **trace**: 정규화된 파일 터치 이벤트 스트림
- **citymap**: 결정론적 저장소 레이아웃
- **report**: LLM 판정자가 만든 증거 기반 발견

즉 "무슨 일이 있었나(trace)", "어디에 그렸나(citymap)", "어떻게 평가하나(report)"를 각각 독립 계층으로 두었다. citymap이 결정론적이라는 건 같은 저장소면 같은 레이아웃이 나온다는 뜻이고, LLM 판정(비결정적·선택적)을 결정론적 지도와 명확히 분리해 둔 설계다.

## 왜 중요한가

에이전트 코딩이 늘면서 병목이 "코드를 만드느냐"에서 **"에이전트가 뭘 했는지 사람이 검증할 수 있느냐"**로 옮겨가고 있다. 수백 줄 diff와 장문 로그를 눈으로 감사하는 건 현실적으로 지속 불가능하다. Mindwalk의 접근은 이 감사 비용을 **공간적 직관**으로 낮추려는 시도다 — 밝은 영역과 어두운 영역의 대비, 편집이 몰린 따뜻한 구간, 사라진 파일의 유령 같은 신호는 텍스트 로그를 읽는 것보다 훨씬 빠르게 "에이전트가 엉뚱한 데를 팠는지, 범위를 벗어났는지"를 알려준다.

같은 문제의식을 가진 도구들(AgentsView, Agent-Blackbox 등)이 동시다발로 등장하는 것 자체가, 에이전트 세션 관측성(observability)이 하나의 도구 카테고리로 굳어지고 있다는 신호다.

## 어떻게 써먹나

- **PR 리뷰 보조**: 에이전트가 만든 변경을 머지하기 전, 지도에서 "건드린 영역이 지시 범위와 맞는지"를 먼저 훑는 스모크 체크로 쓸 수 있다. 밝게 빛나는 파일 집합이 예상 밖이면 그 자체가 경고다.
- **에이전트 프롬프트·범위 튜닝**: 방황(불필요한 탐색) 구간이 지도와 타임라인에서 두드러지면, 컨텍스트 주입 방식이나 작업 지시 범위를 좁힐 근거가 된다.
- **팀 공유·회고**: .webm 내보내기로 "이 세션이 이렇게 움직였다"를 그대로 공유하면, 세션 실패 원인 회고를 로그 대신 영상으로 할 수 있다.
- **로컬 우선이 필요한 환경**: 뷰잉이 완전 로컬이고 평가만 본인 CLI 모델을 쓰므로, 코드가 외부로 나가는 걸 꺼리는 조직에서도 도입 문턱이 낮다.
