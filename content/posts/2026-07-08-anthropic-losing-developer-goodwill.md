한 개발자(raheeljunaid.com)가 "Anthropic이 개발자 호감을 잃는 몇 가지 방법"이라는 글을 냈고, GeekNews에 올라와 논쟁이 붙었다. 핵심 소재였던 **2026년 6월 15일 구독 과금 변경**은 반발 끝에 시행 직전 되돌려진 것으로 보이지만, 그 과정에서 드러난 락인 구조와 신뢰 손상은 그대로 남았다. 이 글은 그 사건과, 여기서 개발자·창업자가 실제로 챙겨야 할 교훈을 정리한다.

## TL;DR
- Anthropic은 6월 15일 Claude 구독을 "1차 도구 사용"과 "제3자 에이전트/SDK 사용" 두 풀로 쪼개 후자를 별도 크레딧(Pro $20·Max 5x $100·Max 20x $200)에서 차감하고 초과분은 API 요금으로 청구하려 했다 — 그리고 **소비자 반발 후 이 변경을 철회/보류했다.**
- 원문은 Claude Code의 품질 논란(약 9,100개 GitHub 이슈, 멈춤 6개월·깜빡임 1년+ 미해결)과 구독-도구 락인을 함께 비판하지만, 이는 상당 부분 **필자의 주장이 담긴 오피니언 글**이며 HN에는 "손실 보조를 줄이는 걸 탐욕이라 부르긴 어렵다"는 반론도 나왔다.
- 진짜 실용적 결론은 과금 논쟁 자체가 아니라 **선택지 확보** — OpenRouter·Requesty·Portkey·Vercel 같은 AI 게이트웨이와 Qwen·GLM·Deepseek·Minimax 같은 오픈소스 모델로 워크플로를 옮길 수 있게 해 두면 특정 벤더의 약관 변경에 인질이 되지 않는다.

## 무슨 일이 있었나 — 6월 15일 과금 변경과 철회

Zed 블로그가 정리한 바에 따르면, 2026년 6월 15일부터 Anthropic은 Claude 구독의 사용을 두 갈래로 나누려 했다.

- **1차 도구 사용**: chat, 공식 Claude Code CLI 등
- **제3자 에이전트·SDK 사용**: ACP, `claude -p`, 기타 서드파티 도구

후자는 기존 Pro/Max 구독 한도에서 차감되지 않고, 새로 만든 월간 **Agent SDK 크레딧**(Pro $20 / Max 5x $100 / Max 20x $200)에서 빠진다. 크레딧을 다 쓰면 'extra usage'가 켜져 있을 때 표준 API 요금으로 계속 청구되고, 꺼져 있으면 다음 결제 주기까지 요청이 멈춘다. 원문은 기존 Claude 구독이 API 가격 대비 약 15~30배 수준으로 에이전트 사용을 보조해 왔다고 보며, 에이전트 헤비 유저에게는 이 변경이 사실상 큰 비용 인상이라고 짚는다.

**그런데 이게 핵심이다: 이 변경은 반발 이후 시행 직전에 되돌려진 것으로 보인다.** 원문에도 수정 메모로 "Anthropic이 소비자 반발 이후 되돌린 것 같다"가 붙었고, HN 토론에서도 "'아마 취소'가 아니라 실제로 취소했다. 지금도 서드파티 실행 틀을 문제없이 쓰고 있다"는 증언과 공식 공지의 "일시 중지" 문구가 함께 언급된다. 즉 2026년 7월 현재, 이 과금 구조를 **현행 사실로 서술하면 틀린다.** 발표됐고, 욕먹었고, 되돌려졌다 — 다만 흉터는 남았다.

## 왜 흉터가 남았나 — 락인과 감지 방식

되돌렸어도 신뢰가 깎인 이유는 두 가지다.

첫째, **구독-도구 락인 구조** 자체다. Claude 구독은 Claude Code CLI/Desktop, Claude CoWork, Slack의 @Claude(수정 메모로 Agent SDK도 추가됨) 위주로 묶여 있고, Vertex AI·AWS Bedrock·Azure 경로는 더 비싼 Anthropic API 크레딧을 써야 한다. 여기에 Claude Code의 품질 논란이 겹친다 — 글 작성 시점 기준 약 9,100개 이슈가 열려 있고, 완전 멈춤은 6개월 이상, 화면 깜빡임은 1년 이상 미해결이라는 지적이다. "가장 인기 있는 하네스인데 동시에 사람을 묶어두는 락인 도구"라는 비판이다.

둘째, **감지 방식의 인상**이다. 원문은 Anthropic이 사용자가 서드파티 도구를 쓴다고 "생각"했을 때 extra usage를 부과한 적이 있고, 그 판정이 세션 디렉터리에 특정 이름 파일이 있는지를 보는 식이었다고 주장한다. 또 구독과 서드파티 하네스 호환을 복원하려던 프록시 도구가 하룻밤 사이 과금 대상이 됐다고 한다. 이 대목은 필자의 서술이라 팩트로 못 박기보다 "이렇게 받아들여졌다"로 읽는 게 맞다.

## 이건 오피니언 글이다 — 반론도 같이 보자

원문은 "고객을 폐쇄 시스템에 락인한다", "경쟁사를 깎아내린다", "공포 마케팅을 위해 제품을 인위적으로 제한한다" 같은 강한 비윤리 프레임을 건다. 규제 포획을 서두른다는 해석도 붙는다. 이는 **필자의 고발이지 확립된 사실이 아니다.** HN에서도 "분명 공격성 글", "7월에 내면서 서사에 안 맞는 6월 가동 시간 데이터를 왜 뺐는지 모르겠다"는 지적이 나왔다.

균형을 위한 반론도 분명하다. HN의 한 의견은 "자기 소프트웨어를 쓰는 동안 토큰을 보조해 주는 구조라면 공정한 교환이고, 묶이기 싫으면 더 내면 된다 — 통신사 보조금 없는 언락폰을 비싸게 사는 것과 같다"고 봤다. "모든 AI 회사가 여전히 돈을 태워 서비스를 보조하는 상황에서, 손실을 조금 줄이려는 행동을 탐욕이라 부르긴 어렵다"는 반론도 있다. 다만 같은 사람도 "이 손실 보조 사이클은 언젠가 엔시티피케이션으로 간다"는 경계는 놓지 않았다.

## 어떻게 써먹나 — 선택지를 자산으로

논쟁의 승패보다 개발자·창업자가 가져갈 실전 결론은 하나다. **한 벤더의 약관이 하룻밤 사이 바뀔 수 있다고 전제하고 이식성을 설계에 넣어라.** 원문 필자 본인의 이동 경로가 그대로 레시피다.

- **AI 게이트웨이로 추상화**: OpenRouter·Requesty·Portkey·Vercel을 두면 여러 모델 중 고르고, 가장 싸거나 가용성 높은 백엔드로 라우팅하고, 데이터 보존/민감정보 노출/고가 모델 사용을 통제할 수 있다.
- **오픈소스 모델을 실사용 후보로**: Deepseek·GLM·Kimi·Qwen·Minimax 등이 경쟁력을 보이며, 필자는 OpenCode에서 Qwen·GLM으로 Sonnet을 대체했다고 한다. 역할 분담 예시로 오케스트레이션에 Qwen·GLM, 검색에 Deepseek, 파일 편집에 Minimax를 쓴다.
- **에이전트 주도에서 agent-assisted로**: 필자는 에이전트가 다 몰고 가는 방식이 코드 이해도 저하로 이어졌다며, GitHub Copilot식 자동완성에 가깝게 — AI가 이해·계획·코드를 보완하되 변경 검토가 쉬운 방식으로 되돌아갔다고 한다. 그 정도 용도라면 Fable이나 Opus까지 갈 필요 없이 Sonnet이면 충분하다는 것.

단, 주의할 트레이드오프도 원문에 그대로 있다 — Claude 구독을 OpenCode 등 일부 서드파티에 붙이는 건 여전히 약관 위반일 수 있고(현재 미집행일 수 있음), 계정 밴을 우려해 OAuth를 피하는 사용자도 있다. 이식성은 공짜가 아니라 관리 비용이 든다.

## 왜 중요한가

제품이 성능×비용의 파레토 최전선에 있으면 사용자는 웬만한 결함을 참는다. 하지만 그 격차가 "몇 광년"이 아니라 몇 달 수준으로 좁혀지고 중국·오픈소스 모델이 같은 역량에 근접하면, 락인과 신뢰 손상은 곧바로 이탈 비용이 된다. 이번 사건의 교훈은 "Anthropic이 나쁘다"가 아니라 — 되돌리긴 했으니 — **경계 없는 기업체에 선의를 전제로 아키텍처를 걸지 말라**는 것이다. IBM이 x86을 2차 공급사(AMD)까지 열어 PC 표준을 만든 것처럼, 전문 사용자는 항상 대체 경로를 확보하고 실제 비용 없이 가능한 곳에서는 주기적으로 재평가하는 게 맞다.
