앤트로픽이 7월 24일 금요일 자사의 오래된 헤비급 라인업의 최신판인 **Opus 5**를 내놨다. 흥미로운 건 포지셔닝이다. Opus 5는 상위 모델 Fable 5보다 "더 작은" 모델인데도, 더 싸고 규제가 덜하며, 심지어 발표에 포함된 몇몇 벤치마크에서는 Fable 5를 앞선다.

## TL;DR
- Opus 5는 Fable 5보다 작은 모델이지만 **더 저렴 + 규제 완화 + 일부 벤치마크에서 우위**라는 조합으로, 앤트로픽은 "대부분의 유스케이스에서 Opus 5가 선호될 것"이라 본다.
- 안전 분류기(classifier)가 Fable 5 대비 **약 85% 덜 발동**하고, Fable·Mythos에 걸리는 **30일 데이터 보존 정책이 Opus에는 적용되지 않는다** — 다만 사이버보안(익스플로잇 생성·바이너리 취약점 스캔 등)엔 여전히 실질적 가드레일이 남아 있다.
- 분류기가 걸렸을 때 에러 대신 하위 모델로 자동 우회해 정상 응답을 돌려주는 **Automatic Fallbacks**(opt-in 베타)를 함께 출시했다.

## 본문

**출시 맥락.** Opus 5는 5월 28일 나온 Opus 4.8로부터 불과 두 달 만에 나왔다. 앞서 6월에 Mythos 5·Fable 5·Sonnet 5가 모두 5 시리즈로 올라섰고, 이제 5 시리즈 업그레이드를 기다리는 건 경량 모델 Haiku 하나만 남았다. 즉 이번 Opus 5로 앤트로픽의 주력 라인은 사실상 5 세대로 정렬이 끝나가는 국면이다.

**"작은데 더 세다"는 포지셔닝.** 이 발표의 핵심 긴장은 여기 있다. Opus 5는 Fable 5보다 **작은** 모델이다. 그런데 (1) 더 싸고, (2) 규제가 덜하고, (3) 발표에 실린 여러 벤치마크에서 Fable 5를 오히려 **능가한다**. 이 세 가지가 겹치기 때문에 앤트로픽은 "대부분의 경우 Opus 5가 더 선호될 것"이라고 말한다. 크기가 곧 성능이라는 단순한 등식이 여기서는 깨지는 셈이다.

**무엇이 좋아졌나.** 앤트로픽은 Opus 5가 "자기 작업을 검증하고, 성공할 때까지 신중하게 반복(iterating)하는 데 훨씬 강하다(much stronger at verifying its work and iterating carefully until it succeeds)"는 점을 강조했다. 근거로 든 예시 중 하나는, 불완전한 프롬프트를 받고서 Opus 5가 **스스로 컴퓨터 비전 파이프라인을 직접 작성**했다는 벤치마크 결과다. 에이전트형 코딩 워크플로에서 중요한, "부족한 지시를 받아도 스스로 검증·재시도로 완주하는" 방향의 개선으로 읽힌다.

**규제·프라이버시 차이.** Opus 5는 출시 이후 Fable을 따라다닌 여러 제약에서 자유롭다. 전작과 마찬가지로, 프라이버시에 민감한 일부 사용자들이 우려했던 **30일 데이터 보존 정책**의 적용을 받지 않는다(이 정책은 Fable과 Mythos에 걸린다). 여기에 더해, 앤트로픽은 안전 분류기가 Fable 5보다 Opus 5에서 **약 85% 덜 발동**할 것으로 예상한다고 밝혔다. 기사에 따르면 이는 "덜 강력한(less capable) 모델에 더 가벼운 손길을 준다"는 크기 기준의 정책 판단이다.

**그래도 남는 가드레일 — 특히 사이버보안.** 규제가 전면 해제된 건 아니다. 익스플로잇 생성·모의침투(penetration testing) 같은 사이버보안 작업에는 여전히 실질적 안전장치가 남는다. 구체적으로 Opus 5는 **소프트웨어 바이너리에서 취약점을 스캔하는 것은 차단**하지만, **소스코드에서 취약점을 찾는 것은 허용**한다. 후자가 방어 목적일 가능성이 더 높다는 판단에서다. 공격/방어 성격에 따라 같은 "취약점 탐색"도 다르게 다룬다는 점이 포인트다.

**Automatic Fallbacks.** 분류기가 걸릴 때의 사용자 경험도 손봤다. 새로 나온 opt-in 베타 기능 **Automatic Fallbacks**를 켜면, 프롬프트가 안전 분류기를 건드릴 때 요청을 자동으로 **더 낮은 성능의 모델로 라우팅**한다. 결과적으로 이 설정을 켠 API 사용자는 에러 메시지 대신 작동하는 응답을 받게 된다.

## 왜 중요한가

- **가격·성능·규제의 삼각형이 재편됐다.** "가장 큰 모델이 가장 좋다"가 아니라, 더 작은 Opus 5가 비용·규제·일부 벤치마크에서 상위 모델을 이기는 구도다. 실무에서 모델 선택 기본값이 Fable에서 Opus로 옮겨갈 수 있다.
- **안전 정책이 이분법에서 그라데이션으로.** 30일 보존 적용 여부, 분류기 발동 빈도(85% 감소), 바이너리 vs 소스코드 취약점 탐색의 구분 — 모델 등급별로 세분화된 정책이 붙기 시작했다. 어떤 모델을 쓰느냐가 곧 어떤 프라이버시·규제 조건을 받느냐가 된다.
- **분류기 오발동의 실무 통증을 제품으로 흡수.** Automatic Fallbacks는 "안전 필터에 걸려 API가 그냥 실패한다"는 개발자들의 오랜 불편을, 에러 대신 하위 모델 응답으로 바꿔 파이프라인이 멈추지 않게 한다.

## 어떻게 써먹나

- **기본 모델 재점검.** 지금 Fable 5(또는 상위 모델)를 기본값으로 쓰고 있다면, 같은 작업을 Opus 5로 돌려 비용·품질을 비교해 볼 값어치가 있다. 앤트로픽 스스로 "대부분의 경우 선호"라고 말하는 만큼, 비용 절감 여지가 크다.
- **프라이버시 민감 워크로드.** 30일 데이터 보존이 걸림돌이던 용도라면, 해당 정책이 적용되지 않는 Opus 계열이 현실적 선택지가 된다.
- **방어적 보안 작업.** 소스코드 취약점 탐색은 Opus 5에서 허용되므로, 코드 리뷰·시큐어 코딩 보조에 붙일 수 있다. 반대로 바이너리 스캔은 막히니, 그 워크플로는 Opus 5로 옮기지 말 것.
- **API 안정성.** 안전 분류기 오발동으로 파이프라인이 깨진 경험이 있다면 Automatic Fallbacks(베타)를 켜 두면 하드 에러 대신 하위 모델 응답으로 흐름을 유지할 수 있다. 단, 응답이 조용히 약한 모델로 바뀌므로 품질 민감 구간에선 이 전환을 로깅·모니터링하는 게 좋다.
