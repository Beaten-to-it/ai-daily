Moonshot AI가 지식 노동자용 데스크톱 에이전트 **Kimi Work**를 내놨다. 웹 챗봇이 아니라 macOS(Apple Silicon)·Windows에 설치되는 로컬 에이전트로, "채팅"이 아니라 "실행"에 방점을 찍었다. 핵심은 세 가지 접근권이다 — 내 로컬 파일에 직접 붙고, 브라우저를 사람처럼 조작하고, 크론으로 24시간 돌아간다.

## TL;DR

- Kimi Work는 로컬 폴더를 마운트해 파일을 다루고, 백그라운드에서 Python/셸을 돌리며, 내장 크론으로 예약 작업을 실행하는 데스크톱 에이전트다(Mac·Windows).
- WebBridge(브라우저 자동화)로 탭을 넘나들며 데이터를 추출하고, Agent Swarm으로 여러 전문 에이전트를 조율해 결과를 PPT·엑셀로 변환한다.
- "Ask before acting" 안전장치로 파일 수정·덮어쓰기·코드 실행 전 명시적 승인을 받는다 — OS 레벨에 얹은 권한 게이트가 이 제품의 성격을 규정한다.

## 무엇인가

Moonshot은 Kimi Work를 웹 버전과 명확히 구분한다. 웹 앱은 빠른 질의응답용이고, Kimi Work는 "시스템 레벨의 디지털 직원(system-level digital employee)"을 표방하는 로컬 에이전트다. FAQ가 정리한 차이는 네 가지다 — (1) 로컬 폴더를 **마운트**하고, (2) WebBridge를 통해 웹을 **자율 탐색**하며, (3) 백그라운드에서 **Python 코드를 실행**하고, (4) **예약 작업**을 돌린다.

**로컬 파일 접근.** 제품 페이지의 데모는 "`~/Documents/KimiWorkspace`에서 'quarterly report'가 든 PDF를 전부 찾아 요약 문서를 만들되 원본은 그대로 둬라" 같은 지시를 그대로 실행하는 그림이다. 즉 파일 검색·읽기·새 산출물 생성까지 로컬에서 처리한다.

**24/7 자동화(크론).** 내장 크론 엔진이 반복 작업을 맡는다. 아침 브리핑을 초안하는 LLM 에이전트 호출, 자정에 대용량 데이터셋을 처리하는 Python 스크립트 등을 예약할 수 있다. 스케줄러가 지원하는 트리거는 **LLM 에이전트 호출 / Python·셸 실행** 등이며 매일·매시간·조건부로 걸 수 있다. 다만 한 가지 주의점 — 밤새 작업이 도는 건 설정에서 **"Keep Computer Awake"를 켰을 때**다. 컴퓨터가 잠들면 그냥 도는 게 아니라, 깨어 있게 유지해야 한다.

**WebBridge(브라우저 자동화).** 목표를 주면 사람처럼 인터넷을 탐색한다. 여러 탭을 오가며 핵심 데이터를 뽑고 다단계 웹 작업을 수행한다 — 클릭·스크롤·리서치를 에이전트가 처리하고 사용자는 프롬프트만 준다. FAQ 예시로는 "특정 사이트 최신 뉴스를 확인해 요약", "과거 주가 데이터를 스크랩해 로컬 엑셀로" 같은 것을 든다.

**Agent Swarm과 오피스 산출물 생성.** 다층 문제를 여러 전문 에이전트로 쪼개 동시에 푸는 스웜 방식이다. 리서치가 끝나면 인사이트를 곧바로 PowerPoint 덱이나 엑셀 시트로 변환한다.

**금융 특화 데이터.** Kimi Work는 A주(중국 본토)·홍콩·미국 주식 데이터 소스가 사전 통합돼 있다고 밝힌다. 복잡한 API 설정 없이 자연어 대화로 실적 보고서를 끌어오고, 시장 이상치를 분석하고, 스프레드시트를 대사(reconcile)할 수 있다는 것. (원문은 "pre-integrated data sources"라고만 하고 실시간·스트리밍 여부는 언급하지 않으니, 사전 연결된 조회 소스 정도로 읽는 게 정확하다.)

**프라이버시 모델.** 로컬 파일에 붙는 에이전트인 만큼 권한 문제가 핵심인데, 답은 **"Ask before acting"**이다. 파일을 수정·덮어쓰기하거나 디렉터리 안에서 코드를 실행하기 전에 명시적 승인을 요청한다. "동의 없이는 아무 일도 일어나지 않는다"는 게 Moonshot의 문구다.

## 왜 중요한가

이건 "더 똑똑한 챗봇"이 아니라 **로컬 실행 권한을 가진 에이전트**의 패키징이다. 구성 요소를 개발자 언어로 풀면 명확하다 — 크론(스케줄러) + Python/셸 실행(임의 코드) + 브라우저 자동화(웹 액션) + 파일시스템 마운트(로컬 I/O), 그리고 그 위에 얹은 **"Ask before acting" 권한 게이트**. 마지막 조각이 결정적이다. 로컬 파일과 셸에 붙는 에이전트는 곧 임의 코드 실행 표면이고, Claude Code류가 터미널에서 보여준 "행동 전 사용자 확인" 동의 모델을 데스크톱 앱 레벨로 끌어올린 셈이다. 자율성과 안전의 트레이드오프를 승인 프롬프트로 중재하는 이 패턴이, 데스크톱 에이전트 카테고리의 사실상 표준이 되어가고 있다.

포지셔닝도 눈여겨볼 만하다. "system-level digital employee"라는 표현은 SaaS 통합이나 브라우저 확장 수준을 넘어, OS 안에 상주하며 파일·웹·스케줄을 통째로 다루는 상주형 에이전트를 노린다는 신호다. 금융 데이터 사전 통합을 전면에 내세운 것도 특정 고가치 워크플로(리서치·재무 분석)를 초기 쐐기로 삼겠다는 의도로 읽힌다.

## 어떻게 써먹나

- **반복 리포트 자동화:** 매일 아침 특정 폴더의 새 PDF/스프레드시트를 요약하는 크론 잡을 걸어 브리핑 초안을 받는다. 밤새 돌릴 거면 "Keep Computer Awake"를 켜는 걸 잊지 말 것.
- **웹 → 로컬 데이터 파이프라인:** WebBridge로 공개 사이트의 시세·뉴스·테이블을 주기적으로 스크랩해 로컬 엑셀에 적재하는 흐름을, API 없이 자연어 지시로 구성해본다.
- **권한 경계 검증부터:** 로컬 파일·셸 접근이 핵심 리스크이니, 도입 시 "Ask before acting"이 어디까지 프롬프트를 띄우는지(수정·삭제·실행별로) 실제로 테스트하고, 민감 디렉터리는 워크스페이스에서 분리해두는 걸 권한다.
