Supabase가 스타트업 빌더 2,000명을 조사한 「2026 스타트업 현황」이 나왔다. 창업팀은 더 작고 고령·비기술로 바뀌었고, AI가 코드베이스 절반 이상을 짜는 게 표준이 됐다. 도구 시장은 Anthropic이 쓸어담았고, 스택은 Postgres·Supabase·Cloudflare로 수렴한다. 그런데 정작 "만드는 건 쉬워졌는데 파는 건 그대로"라는 게 이 리포트가 데이터로 반복해서 보여주는 한 문장이다.

## TL;DR

- **Anthropic 싹쓸이**: Claude Code 사용률 63%(코딩 도구 1위), 유료 Claude 구독 59%(28%→거의 2배), 모델 공급자 점유율 64%(38%→). 반대편에서 Cursor는 19%포인트, OpenAI/ChatGPT 구독은 57%→39%로 빠졌다.
- **만들긴 쉬운데 팔긴 어렵다**: 응답자 61%가 코드베이스 절반 이상을 AI로 생성(76~100%만 40%)했지만, AI 코드 비중이 높은 팀일수록 아직 수익화를 못 했고 고객 확보를 최대 과제로 꼽는다. 최대 과제 1위는 고객 확보 32%, 기술적 복잡성은 24%→11%로 조사 전체에서 가장 크게 추락.
- **스택 수렴**: Postgres 계열 80%, 호스팅은 Supabase 65%·Vercel 45%·Cloudflare 27%(AWS 21% 추월). CRM·관측·분석 SaaS는 안 사고 자체 구축하거나 아예 안 쓰는 팀이 급증.

## 더 작고, 더 나이 들고, 덜 기술적인 창업팀

1인 창업자 비율이 2025년 53%에서 2026년 61%로 8%포인트 뛰었다. 창업자 수 분포는 1명 61%, 2명 29%, 3명 7%, 4명 이상 3%. 2인 공동창업이 줄어든 게 눈에 띈다. AI가 초기 구축의 인력 요구를 깎아내면서 "공동창업자를 구하느니 혼자 시작한다"는 선택이 늘어난 흐름으로 읽힌다.

기술 창업자 비율은 82%에서 78%로 내려왔고, 비기술 창업자가 22%를 차지한다. 그리고 이들이 다른 집단보다 AI 코드 생성을 더 공격적으로 쓴다. 연령대도 위로 이동했다. 40세 이상이 18%→25%로 늘고 22~29세는 4%포인트 줄었다. 흥미로운 건 나이가 많을수록 AI 코드 비중이 높다는 점이다 — 비기술 창업자 중 코드 76~100%를 AI로 짠 비율이 54%, 50~59세에서는 60%까지 올라간다. "AI 코딩은 젊은 개발자의 도구"라는 통념과 정반대 방향이다.

지역도 넓어졌다. 본사 소재지는 북미·유럽 각 28%, 아시아 17%, 아프리카 9%, 원격 7%, 남미 6%. 유럽과 아프리카가 각 3%포인트 성장했고, 북미 안에서도 SF Bay Area 9%·NYC 8% 외에 Toronto·Austin·Chicago 같은 도시로 분산됐다.

## Anthropic 중심으로 재편된 AI 도구 시장

이번 리포트에서 가장 선명한 건 Anthropic의 지배다.

- **코딩 도구**: Claude Code 63%로 1위. 뒤이어 VS Code 44%, Cursor 31%, Antigravity 22%, Lovable 15%, ChatGPT/Codex 13%. 새로 등장한 Antigravity가 곧장 4위에 올랐고, Cursor는 19%포인트 급락, v0·Bolt·Windsurf도 각 6~9%포인트 빠졌다.
- **유료 구독**: Claude 28%→59%로 거의 2배. OpenAI/ChatGPT 57%→39%로 역전. Gemini 27%, Cursor 20%, Copilot 17%.
- **모델 공급자**: Anthropic/Claude 38%→64%로 기본값이 됨. OpenAI 69%→52%로 하락, Gemini 44%. Grok·자체 모델 각 11%, Hugging Face 10%. Hugging Face·자체 모델이 크게 줄면서 자체 추론을 굴리는 팀도 감소하는 추세다.

한 회사가 코딩 에이전트·유료 구독·모델 API를 동시에 석권한 그림인데, 록인 관점에서 보면 꽤 무겁다. 개발 워크플로의 핵심 레이어 대부분이 단일 공급자로 수렴하고 있다.

## 코드 생성은 보편화, 수익화는 뒤처짐 — 단, 인과는 조심

AI 코드 생성은 이제 예외가 아니라 기본이다. 응답자 61%가 코드베이스 절반 이상을 AI로 생성했고, 아예 76~100%를 AI로 짠 팀만 40%다. AI를 전혀 안 쓴 팀은 2%에 불과하다.

여기서 리포트가 반복해 짚는 상관관계가 있다. **AI 생성 코드 비중이 높을수록 아직 수익화하지 못했을 가능성, 그리고 고객 확보를 최대 과제로 꼽을 가능성이 커진다.** 실제로 현재 수익화 중인 비율은 AI를 안 쓰는 집단이 56%인데 AI를 많이 쓰는 집단은 31%로 절반 수준이다.

다만 여기서 "AI 코드가 수익화를 막는다"고 읽으면 오독이다. 리포트 자신이 이걸 인과가 아니라 교란된 상관으로 명시해 둔다 — AI를 많이 쓰는 팀은 대체로 부트스트랩 비중이 높고 생애주기가 이르며, 아직 자기 제품에 대한 시장 수요에 덜 노출된 초기 단계라는 것이다. 즉 "AI를 많이 쓰는 팀 = 갓 시작한 팀"이라는 단계 효과가 수익화 지표를 끌어내리고 있을 뿐, AI 사용 자체가 매출을 깎는다는 증거는 아니다. 낙관론도 같은 방향으로 갈린다(AI 미사용 49% vs 다용 61%) — 초기 팀의 기대치가 높은 것과 일관된다.

## Postgres와 신흥 프런트엔드로 수렴한 스택

데이터·인프라 선택이 눈에 띄게 좁혀졌다.

- **DB**: 어떤 형태로든 Postgres를 쓰는 팀이 80%(전년 76%). 세부로는 Supabase 49%, PostgreSQL 22%, Redis 6%, MySQL·Firebase 각 5%. MongoDB·MySQL·Firebase는 하락했고 Neon·DynamoDB·Convex가 처음 소규모로 진입.
- **인증**(올해 첫 조사): Supabase Auth 72%. Auth0 13%, NextAuth/Auth.js 12%, 자체 구축 11%.
- **호스팅**: Supabase 65%, Vercel 45%, Cloudflare 27%, AWS 21%. Cloudflare가 가장 빠르게 성장하며 AWS를 추월했고, 모든 하이퍼스케일러 점유율이 빠졌다. Vercel은 AWS와 격차를 9%포인트 더 벌렸다.
- **프런트엔드**: React 56%, Next.js 53%가 성장한 가운데 Expo 10%·TanStack 8%·HTMX 4%·Astro 3%가 새로 유의미한 비중 확보. 네이티브 모바일 18%(+3%포인트).

Supabase가 발행한 리포트라 자사 도구 점유율은 감안해서 볼 필요가 있지만(응답자 표본 자체가 Supabase 생태계에 치우쳐 있을 수 있다), Postgres 계열 80%·Cloudflare의 AWS 추월 같은 큰 방향은 표본 편향과 별개로 읽어둘 만하다.

## 에이전트·MCP는 퍼졌지만 운영 기반이 없다

52%가 에이전트를 구축 중이거나 계획 중이다. 주요 용도는 워크플로 자동화 59%, 데이터 분석 49%, 개인화·추천 40%, 고객 지원 38% 순. 멀티 에이전트를 프로덕션에서 굴리는 팀도 24%나 된다. MCP는 출시 1년 만에 프로덕션 29% + 실험 28% = 합계 57%에 도달했다.

문제는 그 뒤를 받칠 운영 체계가 텅 비어 있다는 점이다.

- 프로덕션 프롬프트를 관리하는 공식 체계가 없는 팀 **47%**(소스코드 하드코딩 26%, 버전관리 파일 25%). 전용 프롬프트 플랫폼은 11%.
- 정식 평가 절차가 없는 팀 **36%**. 있어도 수동 테스트·프롬프트 반복이 52%로 대부분.
- AI 워크로드를 별도 모니터링하지 않는 팀 **59%**. Langfuse·LangSmith·Datadog은 각 7%에 그침.

에이전트를 프로덕션에 밀어 넣는 속도는 빠른데, 그걸 관측·평가·관리하는 인프라는 절반 이상이 손도 안 댔다. 여기가 지금 가장 벌어져 있는 갭이고, 곧 사고와 회귀로 드러날 지점이다.

## 운영 SaaS를 사지 않는 스타트업

또 하나의 반복 패턴: 공급자 제품을 건너뛰고 직접 만들거나 아예 안 쓴다.

- 영업 활동이 있는데 정식 CRM/영업 도구가 없는 비율 43%→**53%**. 대체재는 Google Sheets 23%, Notion/Airtable 14%. HubSpot·Salesforce 전부 하락.
- 관측 도구를 안 쓰는 팀 56%, 쓰는 팀 중에선 자체 솔루션이 가장 빠르게 성장(10%). Sentry만 19%로 오류 추적 자리를 지킴.
- 분석·성장 도구도 자체 대시보드가 6%포인트, "아직 추적 안 함"이 5%포인트 증가.

만드는 비용이 낮아지니 "월 구독 SaaS를 살 바엔 하루 만에 대시보드를 짠다"는 계산이 성립한다. 이건 CRM·관측·분석 SaaS 카테고리 전반에 대한 조용한 위협 신호다.

## 유통이 병목이다 — 커뮤니티가 진짜 해자

초기 유료 고객은 개인·업무 네트워크 56%, 콜드 아웃리치 35%, 소셜 인바운드 29% 순으로 온다. 유료 고객 획득을 아예 시도조차 안 한 비율은 62%→67%로 늘었고, 전담 영업은 보통 열 번째 직원쯤 돼야 합류한다.

가장 실용적인 시그널은 커뮤니티 격차다. 개발자 커뮤니티를 구축한 스타트업은 10~11%뿐인데, 이들은 그렇지 않은 팀 대비 개발자 채널·오픈소스에서 첫 고객을 압도적으로 많이 얻는다.

- Discord·Slack·Reddit 경로: **38% vs 7%**
- 전환된 오픈소스 사용자: **29% vs 3%**
- 콘텐츠: 35% vs 20%

반대로 커뮤니티가 없는 팀은 개인 네트워크(57% vs 47%)와 콜드 아웃리치(36% vs 32%)에 더 기댄다. 누구나 제품을 낼 수 있는 시대에는 유통이 병목이고, 커뮤니티를 만든 소수만 남들과 다른 고객 확보 경로를 손에 쥔다.

## 창업자의 채널 이탈과 새로운 불안

창업자들은 소셜/콘퍼런스에서 물러나고 있다. TikTok 빼고 주요 플랫폼 사용이 다 줄었고(X −6%포인트, LinkedIn −3%포인트), 온라인 페르소나가 없다는 응답이 33%(+5%포인트), 산업 콘퍼런스에 안 간다는 응답이 60%(+10%포인트)에 달한다. 콘퍼런스 중심 개발자 마케팅이 닿는 시장이 그만큼 줄었다는 뜻이다.

최대 사업 과제 지형도 바뀌었다. 기술적 복잡성이 24%→11%로 반토막 나며 조사 전체에서 가장 큰 변화를 기록했고, 그 빈자리를 고객 확보(32%, 1위)와 함께 번아웃(11%)·AI 경쟁/파괴(7%)·런웨이 불안(4%)이 채웠다. 1~10명 팀에서는 번아웃이 이미 기술적 복잡성을 넘어 2위 과제다.

## 왜 중요한가

- **"AI 래퍼는 끝났다"의 데이터판**이다. 구축이 사실상 공짜가 되면서 코드는 물처럼 흔해졌고, 차별화가 전부 유통·수익화·커뮤니티 쪽으로 이동했다. 이 리포트의 모든 절이 같은 문장을 반복한다: 만들긴 쉬운데 파는 건 그대로다.
- **도구 시장의 힘이 Anthropic으로 급격히 집중**되는 스냅샷이다. 코딩 에이전트·구독·모델 API 세 레이어를 한 공급자가 석권하는 구도는 스택 의사결정과 록인 리스크를 다시 보게 만든다.
- **인프라 선택의 수렴**(Postgres 80%, Cloudflare의 AWS 추월)과 **SaaS 이탈**(CRM·관측·분석을 안 사고 자체 구축)은 도구 벤더 입장에서 카테고리 지형이 재편되고 있다는 조기 경보다.

## 어떻게 써먹나

- **스택 수렴에 올라타되 록인은 계산하라.** Postgres·Supabase·Cloudflare로 굳어지는 흐름은 기본값으로 삼을 만하지만, Anthropic 단일 의존이 커지는 만큼 모델·에이전트 레이어는 교체 가능성을 열어두는 게 안전하다.
- **유통을 제품과 동급으로 취급하라.** 커뮤니티를 만든 10%가 개발자·오픈소스 채널에서 5~10배 높은 고객 전환을 보인다. 코드가 흔해진 시장에서 커뮤니티 주도 유통은 "있으면 좋은 것"이 아니라 실제 해자다.
- **운영 갭을 지금 메워라.** 프롬프트 관리 없음 47%·평가 없음 36%·모니터링 없음 59%는 남들이 방치한 자리다. 에이전트를 프로덕션에 올린다면 관측·평가부터 깔아두는 게 곧 다가올 회귀·사고의 방파제이자, 이 공백을 노리는 도구라면 시장 기회다.
- **수익화 지표에 정직하라.** AI 코드 비중이 높다고 매출이 나오는 게 아니다(오히려 초기 단계일 뿐). "빠르게 만들었다"를 "잘 팔린다"로 착각하지 말 것.
