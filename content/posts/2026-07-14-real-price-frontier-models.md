## TL;DR

- 모델 요금표의 `$/100만 토큰`은 벤더 간 비교가 불가능하다. "토큰"의 크기가 토크나이저마다 다르기 때문 — Playcode가 동일 바이트를 각 벤더 실제 토크나이저로 세어보니 **같은 TypeScript 파일이 GPT-5.x에선 681토큰, Claude 최신 토크나이저에선 1,178토큰(1.73배)**이었다.
- Claude의 새 토크나이저는 자사 이전 것보다 코드 기준 **약 30% 더 많은 토큰**을 만든다. 스티커 가격은 그대로 — Opus 4.6→4.8이 실효 단가로는 조용히 ~32% 오른 셈이고, Sonnet 5의 "인하"는 2026-08-31에 끝나는 임시 완충일 뿐이다.
- 격차는 **코드에서 가장 크다**(Python·JS·Rust·TS 1.50~1.73배, 영어 산문은 1.40배). 코딩 에이전트는 하루 종일 코드를 뱉으므로, 당신 청구서에 실제로 곱해지는 건 이 1.50~1.73배 구간이다.

## 요금표가 안 보여주는 숫자

LLM 청구액은 두 숫자의 곱이다.

> 비용 = (내 콘텐츠가 변환된 토큰 수) × (토큰당 단가)

요금표는 **둘째 숫자만** 보여주고 첫째 숫자를 상수처럼 취급한다. 그런데 첫째는 상수가 아니라 모델 토크나이저의 성질이다. 토크나이저는 텍스트를 과금 단위로 쪼개는 부품이고, 같은 문단이라도 어떤 모델은 더 잘게 쪼갠다. 두 모델이 똑같이 "입력 100만 토큰당 $5"라고 광고해도 같은 문단에 다른 청구서를 내미는 이유가 여기 있다. 아무도 "콘텐츠당 토큰 수"를 인쇄하지 않으니 아무도 비교하지 않는다. 그래서 Playcode가 직접 쟀다.

두 갈래 결론이다.

- **같은 벤더 안에서**: Anthropic의 새 토크나이저는 같은 코드에 대해 이전보다 ~30% 더 많은 토큰을 만든다. 스티커 가격은 그대로 — 소리 없는 인상.
- **벤더 간에서**: 코드 기준 Claude 새 토크나이저는 GPT의 1.50~1.73배 토큰을 만들고, 코딩 에이전트가 가장 많이 쓰는 TypeScript가 최악의 케이스다.

## 어떻게 쟀나

생성이나 추정 없이, 실제 파일 16종(영어 산문, HTML, JavaScript, Python, TypeScript, Rust, JSON 툴 스키마·툴 결과, 중국어 채팅·산문, 기호 밀집 텍스트, 자사 라이브 에이전트 시스템 프롬프트)을 각 모델의 실제 토크나이저로 바이트 단위로 세는 방식이다.

- **Anthropic(Claude)**: 공식 `count_tokens` 엔드포인트. Anthropic이 실제 과금에 쓰는 바로 그 수치라 권위 있다.
- **OpenAI(GPT)**: 문서화된 `o200k_base`를 tiktoken으로 계산. 최신 모델은 곧이곧대로 믿지 않고 GPT-5.1·5.5·5.6 Sol에 실제 API 호출을 넣어 라이브 usage를 읽었고(요청 프레이밍은 long-minus-short 델타로 상쇄), 셋 다 `o200k_base`와 정확히 일치(비율 1.0000)했다.
- **Google(Gemini)·xAI(Grok)**: 각 벤더 자체 토큰 카운트 엔드포인트.

이 글 내내 GPT의 `o200k`가 1.00배 기준자다. 기준으로 삼기 적절한 이유는 그것이 움직이지 않기 때문 — `o200k`는 오래전부터 동결·공개돼 있고, 계속 바뀌는 쪽은 Claude 토크나이저다. DeepSeek와 GLM은 의도적으로 제외했다. "문자수÷4"라는 대략 추정치밖에 없는데, 지어낸 숫자야말로 이 글이 지적하려는 대상이기 때문이다.

## 발견 1: 같은 스티커 가격, ~30% 더 많은 토큰

요금표에서 아무것도 안 움직이는, 데이터셋에서 가장 깔끔한 케이스다. Opus 4.6과 4.8은 동일한 $5.00 / $25.00다. 바뀐 건 토크나이저뿐 — 구형은 Sonnet 4.6·Opus 4.6에, 신형은 Sonnet 5·Opus 4.8·Fable 5에 들어간다. 같은 바이트, 같은 벤더, Anthropic 자체 엔드포인트로 센 결과:

| 콘텐츠 | 구 토크나이저 | 신 토크나이저 | 변화 |
|---|---|---|---|
| 영어 산문 (2,115자) | 476 | 636 | +34% |
| HTML 페이지 (3,195자) | 1,131 | 1,302 | +15% |
| JavaScript (1,933자) | 659 | 794 | +20% |
| Python (2,251자) | 831 | 1,022 | +23% |
| TypeScript (2,888자) | 898 | 1,178 | +31% |
| Rust (2,924자) | 1,019 | 1,312 | +29% |
| JSON 툴 스키마 (9,948자) | 2,631 | 3,306 | +26% |
| 에이전트 시스템 프롬프트 (42,661자) | 10,761 | 14,953 | +39% |
| 중국어 산문 (379자) | 435 | 433 | ~0% |

실제 에이전트 요청 구성(주로 영어 시스템 프롬프트+툴 스키마+코드+JSON)으로 섞으면 신 토크나이저는 요청당 약 +32%다. 마지막 행에 주목 — 중국어는 거의 안 변했다. 이 인플레이션은 **영어·코드에서만 나타나는 효과**다.

### "인하"가 아니었던 인하

이 사실은 좋은 뉴스처럼 보였던 헤드라인을 다시 쓰게 만든다. Sonnet 5는 $2.00 / $10.00로 출시돼 Sonnet 4.6($3.00 / $15.00)보다 낮았다. 그러나 이건 **2026년 8월 31일에 끝나는 도입 가격**이다. 도입 기간엔 산수가 대충 상쇄된다 — 토큰은 ~32% 더 나오지만 토큰당 단가가 1/3 싸서 총액이 살짝 저렴하다. 9월 1일이 되면 스티커는 $3.00 / $15.00로 복귀하고 +32% 토큰 인플레이션은 그대로 남는다. 그날부터 같은 코드가 **동일 리스트 가격에서 Sonnet 4.6보다 ~32% 비싸진다.** 할인은 인하가 아니라 전환기 완충이었던 것.

### 실제 청구서로 검증

토큰 카운터는 과금 전까진 약속에 불과하니, `max_tokens: 1`짜리 실제 유료 요청을 쏴서 각 벤더가 실제 과금한 `usage.input_tokens`를 읽었다. 동일 콘텐츠에 대해 Opus 4.6은 2,541 입력 토큰, Opus 4.8은 3,191을 청구했고 각각 자신의 `count_tokens` 예측과 토큰 단위까지 일치했다. 인플레이션은 추정기뿐 아니라 청구서에 실재한다. Fable 5도 같은 콘텐츠에 3,191(=Opus 4.8과 동일)을 청구 — 같은 신 토크나이저를 쓰며 숨은 토큰당 추가세는 없다(Fable은 스티커 $10/$50로 비싼 것이지 몰래 물리는 세금 때문이 아니다). 이 검증 총비용은 약 $0.08.

## 발견 2: 격차는 코드에서 가장 넓다

벤더 간 비교. 아래 모든 숫자는 동일 파일에 대한 GPT 토큰 수의 배수다(GPT `o200k`=1.00배 기준자, 1.20배 = "GPT보다 20% 더").

| 콘텐츠 | Claude(신) | Claude(구) | Gemini 3 Flash | Grok 4.5 |
|---|---|---|---|---|
| TypeScript | 1.73x | 1.32x | 1.16x | 1.05x |
| Rust | 1.58x | 1.22x | 1.19x | 1.05x |
| JavaScript | 1.52x | 1.26x | 1.23x | 1.11x |
| Python | 1.50x | 1.22x | 1.20x | 1.09x |
| HTML 페이지 | 1.36x | 1.18x | 1.08x | 1.04x |
| 영어 산문 | 1.40x | 1.05x | 1.01x | 1.00x |
| 중국어 산문 | 1.44x | 1.45x | 0.85x | 0.86x |
| 중국어 채팅 | 1.53x | 1.55x | 0.91x | 0.92x |

코드 행이 나머지와 깨끗하게 분리된다. TypeScript가 1.73배로 가장 넓지만 혼자가 아니다 — Rust 1.58, JS 1.52, Python 1.50 전부 영어 산문(1.40배)보다 위다. TypeScript만의 우연이 아니라 **코드 카테고리 전체가 위이고 그 꼭대기가 TS**다.

### 왜 하필 TypeScript인가

GPT `o200k`가 유독 TS에 효율적이기 때문이다 — 토큰당 약 4.24자. 웹 JS/TS로 무겁게 학습된 토크나이저의 지문으로, camelCase 식별자와 JSX 패턴이 단일 토큰으로 접힌다. 이 효율은 Rust(토큰당 ~3.51자)에서 떨어지는데, Claude 토크나이저는 둘 다 비슷하게 조밀하다. 즉 한 벤더가 딱 당신이 쓰는 언어에 맞춰 토크나이저를 튜닝했고 다른 벤더는 안 했다. **격차는 GPT가 가장 강한 바로 그 지점에서 가장 넓다.**

### 중국어 행은 다른 이야기

중국어에서 Claude는 GPT보다 ~1.45~1.55배지만 **신·구 토크나이저 둘 다** 그렇다(구 435, 신 433 vs GPT 300). 이 세금은 새 릴리스 탓이 아니라 Claude 계열의 오래된 CJK 불리함이고 새 토크나이저가 손대지 않았다. (Gemini는 중국어에서 오히려 GPT를 이긴다 — 256 vs 300.) 교훈은 "어떤 모델이 항상 제일 싸다"가 아니라, **어느 토크나이저가 얼마나 세게 과세하느냐는 당신이 무엇을 쓰느냐에 달렸다**는 것.

## 그게 가격에 하는 일

리스트 가격에 측정된 발산을 곱하면 실효 단가 — 같은 작업을 처리하는 데 실제로 내는 돈 — 가 나온다. 아래 발산은 현실적인 영어 코딩 요청의 블렌드 배수를 `o200k` 기준으로 정규화한 값이다.

| 모델 | 리스트 in/out ($/Mtok) | 발산 | 실효 in/out ($/Mtok) |
|---|---|---|---|
| GPT-5.1 | $1.25 / $10.00 | 1.00x (기준) | $1.25 / $10.00 |
| GPT-5.5 | $5.00 / $30.00 | 1.00x | $5.00 / $30.00 |
| GPT-5.6 Sol | $5.00 / $30.00 | 1.00x (검증) | $5.00 / $30.00 |
| Grok 4.5 | $2.00 / $6.00 | 1.03x | $2.06 / $6.18 |
| Gemini 3 Flash | $0.50 / $3.00 | 1.09x | $0.55 / $3.27 |
| Claude Sonnet 4.6 | $3.00 / $15.00 | 1.14x (구) | $3.42 / $17.10 |
| Claude Sonnet 5 (도입) | $2.00 / $10.00 | 1.50x (신) | $3.00 / $15.00 |
| Claude Sonnet 5 (9/1부터) | $3.00 / $15.00 | 1.50x | $4.50 / $22.50 |
| Claude Opus 4.6 | $5.00 / $25.00 | 1.14x (구) | $5.70 / $28.50 |
| Claude Opus 4.8 | $5.00 / $25.00 | 1.50x (신) | $7.50 / $37.50 |
| Claude Fable 5 | $10.00 / $50.00 | 1.50x (신) | $15.00 / $75.00 |

Opus 4.6과 4.8은 $5/$25 스티커를 공유하지만 실효 단가는 ~32% 차이 — 발견 1을 달러로 옮긴 것이다. GPT-5.5와 GPT-5.6 Sol은 스티커도 실효가도 같은데, 검증된 같은 토크나이저를 쓰기 때문이다(두 티어 차이는 성능이지 숨은 토큰세가 아니다). Gemini 3 Flash는 토크나이저가 GPT보다 약간 무겁지만 스티커가 충분히 낮아 실효 기준 여전히 가장 싸다.

독립적인 데이터 한 점이 같은 방향을 가리킨다. Ploy가 이번 주 GPT-5.6 Sol로의 프로덕션 마이그레이션을 공개하며 같은 빌드에 대해 입력 1.70M 토큰 vs Claude Opus 4.8의 2.60M — 약 35% 적음 — 을 보고했다. 합성 프로브가 아닌 실제 청구서이고, 더 가벼운 토크나이저와 모델 자체의 장황함이 함께 섞인 수치다. 측정 방식은 달라도 방향은 같다.

## 정직한 범위: 2~4배가 아니라 1.4~1.73배

"Claude가 GPT의 2~4배 토큰을 쓴다"는 주장을 볼 것이다. Playcode의 측정은 이를 뒷받침하지 않고, 과장은 오히려 진짜 논점을 무너뜨린다. Claude 새 토크나이저를 GPT `o200k` 기준으로:

- 영어 산문·HTML·JSON: 약 1.36~1.42배
- 코드(Python·JS·Rust·TS): 약 1.50~1.73배, TS가 최대
- 중국어·기호 밀집 텍스트: 약 1.44~1.53배

실재하고 중대하지만 유계다. 제목에 TypeScript 수치를 넣은 건 그것이 범위의 꼭대기이자 코딩 에이전트가 하루 종일 처리하는 것 — 즉 실제 청구서에 매핑되는 숫자 — 이기 때문이다. 산문의 정직한 값이 1.4배인데 3배라고 부르면 논증 전체가 쉽게 기각된다. 정밀함이 핵심이다.

## 왜 중요한가

- **`$/Mtok`은 비교 가능한 숫자가 아니다.** 같은 스티커 가격이 같은 작업에 다른 청구서를 낸다. 벤더 선택·예산 산정을 스티커로만 하면 코드 워크로드에서 최대 73%까지 어긋난다.
- **"같은 가격에 새 모델" 뒤에 소리 없는 인상이 숨을 수 있다.** Opus 4.6→4.8은 명세서 한 줄 없이 실효 ~32% 인상이었다. 토크나이저 교체는 라인 아이템 없는 가격 변경이다.
- **코딩 에이전트일수록 타격이 크다.** 사용자 채팅이 영어든 중국어든, 요청은 영어 스캐폴딩(시스템 프롬프트·툴 스키마·코드·JSON)이 지배한다. 채팅 한 줄은 수만 토큰 스캐폴딩 옆에서 반올림 오차다. 그래서 에이전트에겐 토크나이저의 **영어·코드 거동(≈1.50배)**이 유일하게 의미 있는 숫자다.

## 어떻게 써먹나

- **스티커 말고 당신 콘텐츠로 비교하라.** 대표 샘플을 각 토크나이저에 통과시킨 뒤 요금표를 신뢰하라. 언어와 파일 유형이 배수를 결정한다.
- **토크나이저 변경을 가격 변경으로 취급하라.** 벤더가 "같은 가격"에 새 모델을 내면 토크나이저가 움직였는지 확인하라.
- **토큰당이 아니라 작업당 달러로 측정하라.** "이 빌드가 실제로 얼마 들었나"는 토크나이저와 모델 장황함을 함께 접는다. 벤더 자체 usage 필드가 그라운드 트루스다.
- **`$/Mtok`은 답이 아니라 첫 마디로 다뤄라.** 필요하고 유용하지만 토크나이저를 넘나들면 비교 불가다.

어느 모델도 보편적으로 옳지는 않다. GPT-5.x는 영어·코드에서 토큰이 가벼운 선택, Gemini 3 Flash는 실효 기준 놀랍도록 싸고, Claude는 토큰을 더 쓰더라도 품질로 제 값을 한다. 정직한 결론은 단순하다 — **비교해야 할 가격은 토크나이저를 통과하기 전이 아니라 통과한 후, 당신이 실제로 내는 가격이다.**
