Hugging Face의 오픈소스 로봇 학습 프레임워크 LeRobot이 v0.6.0을 냈다. 이번 릴리스의 한 줄 요약은 팀이 직접 쓴 표현대로 "로봇 학습 루프를 닫는 것(closing the robot learning loop)"이다. 행동하기 전에 미래를 상상하는 정책, 로봇이 성공했는지 알려주는 보상 모델, 실패를 곧바로 학습 데이터로 바꾸는 배포 CLI, 그리고 이 모든 걸 측정할 6개의 새 시뮬레이션 벤치마크가 한 번에 들어왔다.

## TL;DR

- **정책이 미래를 상상한다** — 학습 중에만 미래를 예측하고 추론 시엔 그 world model을 버려 추가 추론 비용 0으로 만드는 world model 정책 3종(VLA-JEPA, LingBot-VA, FastWAM)이 새로 들어왔고, VLA 모델 동물원(GR00T N1.7, MolmoAct2, EO-1, Multitask DiT, EVO1)이 계속 커졌으며, 성공·진행도를 판정하는 통합 보상 모델 API(`lerobot.rewards`, 신규 Robometer·TOPReward 포함)가 생겼다.
- **평가와 배포가 각자 CLI를 얻었다** — 새 시뮬 벤치 6종을 `lerobot-eval` 하나로 돌려 총 9개 벤치마크 패밀리를 한 지붕 아래 모았고, DAgger식 사람 개입 교정을 지원하는 배포 전용 `lerobot-rollout` CLI, FSDP 분산 학습, 플래그 하나로 되는 HF Jobs 클라우드 학습이 추가됐다.
- **데이터셋은 더 빠르고 풍부해졌다** — depth(깊이) 지원, VLM 자동 언어 주석 파이프라인, 커스텀 비디오 코덱, 최대 약 2배 빠른 로딩이 붙었고, 베이스 설치 의존성은 약 40% 줄어 `pip install lerobot`이 진짜 가벼워졌다.

## 미래를 상상하는 정책: world model이 실제로 도움이 되는가

로보틱스가 지금 던지는 큰 질문은 "world model이 로봇 정책에 정말 도움이 되냐"는 것이다. v0.6.0은 이 질문에 답하려는 정책 3개를 서로 다른 접근으로 들여왔다. 셋의 공통점은 학습 과정에서 "미래를 상상"하도록 배운다는 것, 그리고 그 상상 비용을 각자의 방식으로 감당 가능하게 낮춘다는 점이다.

- **VLA-JEPA**: Qwen3-VL-2B 위에 얹은 컴팩트 VLA가 잠재 공간(latent space)에서 미래를 예측하며 행동을 학습한다. 학습 중에는 JEPA world model이 모델 자신의 행동으로부터 다음 프레임을 예측해야 하지만, **추론 시엔 이 world model이 사라진다.** 즉 world model의 지도(supervision) 효과는 얻으면서 추론 비용은 0이다. DROID로 사전학습된 파인튜닝용 베이스를 포함해 체크포인트 3종이 Hub에 올라와 있다.
- **LingBot-VA**: 한 걸음 더 나아가, 미래 비디오와 행동을 청크 단위로 함께 예측하는 자기회귀(autoregressive) 비디오-액션 모델이다. 실제 관측을 되먹여 상상이 현실에서 벗어나지 않게 붙든다. `--policy.save_predicted_video=true`로 로봇이 "상상한" 영상을 저장해 실제 일어난 일과 비교할 수도 있다. 추론은 24~32GB GPU 한 장에서 돈다.
- **FastWAM**: 논문 제목 자체가 질문이다 — "world action model에 테스트타임 미래 상상이 필요한가?" ~5B 비디오 생성 전문가와 컴팩트 액션 전문가를 한 네트워크에 짝지어, 모델이 스스로 롤아웃을 "꿈꾸도록" 학습한다. 그런데 추론 시엔 그 꿈꾸기를 통째로 건너뛰고 액션 청크를 곧바로 디노이징한다. `lerobot/fastwam_base`에서 파인튜닝한다.

세 정책 모두 "학습 때 상상하고 추론 때 버린다"는 공통 철학을 공유한다는 점이 핵심이다. world model의 이득은 취하되, 실전 배포에서 비싼 미래 예측을 실시간으로 돌리지 않아도 되게 설계했다.

## VLA 모델 동물원은 계속 커진다

- **GR00T N1.7**: NVIDIA의 크로스-임바디먼트 파운데이션 모델 최신 오픈 세대. 기존 VLM을 Cosmos-Reason2-2B(Qwen3-VL 기반)로 교체하고 flow-matching 액션 헤드에 물린다. LeRobot 통합은 NVIDIA 원본 Isaac-GR00T 구현과 parity 테스트(같은 입력 → 같은 출력)를 거쳤다. Flash-attention이 이제 선택사항이라 `pip install 'lerobot[groot]'`이 그냥 된다. **N1.7이 LeRobot에서 N1.5를 대체하므로, N1.5가 필요하면 `lerobot==0.5.1`로 핀해야 한다.**
- **MolmoAct2**: Allen Institute for AI의 VLA. 파인튜닝(풀/LoRA)·평가·실로봇 배포까지 전 생애주기가 포팅됐다. 캘리브레이션 보정이 내장된 체크포인트 덕에 SO-100/101에서 zero-shot으로 돌릴 수 있다. bf16 추론이 ~12GB, LoRA 파인튜닝이 24GB GPU 한 장에 들어간다.
- **EO-1**: 상류에서 vision-text-action이 교차된 데이터로 사전학습된 VLA. Qwen2.5-VL-3B 백본 + flow-matching 액션 헤드이고, 논문 저자 중 한 명이 직접 기여했다. `--policy.type=eo1`로 표준 `lerobot-train` 워크플로에서 학습한다.
- **Multitask DiT**: TRI의 Large Behavior Models 레시피를 가져온 ~450M 파라미터 diffusion transformer. CLIP 비전·언어 임베딩으로 조건화돼 자연어로 태스크를 골라 한 모델이 여러 태스크를 배운다. diffusion과 flow-matching 목적함수를 둘 다 지원하며, 직접 학습할 만큼 작다.
- **EVO1**: VLA가 꼭 거대할 필요는 없다는 증명. 0.77B 파라미터(InternVL3-1B 백본 + flow-matching 헤드)로, 웬만한 GPU에서 실시간으로 파인튜닝·구동된다. 2단계 파인튜닝과 Real-Time Chunking을 기본 지원한다.

## 보상 모델: 로봇이 성공했는지 어떻게 아는가

성공 판정과 진행도 추정은 로봇 학습 루프에서 빠져 있던 조각인데, v0.6.0이 이걸 정식으로 품었다. 정책 API를 거울처럼 본뜬 통합 보상 모델 API(`lerobot.rewards`)가 생겼고, 하나의 인터페이스 뒤에 4개 보상 모델(HIL-SERL 보상 분류기, SARM, 그리고 신규 2종)이 붙는다.

- **Robometer**: 사전학습된 범용 보상 모델. `lerobot/Robometer-4B`를 아무 LeRobot 데이터셋에 겨누면 태스크별 추가 학습 없이 원시 비디오 + 언어 지시로부터 진행도와 성공 여부를 채점한다. Qwen3-VL-4B 기반이며 100만 개 이상 로봇 궤적에 대한 궤적 비교로 학습됐다(RSS 2026 논문).
- **TOPReward**: 완전 zero-shot으로, 보상 가중치가 아예 없다. 기성 VLM(Qwen3-VL)을 감싸, 궤적 비디오와 태스크 지시가 주어졌을 때 토큰 "True"의 로그확률을 읽는다. 즉 웬만한 VLM이 그대로 보상 함수가 된다.

둘 다 프레임별 진행도 곡선을 데이터셋에 기록하는 라벨링 스크립트를 함께 제공해, reward-aware behavior cloning(RA-BC)·데이터셋 품질 검사·진행도 오버레이 영상에 바로 쓸 수 있다.

## 데이터셋: 더 빠른 로딩, 더 풍부한 데이터

- **코덱 자유화**: 녹화가 더 이상 하드코딩된 코덱 하나에 묶이지 않는다. `--dataset.rgb_encoder.*` 옵션으로 코덱·품질·픽셀 포맷·GOP·프리셋 전체를 노출하고, `vcodec=auto`가 NVENC·VideoToolbox·VAAPI·QSV 같은 하드웨어 인코더를 탐지한 뒤 소프트웨어 AV1로 폴백한다. 기존 데이터셋은 `lerobot-edit-dataset ... --operation.type reencode_videos`로 한 번에 재인코딩된다.
- **Depth 지원(엔드투엔드)**: Intel RealSense를 꽂고 `use_depth: true`만 켜면 깊이 맵이 밀리미터 단위로 캡처돼 컴팩트한 12비트 depth 비디오로 RGB 옆에 압축 저장되고, 학습 시 물리 단위로 디코딩된다. SO-100/101, Koch, OpenArm, reBot, Unitree G1 등에서 동작한다.
- **대규모 언어 주석**: 데이터셋이 에피소드당 태스크 문자열 하나에서 벗어났다. 이제 타임스탬프 서브태스크·계획·메모리·교정·발화·카메라별 VQA 쌍 같은 풍부한 언어 주석을 네이티브로 저장하고, 새 `lerobot-annotate` CLI가 VLM(예: Qwen2.5-VL-7B-Instruct)으로 에피소드를 보며 자동으로 채운다. YAML 레시피 층이 이 주석을 샘플 시점에 채팅 스타일 학습 메시지로 렌더링한다 — 장기 호라이즌·대화형 로봇 정책이 학습할 바로 그 데이터다.
- **최대 ~2배 빠른 로딩**: 멀티카메라 프레임을 병렬 디코딩하고, 워커가 컴팩트 uint8 프레임을 보내(프로세스 간 메모리 4배 절감), persistent 워커가 에폭 간 디코더 캐시를 유지한다. 대형 데이터셋의 부분 로딩(`episodes=[...]`)은 벤치마크에서 **275초 → 0.06초**로 떨어졌다. 샘플링도 결정적·재개 가능해져, 중단된 학습이 샘플 단위로 정확히 재시작된다.

## 벤치마크: 하나의 CLI로 전부 평가

v0.5.0이 LeRobot을 VLA 평가 허브로 못 박았다면, v0.6.0은 6개 새 시뮬 벤치마크를 모두 같은 `lerobot-eval` CLI로 돌리게 해 이를 실체화했다. 각 벤치는 문서 페이지·Docker 이미지·CI에서 스모크 테스트된 SmolVLA 베이스라인 체크포인트를 갖춘다.

- **LIBERO-plus**: LIBERO를 조명·카메라 시점·재작성 지시 등 7개 축으로 교란한 약 10,000개 변형으로 VLA를 스트레스 테스트. 정책이 어디서 깨지는지 알려준다.
- **RoboTwin 2.0**: SAPIEN 위 양팔 조작 50개 태스크, 강한 도메인 랜덤화. Hub에 10만+ 학습용 궤적이 준비돼 있다.
- **RoboCasa365**: 절차적으로 생성된 2,500개 주방에서 365개 주방 태스크(모바일 매니퓰레이터). 라인업 중 가장 넓은 태스크 표면.
- **RoboCerebra**: 언어 기반 중간 지시 아래 3~6개 서브골을 잇는 장기 호라이즌 행동 평가. 6,660개 에피소드 데이터셋 포함.
- **RoboMME**: 메모리 시험 — 반복 세기, 숨은 물체 추적, 시연 절차 모방. 4개 메모리 스위트 16개 태스크.
- **VLABench**: 물리 질문부터 커피 내리기 같은 복합 태스크까지, 조작에서의 지식·추론을 테스트.

기존 LIBERO·Meta-World·NVIDIA IsaacLab-Arena까지 합치면 한 지붕 아래 **9개 벤치마크 패밀리**다. 평가도 빨라져 병렬 eval이 이제 async 벡터화 환경을 기본값으로 쓰며 최대 2배 빠르다.

## 학습·추론: 배포가 데이터 수집이 되는 순간

- **`lerobot-rollout` — 배포 전용 CLI**: 예전엔 정책 배포가 `lerobot-record` 위의 임시방편이었다. 이제 배포가 독립 워크플로가 됐고, 교체 가능한 전략과 추론 백엔드(느린 호환 VLA용 Real-Time Chunking 포함)를 갖는다. 전략은 base(그냥 실행), sentry(계속 녹화·순환 업로드), highlight(링버퍼로 마지막 N초 저장), episodic(고전적 에피소드/리셋), 그리고 **dagger**가 있다.
  - DAgger 전략은 배포를 데이터 수집으로 바꾼다: 정책이 도는 걸 지켜보다 잘못되는 순간 키(또는 USB 풋페달)를 눌러 리더 암으로 교정을 직접 시연하고 제어권을 넘긴다. 능동 리더는 넘겨받기 전 팔로워 자세로 구동돼 인수인계가 매끄럽다(jerk-free). 모든 교정 프레임엔 개입(intervention) 플래그가 붙어 다음 파인튜닝에 바로 쓸 데이터셋이 된다. **배포 → 교정 수집 → 파인튜닝 → 반복**의 로봇 학습 플라이휠이 이제 CLI 플래그가 됐다.
- **FSDP — GPU보다 큰 모델 학습**: 로봇 파운데이션 모델이 단일 GPU를 넘어서기 시작했다. Accelerate를 통한 FSDP로 파라미터·그래디언트·옵티마이저 상태를 GPU들에 샤딩하고, 체크포인트는 다시 모여 여느 정책처럼 로드되는 단일 `model.safetensors`가 된다. FSDP 실행을 다른 GPU 개수로 재개할 수도 있다.
- **HF Jobs 클라우드 학습**: GPU가 없어도 된다. 똑같은 `lerobot-train`에 `--job.target=a10g-small` 같은 플래그 하나만 붙이면 클라우드에서 돈다. LeRobot이 필요 시 로컬 데이터셋을 비공개 Hub 레포로 밀고, 잡을 제출하고, 로그를 터미널로 스트리밍하고, 끝나면 학습된 정책을 Hub에 올린다. T4부터 8x H200까지 고를 수 있고 컴퓨트는 사용량 과금이다.

## 코드베이스: 더 가볍고 깔끔하게

`pip install lerobot`이 베이스 의존성 약 40% 감소로 진짜 가벼워졌다. 기능별 extras(`[training]`, `[core_scripts]`, `[evaluation]` 등)가 나머지를 덮고, 의존성 누락 에러가 어떤 extra를 추가할지 정확히 알려준다. LeRobot 데이터셋만 쓴다면 하드웨어 관련 의존성을 설치할 필요가 없다. 지원 PyTorch는 2.7~2.11로 이동, Linux uv 설치엔 CUDA 12.8 휠이 기본 핀된다. `--policy.dtype=bfloat16`이 이제 Accelerate로 진짜 혼합정밀 학습을 구동하고, 커밋된 `uv.lock`이 CI·Docker·개발의 권위 있는 의존성 스펙이다. `--display_mode=foxglove`로 원격 시각화를 스트리밍하고, 녹화 중 키보드 제어가 Wayland·SSH·헤드리스·macOS(접근성 권한 없이)에서 동작한다.

## 왜 중요한가

- **로봇 학습 루프가 실제로 닫혔다.** 그동안 흩어져 있던 조각 — 상상하는 정책, 성공을 판정하는 보상 모델, 배포를 데이터 수집으로 바꾸는 CLI, 그걸 측정하는 벤치마크 — 이 한 릴리스에 정렬됐다. 특히 DAgger 롤아웃은 "배포에서 실패한 순간이 곧 다음 학습 데이터"라는 플라이휠을 CLI 플래그 수준으로 내렸다. 이게 로보틱스판 데이터 엔진의 문턱을 크게 낮춘다.
- **world model의 "학습 때만 상상" 패턴이 실전적이다.** VLA-JEPA·FastWAM처럼 추론 시 world model을 버리는 설계는 "미래 예측의 이득은 얻되 실시간 배포 비용은 안 낸다"는, 학계 아이디어를 실전에 앉히는 현실적 절충이다.
- **진입 장벽이 전방위로 낮아졌다.** 40% 가벼운 설치, 24GB·12GB급 GPU에서 도는 모델들(EVO1 0.77B, MolmoAct2), GPU 없이 플래그 하나로 되는 클라우드 학습, 브라우저 UI(LeLab)까지 — 취미가·학생·소규모 팀이 실물 로봇 학습에 진입하는 비용이 계속 떨어지고 있다.

## 어떻게 써먹나

- **실물 로봇 데이터 플라이휠 구축**: `lerobot-rollout --strategy.type=dagger`로 배포하며 정책이 실수하는 순간만 리더 암으로 교정해 개입 플래그가 붙은 교정 데이터셋을 모으고, 그걸로 파인튜닝 → 다시 배포를 반복한다. 처음부터 대량 텔레옵을 안 해도 실패 지점 위주로 데이터가 쌓인다.
- **GPU 없이 학습 시작**: 로컬 데이터셋만 있으면 `lerobot-train ... --job.target=a10g-small`로 HF Jobs에 던져 사용량 과금으로 학습하고, 결과 정책을 Hub에서 바로 받는다. T4부터 8x H200까지 규모를 고른다.
- **라벨 없이 데이터셋 품질 점검**: `lerobot/Robometer-4B`(사전학습) 또는 TOPReward(완전 zero-shot)로 기존 데이터셋에 프레임별 진행도·성공 점수를 매겨, 나쁜 궤적을 걸러내거나 reward-aware BC 학습에 활용한다.
- **주석 자동 확장**: `lerobot-annotate`에 VLM을 물려 에피소드를 보게 하고, 태스크 문자열 하나짜리 데이터셋을 서브태스크·계획·VQA가 붙은 장기 호라이즌 학습용 데이터로 승격시킨다.
- **정책 견고성 스트레스 테스트**: 배포 전 `lerobot-eval`로 LIBERO-plus(약 1만 교란 변형) 등에 정책을 걸어, 조명·시점·지시 변형에서 어디가 깨지는지 미리 확인한다.
