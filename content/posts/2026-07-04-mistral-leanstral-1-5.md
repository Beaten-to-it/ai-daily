Mistral이 2026년 7월 2일 **Leanstral 1.5**를 내놨다. Lean 4 정형증명(formal proof)에 특화된 모델이고, Apache-2.0 라이선스로 가중치까지 완전 공개, 게다가 무료 API까지 붙였다. 핵심 숫자부터 보면 왜 이게 화제인지 감이 온다.

## TL;DR

- **총 119B / 활성 6B 파라미터의 무료(Apache-2.0) 형식검증 모델.** miniF2F를 val·test 양쪽 100%로 완전 포화시키고, PutnamBench 672문제 중 587문제를 풀었으며, 대학원·박사급 추상대수 벤치 FATE-H·FATE-X에서 각각 87·34문제 해결로 새 SOTA를 세웠다.
- **비용 효율이 본론이다.** PutnamBench에서 Seed-Prover 1.5(high 세팅, 문제당 $300+ 추정)를 7문제 앞서면서 문제당 약 $4에 돌렸다. 토큰 예산을 25k→4M로 키우면 성능이 매끄럽게 단조 상승(50k=44문제 → 200k=244 → 1M=493 → 4M=587).
- **수학 넘어 실제 코드 검증까지.** Rust→Lean 파이프라인으로 57개 오픈소스 리포를 돌려 11개 진짜 버그(그중 5개는 GitHub 미보고)를 자동 발굴했고, AVL 트리의 O(log n) 시간복잡도를 270만 토큰·22회 컨텍스트 압축을 거쳐 증명했다.

## 무엇을 공개했나

Leanstral은 원래 Lean 4에서 실용적 증명 엔지니어링을 겨냥한 오픈 모델 계열이다. 이번 1.5는 그 성능 업그레이드판이다. 구조는 **총 119B 파라미터 중 6B만 활성화**하는 형태 — 원문 표현대로면 "활성 파라미터 6B"라 추론 비용이 작다는 게 뒤이어 나오는 비용 우위의 배경으로 보인다.

학습은 3단계다: **mid-training → 지도 미세조정(SFT) → CISPO를 쓴 강화학습(RL)**. RL은 두 환경에서 돌렸다.

- **멀티턴 환경**: 정리(theorem)를 주면 증명하거나 반증한다. 증명을 제출 → Lean 컴파일러 피드백을 받고 → 다시 다듬는 루프. 컴파일되면 성공, 아니면 예산 소진까지 반복.
- **코드 에이전트 환경**: 모델이 개발자처럼 **날것의 파일시스템**에서 작동한다. 파일을 편집하고, bash를 돌리고, Lean 언어서버(LSP)로 goal·에러·타입 정보를 실시간 조회한다. 리포지토리의 부분 증명 완성, 보조 정리(lemma) 작성, 여러 번의 컨텍스트 압축을 넘나드는 장기 작업(long-horizon)을 이렇게 소화한다. 최종 정합성은 Mistral이 포크한 SafeVerify로 검증한다.

## 벤치마크: 포화, 그리고 비용

평가 벤치는 다섯이다. **miniF2F**(초등~IMO급 크로스시스템 형식수학), **PutnamBench**(Putnam 대회 672문제, 긴 증명 사슬 요구), **FATE-H/FATE-X**(각각 대학원·박사급 추상대수 — 군론·환론·가군론), **FLTEval**(페르마 마지막 정리 리포의 실제 PR 기반, 실무 복잡도).

결과:
- **miniF2F**: val·test 100% 완전 포화.
- **FATE-H/X**: 각각 87문제·34문제 해결로 새 SOTA (자연어 가이드 없는 Goedel-Architect, Seed-Prover 1.5 high, AxProverBase와 비교).
- **PutnamBench**: Seed-Prover 1.5 high를 7문제 앞섬. 여기서 핵심은 **비용**이다. Leanstral은 문제당 약 $4, Seed-Prover high는 문제당 10 H20-day 예산으로 추정 $300+. 더 높은 순위 프로버들은 조건이 다르다 — 일부는 자연어 증명 가이드를 받거나(Leanstral은 안 받음), Aleph Prover처럼 문제당 $54–68로 훨씬 비싸다.

가장 인상적인 대목은 **test-time scaling**이다. PutnamBench Pass@8에서 시도당 토큰 예산을 25k에서 4M까지 올리자 성능이 **단조·매끄럽게** 올라갔다: 50k에서 44문제 → 200k에서 244 → 1M에서 493 → 4M에서 587. 증명이 길어진다고 포기하지 않고 계속 추론·파일 편집·수정을 이어가며 예산을 그대로 "풀린 문제"로 환전한다는 뜻이다. 뒤에 나오는 AVL 트리 증명(270만 토큰, 22회 압축)이 같은 행동의 실물 사례다.

FLTEval도 이번에 완전 오픈소스로 풀었다. Leanstral 1.5는 pass@1을 21.9→28.9, pass@8을 31.9→43.2로 끌어올렸고, **Opus 4.6의 39.6을 1/7 비용에 앞선다**. 3~10배 큰 오픈소스 모델들과의 격차도 더 벌렸다.

## 코드 검증 사례 두 개

수학용으로 주로 학습됐지만 코드 검증에서도 세다는 걸 두 사례로 보여준다.

**1) AVL 트리 시간복잡도 증명.** AVL 트리는 삽입·삭제 시 재균형으로 O(log n) 높이를 유지하는 자가균형 이진탐색트리다. Leanstral은 실제 구현에 대해 이 시간복잡도 보장을 증명했다 — 트리의 재귀 구조를 반영한 구조적 귀납법, 모나딕 시간 추적(TimeM 모나드)의 조심스러운 처리, 재균형 경로에 대한 전수 case 분석이 필요한 작업이다. **270만 토큰·22회 압축**에 걸쳐 TimeM 모나드를 층층이 풀어 헤쳐, 삽입에 대해 "높이 단위당 약 48스텝 + 상수"라는 거의 tight한 경계를 세우고, 높이와 트리 크기를 로그 관계로 연결해 삽입·삭제가 실제로 O(log n)임을 완전 검증했다.

**2) 버그 발굴.** 자동 파이프라인을 만들었다: **Aeneas가 Rust 코드를 Lean으로 번역** → Leanstral이 코드에서 사용자 의도를 추론해 정합성 속성(correctness property)을 생성 → 각 속성을 4번 증명 시도 → 전부 실패하면 부정(negation)을 다시 4번 증명 시도. **57개 리포**에서 47개 위반 속성을 잡았고, 그중 **11개가 진짜 버그, 5개는 GitHub 미보고**였다. 대표 사례가 `datrs/varinteger`의 zigzag 디코딩용 sign 함수 — 입력 `Std.U64.MAX`에서 `(value + 1)`이 오버플로해 디버그 모드에선 크래시, 릴리스 모드에선 조용한 데이터 손상(silent corruption)을 일으키는, 테스트·퍼징이 보통 놓치는 엣지 케이스다. 파이프라인이 이걸 자동으로 잡아냈다.

## 왜 중요한가

- **"정형검증은 비싸서 실무엔 무리"라는 통념을 정면으로 친다.** 문제당 $4 · 활성 6B · Apache-2.0 무료 조합은, 지금까지 SOTA 프로버들이 문제당 수백 달러를 태우던 영역을 한 자릿수 달러로 끌어내린다. 형식검증의 진입장벽이 비용에서 접근성으로 넘어가는 신호다.
- **test-time scaling이 형식증명에서 실제로 먹힌다는 증거.** 25k→4M 토큰에서 성능이 꺾이지 않고 단조 상승한다는 건, "예산을 더 주면 더 어려운 정리를 푼다"는 예측 가능한 곡선을 준다. 증명 작업의 계획·예산 편성이 가능해진다.
- **버그 발굴이 데모가 아니라 파이프라인이다.** Rust→Lean 자동 번역 + 속성 자동생성 + 증명/반증 루프로 실제 오픈소스에서 미보고 버그를 잡았다. 퍼징이 놓치는 오버플로 엣지케이스를 정형방법이 자동으로 집는, 재현 가능한 워크플로다.

## 어떻게 써먹나

가중치는 Hugging Face에 있고, `leanstral-1-5`라는 이름의 **무료 API 엔드포인트**로도 바로 쓸 수 있다. Mistral은 자사 에이전트 도구 Vibe에서 쓰길 권한다 — 원문 기준 대략의 흐름은 (1) `mistral-vibe` 설치·셋업, (2) 에이전트 내에서 Leanstral 설치, (3) `vibe --agent lean`으로 실행, (4) 선택적으로 Lean LSP MCP 서버 연결(모델이 goal·타입 정보를 실시간 조회하게 해줘 강력 권장), (5) 정리 증명·증명 디버깅·리포 기여를 시킨다.

실전 각도로 보면 세 갈래다: **① Lean 4 리포의 부분 증명 완성·보조정리 자동화**(코드 에이전트 환경이 이걸 겨냥해 학습됨), **② 기존 코드베이스에 대한 정합성 속성 검증**(AVL 사례처럼 시간복잡도·불변식 증명), **③ Rust 코드 버그 헌팅 파이프라인**(Aeneas 번역 → 속성 생성 → 증명/반증). 특히 무료·오픈이라 사내 정형검증 실험을 비용 리스크 없이 붙여볼 수 있다.
