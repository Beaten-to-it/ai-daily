Vectoral의 Matt Lenhard가 AI 게이트웨이를 운영하며 겪은 남용(abuse) 경험에서 출발해, 중국어 포럼에서 운영자들이 공개적으로 주고받은 대화를 추적한 조사 노트다. 요지는 하나다 — 미국 모델 접근권을 훔치거나 풀링(pooling)해 헐값에 되파는 **'릴레이(중전참, 中转站) 시장'**이 이미 성숙한 산업으로 자리 잡았고, 그 뒤에는 정교한 4단계 공급망이 돌아가고 있다는 것.

## TL;DR
- 미국 모델 접근권을 훔치거나 풀링해 되파는 '릴레이(중전참)' 시장이 이미 성숙 단계에 도달했고, 상위 10개 릴레이만 합쳐 월 360만 방문을 찍는다.
- 공급망은 4단계다 — 상류(카드/계정 상인) → 중류(계정 풀) → 하류(릴레이/중전참) → 최종 사용자(싼 토큰을 좇는 개발사, 그리고 **모델 증류**를 노리는 상업 구매자).
- 방어에 은탄환은 없다. 계정 생성 비용을 올리고 돈·행동 신호를 감시하며 계정당 지출 상한·동시성 제한을 걸고, 잡으면 '조용히' 스로틀링해 공격자에게 어떤 신호를 고쳐야 하는지 알려주지 않는 게 현실적 대응이다.

## 릴레이(중전참)란 무엇인가

릴레이는 '중전참(transfer station)', 즉 트래픽을 미국 모델로 **중계·프록시**해 주면서 대폭 할인가에 파는 서비스다. 저자가 든 예시가 시장의 성격을 압축한다 — 한 운영자의 가격 비교 사이트에는 **공식 Anthropic 크레딧 $3,333어치를 425 RMB(약 $60 수준)에** 파는 패키지가 올라와 있었다. 실효 환산으로 **$1을 쓰면 공식 사용량 기준 약 $0.13**을 쓰는 셈이다. 저자가 추적하는 릴레이 중 가장 싼 곳은 공식가 대비 **97.8% 할인**까지 내려간다.

할인율 순위 상위권은 Now Coding(97.8%), I Code Easy(97.1%), Claude ZZ(96.6%), Doro(96.4%), UoCode(96.3%) 순으로, 저자는 총 49개 릴레이를 추적한다고 밝힌다. 90%대 중반 할인이 '평범한' 수준이라는 게 이 시장의 왜곡된 정상성을 보여준다.

## 시장은 4단계로 굴러간다

원문이 정리한 공급망은 위에서 아래로 네 겹이다.

- **상류 — 카드상(卡商)·호상(号商):** 미국·유럽 결제 검증을 통과하도록 만들어진 가상 신용카드, 그리고 대량 등록된 계정을 판다. 남용의 원재료를 공급하는 층이다.
- **중류 — 계정 풀(账号池):** 상류 계정 수백 개를 모아 인증 토큰과 레이트리밋을 관리하고, 계정이 플래그되면 페일오버(failover)하며, 하류가 소비할 **단일 API 표면**으로 노출한다. 여기서 눈여겨볼 대목 — 재고는 랩(lab) API 계정만이 아니다. OpenAI·Anthropic·Google 직접 크레딧과 나란히, **Kiro나 antigravity 같은 소비자 제품**에서 '리버스 엔지니어링'으로 뽑아낸 애플리케이션 레이어 접근권도 함께 유통된다. 풀 입장에선 토큰이 랩에서 왔든 그 위에 지어진 앱에서 왔든 상관없다. 모델을 재판매하거나 노출하는 것이면 무엇이든 표적이다.
- **하류 — 릴레이/중전참:** 소비자 대면 층. 풀의 API를 깔끔한 중국어 제품으로 감싸 과금·인보이스를 처리하고 위챗 고객지원 그룹을 돌리며 가격으로 경쟁한다.
- **최종 사용자:** 싼 추론을 좇는 개인 개발자·스타트업·중견 SaaS, 그리고 이 인프라로 **모델 증류(distillation)**를 돌리는 더 큰 상업 구매자들.

실제로는 이 층들이 뒤섞인다. 많은 운영자가 풀과 릴레이를 동시에 돌리고, 포럼 참여자들도 '풀'과 '중전참'을 사실상 같은 뜻으로 쓴다.

## 릴레이를 돌리는 소프트웨어 — one-api / new-api

기술적으로 흥미로운 부분이다. 저자가 살펴본 릴레이 거의 전부가 **one-api** 또는 그 포크인 **new-api**, 두 오픈소스 프로젝트 중 하나 위에서 돈다. 둘 다 OpenAI 호환 게이트웨이다. 운영자는 패널을 배포하고 **채널(渠道)** 집합을 추가하는데, 각 채널은 '공급자 + API 키 풀'을 의미한다. 패널은 OpenAI API와 동일한 단일 엔드포인트를 노출하므로, 구매자는 기존 SDK의 URL만 릴레이 주소로 바꾸면 그대로 붙는다. 요청이 올 때마다 풀에서 키를 하나 뽑아 상류로 포워딩하고, 응답을 돌려준 뒤 사용량 × **배율(倍率)**로 쿼터를 차감한다.

new-api는 more actively developed 포크로, 차이는 대체로 '상업성'이다 — 셀프서비스 결제·충전, 이미지·비디오·오디오 모델이 붙어 있다. 다만 저자가 추적한 릴레이에서 **one-api가 new-api보다 약 4배 자주** 등장한다. 팔기 위해 만들어진 건 new-api지만, 더 널리 퍼진 건 원본 쪽이다.

**여기서 선을 긋자.** 원문도 명시하듯 one-api·new-api 자체는 중립적이고 합법적인 도구다. 자기 계정을 단일 게이트웨이 뒤에 두고 팀 쿼터·지출 추적을 붙이려는 정상 기업들이 얼마든지 셀프호스팅한다. 릴레이가 선을 넘는 지점은, 채널을 운영자 자기 키가 아니라 **훔치거나 유출되거나 풀링된 키**로 채우고, 공급자 약관을 어기며 그 접근권을 재판매할 때다.

## 남용은 어떤 얼굴로 오는가 (방어자가 마주하는 위협 지형)

원문이 정리한 남용 유형 — 방어 설계의 관점에서 읽어야 할 '공격 표면 목록'이다.

- **무료체험 남용:** 계정 생성을 자동화해 대량으로 무료 크레딧을 챙긴 뒤 그 트래픽을 자기 사용자에게 프록시한다.
- **차지백 공격:** 사용 기간이 끝난 뒤 결제를 취소(chargeback)해 비용을 회수하거나, 애초에 훔친 카드를 쓴다.
- **선불카드:** 한도가 정해진 선불카드로 계정에 자금을 넣는다.
- **오픈 추론(open inference):** 가드레일이 허술한 지원 챗봇은 트래픽을 프록시로 통과시키기 좋은 표적이 된다.
- **월렛 소진(Denial of Wallet):** 엄밀히 릴레이 기법은 아니지만 저자가 추적 중인 신종 남용. 오로지 공급자의 지출을 태우려고 동시 요청을 퍼붓는다. 위 방법 어느 것으로든 촉진될 수 있고, 결정적 차이는 **금전적 동기가 없다**는 점이다.

## 구매자는 누구이고, 왜 사는가

주된 용도는 세 가지 — 싼 토큰, 지역 제한 우회, 그리고 **모델 증류**다. 특히 증류에 대한 포럼 발언이 이 시장의 규모감을 드러낸다.

> "증류는 Claude/CodeX 모델로 국산 모델을 학습시킨다. … 프로그래밍 역량이 강한 회사들은 죄다 Claude를 증류하고 있고, 수십억 RMB 규모의 산업 사슬이다." — V2EX 스레드 번역 인용

또 다른 답글은 "이건 사실일 뿐 아니라, 업계의 많은 증류업자가 수백만을 벌었다"고 덧붙인다. 신규 릴레이가 "온라인 첫날 20TB 트래픽을 받았다"는 증언까지 나온다. 가격 비교 사이트, 제휴(affiliate) 프로그램, 게이트웨이 제품이 이미 갖춰진 성숙한 생태계다.

정상화의 상징적 장면 하나 — 한 릴레이 디렉터리(hvoy.ai, 스스로는 릴레이 진위 검증·가격 비교 도구를 표방)는 **매일 $100짜리 API 키 50개를 추첨**으로 나눠준다. 일일 체크인으로 얻은 포인트 20점으로 티켓 한 장을 사고 라운드당 최대 3장까지 살 수 있다. 웃지 못할 대목은 '공정성 연출'이다 — 추첨 시드는 최신 비트코인 블록 해시, 당첨자는 Partial Fisher-Yates 셔플로 뽑고, 전체 참가 명단을 추첨 전 스냅샷으로 공개한다. 크립토 도박 사이트가 '조작하지 않았다'를 증명할 때 쓰는 바로 그 기법이다.

## 왜 중요한가

1. **AI 제품을 운영한다면 이건 남의 이야기가 아니다.** 저자 자신이 게이트웨이를 돌리며 겪었고, 지인 회사들이 하루 수백만 달러의 남용 손실을 봤다는 이야기를 전한다. 무료 크레딧, 지원 챗봇, 결제 흐름 — 모델을 노출하는 모든 표면이 풀의 재고가 될 수 있다.
2. **위협 지형이 랩 API 너머 애플리케이션 레이어로 확장됐다.** Kiro·antigravity 같은 소비자 앱에서 뽑아낸 접근권이 유통된다는 사실은, "우리는 API 키를 직접 팔지 않으니 안전하다"는 가정을 무너뜨린다. 모델 위에 앱을 얹은 순간 당신도 표적 목록에 오른다.
3. **KYC는 남용을 없애는 게 아니라 이동시킨다.** 저자의 예측 — Anthropic 등이 KYC·신원 검증을 강화할수록 남용은 사라지지 않고 더 약한 애플리케이션 레이어로 옮겨간다. 방어를 랩에만 의존할 수 없다는 뜻이다.

## 어떻게 써먹나 (제공자 방어 체크리스트)

원문의 "How Providers Can Defend Themselves"를 실무 순서 — 계정 생성 → 탐지 → 피해 억제 — 로 정리했다. 은탄환은 없고, 공격 비용을 '수지가 안 맞을 만큼' 올려 더 쉬운 표적으로 옮겨가게 만드는 게 목표다.

**진입 비용을 올린다.**
- 대량 계정 생성을 어렵게 만들고, 신규 계정의 지출 상한을 낮게 건다.
- 브라우저 자동화 신호를 확인한다. 클라이언트 측 탐지는 모두 우회 가능하지만, 마찰 하나하나가 공격자 비용을 올린다.

**돈과 행동을 감시한다.**
- 선불카드·가상카드·불일치 청구정보, 그리고 카드 유효성 테스트용 소액 결제를 플래그한다.
- 실사용자라면 나오지 않을 패턴을 본다 — 가입에서 첫 토큰까지 걸린 시간, 선택한 모델, (측정 가능하다면) 프롬프트 적합성, 계정 나이, IP 신호(프록시·VPN·국가).
- 계정을 클러스터링한다. IP 시빌(sybil)과 공유 디바이스 지문으로 '별개인 척하는' 계정들을 한 운영자로 엮는다.
- AI 지출에 이상탐지 모니터·알림을 걸어, 남용이 시작되면 스위치를 내릴 수 있게 한다.

**뚫린다는 전제로 손실을 가둔다.**
- 계정당 지출 상한(spend cap)·지출 잠금(spend lock)·동시성 제한을 강제한다.
- **모든 in-flight 요청에 예산을 예약**해, 동시 호출이 한도를 넘어 폭주하지 못하게 한다.
- 신규 계정은 낮은 한도로 시작하고, 나이와 검증된 카드로 한도를 '벌게' 한다.
- 세션 중 위험도가 올라가면 CAPTCHA나 추가 신원 검증 같은 마찰을 끼운다.
- 잡았을 때는 **조용히 스로틀링**한다. 깔끔한 에러는 공격자에게 '어떤 신호를 고치고 다시 오면 되는지'만 알려줄 뿐이다.
