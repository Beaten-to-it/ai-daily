OpenAI가 **ChatGPT Work**를 내놨다. 한 줄로 요약하면 "질문에 답하는 챗봇"에서 "실제 결과물을 만들어 내는 업무 에이전트"로의 포지션 이동이다. 연결된 앱과 워크플로를 가로질러 정보를 긁어모아 시트·슬라이드·문서·웹앱 같은 **완성된 산출물**을 만들고, 복잡한 프로젝트를 작은 단계로 쪼개 몇 시간 동안 스스로 붙잡고 진행한다는 게 핵심 주장이다.

## TL;DR
- ChatGPT에 **Codex 기술을 내장**해, 연결된 앱을 넘나들며 시트·슬라이드·문서·웹앱을 만들고 멀티스텝 작업을 몇 시간씩 자율 수행하는 에이전트 **ChatGPT Work**가 출시됐다. 구동 모델은 오늘 함께 공개된 **GPT‑5.6**.
- **Codex 앱이 새 ChatGPT 데스크톱 앱으로 통합**된다. 데스크톱에서는 로컬 파일·앱 접근, 내장 브라우저, Computer Use(대신 클릭·타이핑)까지 지원하고, 기존 데스크톱 앱은 **ChatGPT Classic**으로 개명된다. 독립형 **Atlas 브라우저는 단계적 폐기(sunset)**.
- 웹·모바일은 오늘 Pro·Enterprise·Edu부터 롤아웃(Plus·Business는 며칠 내), 데스크톱 앱은 오늘 전 세계 Mac·Windows에 배포되며 **Chat·Work·Codex가 Free 포함 전 플랜에서** 쓸 수 있다.

## 무엇이 나왔나

**ChatGPT Work**는 ChatGPT 안에서 도는 에이전트다. 원문이 드는 예시는 월말 예산 변동 분석, 소스 자료를 마케팅 캠페인 브리프로 전환, 세일즈 미팅 준비 같은 것들이다. 사용자는 진행 상황을 따라가며 질문에 답하고, 방향을 바꾸고, 중요한 액션은 승인하는 식으로 개입한다. 한 번의 요청으로 "고객 리서치 → 캠페인 브리프 → 마케팅 자산 → 시장별 현지화"처럼 **워크플로 전체**를 맡길 수도 있다고 한다.

구동 모델은 오늘 같이 롤아웃되는 **GPT‑5.6**이다. OpenAI는 이 모델이 멀티스텝 추론과 "당신의 템플릿·참조 파일을 따르는 산출물 생성"에서 SOTA라고 표현한다. 여기서 Codex의 존재감이 크다. OpenAI 주장으로 **주간 500만 명이 Codex를 쓰고, 그중 100만 명 이상이 소프트웨어 개발 외 업무에 쓴다** — 코딩 에이전트로 시작한 물건이 일반 업무 에이전트로 번지고 있다는 서사이고, ChatGPT Work는 그 기술을 챗 인터페이스에 얹은 것이다.

**연결(Plugins)** 이 전제 조건이다. Slack·Teams, Google Drive·SharePoint, 이메일·캘린더, CRM, 프로젝트 트래커 등을 붙이면 ChatGPT가 프롬프트에 맞춰 알아서 참조하거나, `@앱이름`으로 특정 소스를 직접 지목할 수 있다. 새 통합 플러그인 디렉터리로 한곳에 모았다.

**Scheduled Tasks(예약 작업)** 로 자리를 비운 사이에도 일을 굴린다. 예: Teams·Slack의 새 메시지를 문서·슬라이드로 갱신, 매일 아침 대시보드 변화 요약 리포트, 고객 피드백의 반복 테마를 우선순위 매긴 제품 아이디어로 전환. 이벤트 발생 시 1회 실행하거나 주기적으로 돌리거나 변화를 모니터링하는 세 가지 모드다.

**Sites(퍼블릭 베타)** 도 함께 나왔다. 작업물이나 아이디어를 인터랙티브 사이트/웹앱으로 만들어 URL로 공유하는 기능 — 라이브 대시보드, 프로젝트 트래커, 런치 캘린더, 프로토타입, 내부 포털 같은 것들. ChatGPT 안에서 바로 테스트하고, 원본 데이터가 바뀌면 갱신도 시킨다.

**데스크톱이 상한선을 올린다.** 데스크톱 앱은 로컬 파일·앱을 직접 다루고, 내장 브라우저로 웹 기반 작업을 한 곳에서 하며, **Computer Use**로 앱·툴·브라우저를 가로질러 백그라운드에서 클릭·타이핑·파일 이동을 대신한다. Chrome 확장은 사이드바에서 바로 쓰도록 업데이트된다. 이 흐름의 대가로 **독립형 Atlas 브라우저는 단계적 폐기**되고, ChatGPT로의 전환 안내가 예고됐다.

**개발자 관점의 핵심 통합:** 오늘부터 **Codex 앱이 새 ChatGPT 데스크톱 앱에 합쳐진다.** Codex는 그대로 코딩 에이전트로 남되 새 기능이 붙는다 — diff 안 인라인 편집, 사이드 패널 PR 리뷰, (GPT‑5.6 기반) 더 빠른 computer use, **단일 프로젝트에서 다중 레포 지원.** 기존 Codex 앱은 업데이트하면 그대로 새 데스크톱 앱이 되고, 개발자는 Codex 뷰를 기본으로 두고 아이콘도 Codex 로고로 바꿀 수 있다. 반대로 기존 ChatGPT 데스크톱 앱은 **ChatGPT Classic**으로 이름이 바뀐다.

**보안·거버넌스**는 ChatGPT Enterprise 기반 위에 세웠다. Enterprise·Edu 관리자는 접근 권한, 참조 가능한 컨텍스트, 연결 툴, 허용 액션을 중앙 관리하고, Compliance API로 대화·액션을 감사한다. 눈에 띄는 건 **Auto-review** — 연결된 툴·API가 얽힌 중요 액션을 실행 전에 상위 모델이 검토해 민감 정보 무단 공유를 막는다는 것. OpenAI는 적대적 레드팀 과정에서 이 auto-review가 **보호 데이터 추출 시도를 100% 차단했다(훈련 때 못 본 공격 포함)** 고 주장한다.

**과금**은 일반 챗과 다르다. ChatGPT Work는 길고 무거운 작업용이라 **Codex와 동일한 사용량 구조**를 따르고, 복잡한 작업일수록 플랜 포함 사용량을 더 먹는다. Enterprise·Edu 관리자는 Admin Console에서 워크스페이스 기본값·그룹 한도·개인 오버라이드로 지출을 통제할 수 있다.

## 왜 중요한가

- **"챗봇 → 업무 실행자"로의 무게중심 이동이 제품 레벨에서 굳어졌다.** 몇 시간짜리 멀티스텝 작업, 예약 실행, 로컬 파일·Computer Use — 데모용 자율 에이전트가 아니라 기본 UI로 편입됐다는 게 신호다.
- **Codex가 개발 도구를 넘어 일반 업무 에이전트의 엔진이 됐다.** 주간 500만 사용자, 그중 100만+가 비개발 업무(OpenAI 주장)라는 숫자는 "코딩 에이전트 인프라가 곧 화이트칼라 업무 에이전트 인프라"라는 베팅을 보여준다. 다중 레포 프로젝트·인라인 diff 편집·사이드 패널 PR 리뷰는 개발자에게 직접적 실익이다.
- **브라우저 전략 정리.** 별도 Atlas 앱 대신 데스크톱 내장 브라우저 + Chrome 사이드바로 수렴한다. 에이전트가 웹을 조작하는 능력을 별도 브라우저가 아니라 ChatGPT 본체에 담겠다는 것.
- **단, 100% 류 수치는 OpenAI 내부·자체 레드팀 주장이다.** "사내 팀 거의 100% 사용", "추출 시도 100% 차단" 모두 자기 발표다. 로컬 파일·Computer Use·연결된 CRM에 에이전트가 쓰기 권한을 갖는 순간 프롬프트 인젝션·과잉 액션·오작동 반경이 커진다 — auto-review와 승인 게이트가 실제 얼마나 막는지는 외부 검증 전엔 낙관 금지.

## 어떻게 써먹나

- **가장 잘 아는 반복 업무 하나부터.** 원문 권고대로, 이미 손에 익은 작업(월말 마감, 리서치→브리프, 미팅 준비)을 시켜 결과물과 개입 지점을 관찰하는 게 학습 경로다. 잘 모르는 작업으로 시작하면 검증 비용만 커진다.
- **개발자라면 Codex 통합부터.** 데스크톱 앱 업데이트로 인라인 diff 편집·사이드 패널 PR 리뷰·다중 레포 프로젝트를 바로 시험. Free 포함 전 플랜에서 Chat·Work·Codex가 열리므로 진입 장벽이 낮다.
- **자동화는 Scheduled Tasks로.** "매일 아침 대시보드 변화 요약해 리포트", "새 피드백 오면 슬라이드 갱신" 같은 얇은 반복 작업을 먼저 예약해 보고, ROI가 보이면 워크플로를 늘린다.
- **권한은 최소로 시작.** 연결 툴·허용 액션·승인 필요 지점을 좁게 잡고, 민감 시스템 쓰기는 승인 게이트를 걸어 두라. 관리자라면 spend control로 사용량이 새는지 초기에 잠근다.
- **과금 모델 유의.** 무거운 작업은 Codex식 사용량을 먹는다. "챗 한 번" 감각으로 긴 자율 작업을 남발하면 플랜 한도가 빨리 소진될 수 있다.
