1Password가 Claude용 브라우저 통합 기능 **"1Password for Claude"**를 내놨다. 핵심은 한 문장이다 — Claude 에이전트가 로그인이 필요한 작업을 대신 처리하되, 당신의 비밀번호 자체는 절대 보지 못한다.

## TL;DR

- 1Password가 Claude 브라우저 통합을 출시 — Claude가 저장된 로그인 자격증명으로 여행 예약·계정 관리 같은 멀티스텝 작업을 대신 수행하되, 비밀번호·MFA 코드 원문은 모델에 노출되지 않는다.
- 작동 방식은 1Password의 "제로 노출(zero-exposure) 보안 프레임워크" — 작업마다 필요한 자격증명을 Claude가 볼 수 없는 보안 채널로 주입하고, 접근은 작업 단위로 승인하며 생체 인증 한 번으로 허용/거부한다.
- 지금은 **Mac**의 1Password 사용자(비즈니스·패밀리·개인 요금제) 대상이고 **로그인 정보에 한정**되며, 결제 카드·신원 정보 지원은 출시 이후로 예정.

## 본문

1Password가 Anthropic의 Claude를 위한 새 브라우저 통합을 공개했다. 이 기능을 켜면 Claude 챗봇이 볼트(vault)에 저장된 사용자명·비밀번호 같은 자격증명에 접근할 수 있고, 사용자는 로그인 정보를 매번 손으로 입력하지 않고도 여행 예약이나 온라인 계정 관리 같은 여러 단계짜리 작업을 Claude에게 위임할 수 있다.

여기서 가장 중요한 설계 결정은 "위임하되 노출하지 않는다"는 것이다. 1Password에 따르면 이 통합은 새로 개발한 **"제로 노출 보안 프레임워크(zero-exposure security framework)"** 위에서 돌아간다. 각 작업에 필요한 자격증명을 Claude 에이전트가 들여다볼 수 없는 별도의 보안 채널로 주입하는 방식이다. 그 결과 AI가 저장된 정보를 "쓸" 권한을 받더라도, 비밀번호나 MFA 일회용 코드 자체를 눈으로 보지는 못한다.

접근 권한은 작업 단위(per task)로 부여된다. 1Password는 사용자가 생체 인증 프롬프트 한 번으로 각 요청을 승인하거나 거부할 수 있다고 밝혔다. 회사 표현대로 이건 여전히 "작업 흐름의 중단(workflow interruption)"이긴 하지만, 에이전트를 잠깐 멈추고 사람이 직접 로그인창을 넘겨받아 인증하던 것보다는 성가심이 덜하다는 게 1Password의 주장이다.

안전장치도 붙었다. 1Password는 자동 입력(autofill)이 일어날 때마다 페이지를 스캔해, 폼 제출 과정에서 노출된 정보가 남아 있지 않은지 확인한 뒤에야 제어권을 Claude에게 돌려준다고 한다. 회사는 보도자료에서 이렇게 말했다: *"AI 에이전트가 브라우저를 장악하는 순간, 1Password는 자동으로 잠금 모드에 들어가 현재 작업에 명시적으로 허용된 자격증명만으로 접근을 제한한다. 볼트의 나머지 어떤 것에도 닿을 수 없다."*

가용 범위는 아직 좁다. **Mac**에서 1Password를 쓰는 사용자가 대상이며, 비즈니스·패밀리·개인 요금제 전반에서 지금 쓸 수 있다. 단, 이 기능을 쓰려면 1Password 데스크톱 앱과 브라우저 확장, 그리고 Claude 데스크톱 앱과 브라우저 확장이 **모두** 필요하다.

1Password 볼트에는 비밀번호뿐 아니라 패스키, 2FA 코드, API 토큰, 주소·금융 정보 같은 개인정보까지 다양하게 저장할 수 있다. 다만 1Password는 Claude가 정확히 어떤 자격증명에 접근할 수 있는지는 명시하지 않았고, 현재로선 **로그인 관련 정보에 한정**된 것으로 보인다. 결제 카드와 신원 정보에 대한 지원은 출시 이후 언젠가 제공될 예정이라고 밝혔다.

## 왜 중요한가

에이전트가 브라우저를 대신 조작하는 시대의 병목은 언제나 인증이었다. 로그인 벽 앞에서 에이전트는 멈추고, 사람이 넘겨받아 비밀번호와 MFA를 입력해야 했다. 이 통합은 그 병목을 겨냥한다.

더 눈여겨볼 건 자격증명 관리자가 취한 **신뢰 경계(trust boundary)** 설계다. 순진한 접근이라면 비밀번호를 프롬프트나 자동입력 텍스트로 모델에 그냥 넘겼을 것이고, 그러면 그 비밀은 모델 컨텍스트·로그·훈련 파이프라인 어디로든 샐 수 있는 값이 된다. 1Password는 대신 "에이전트에게 능력은 주되 비밀은 주지 않는다"는 구도를 택했다 — 자격증명은 Claude가 볼 수 없는 채널로 주입되고, 에이전트가 브라우저를 잡는 순간 볼트는 현재 작업분만 남기고 잠긴다. AI 에이전트에게 실제 권한(자격증명·결제·계정)을 위임할 때 어떻게 최소 권한과 감사 가능성을 유지할지에 대한 하나의 구체적 답안이다.

동시에 이건 트레이드오프를 그대로 보여준다. "작업마다 생체 인증 한 번"은 진짜 공격면 축소다 — 에이전트가 임의 사이트에서 볼트 전체를 긁어가는 걸 막는다. 하지만 1Password 스스로 인정하듯 그건 여전히 자동화 흐름을 끊는 개입 지점이다. 완전 무인 자동화와 사용자 확인(human-in-the-loop) 사이의 다이얼을, 지금은 보안 쪽으로 돌려놓은 셈이다.

## 어떻게 써먹나

- **에이전트 워크플로를 만드는 사람에게**: Claude 데스크톱으로 로그인 벽 뒤의 반복 작업(예약, 계정 설정 확인, 대시보드 조작)을 자동화하려던 시나리오가 있다면, 이제 Mac + 1Password 조합에서 자격증명 입력 단계를 사람이 매번 넘겨받지 않아도 된다. 단 데스크톱 앱·확장 4종(1Password 앱/확장, Claude 앱/확장)이 다 깔려 있어야 한다.
- **보안을 설계하는 사람에게**: 자체 에이전트에 비밀을 물릴 때의 참고 패턴으로 볼 만하다 — 비밀을 모델 컨텍스트에 절대 넣지 않고 별도 채널로 주입, 작업 단위 스코프, 사용 후 페이지 잔여 노출 스캔, 기본 잠금(default-deny). 반대로 지금은 **로그인 정보만** 열려 있고 결제·신원 정보는 아직이라는 점, Mac 한정이라는 점은 도입 범위를 좁게 잡아야 하는 제약이다.
