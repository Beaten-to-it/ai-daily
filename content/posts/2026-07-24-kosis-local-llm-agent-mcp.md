국가통계포털(KOSIS)이 공식 MCP 시범서비스를 연 걸 계기로, 프로젝트 저자(GeekNews의 hjm1980)가 자신의 오픈소스 **Spring AI Playground**에 이걸 붙여 돌려본 Show GN 데모다. 특이한 건 클라우드 API가 아니라 노트북에서 도는 9B 로컬 모델을 썼고, API 키를 하나도 쓰지 않았다는 점이다. 저자 본인의 데모라 독립 검증된 벤치마크는 아니지만, "로컬 모델 + 공공데이터 MCP + 사람 승인 게이트"라는 조합을 실물로 보여준다는 데 의미가 있다.

## TL;DR

- KOSIS 공식 MCP 시범서비스를 노트북의 9B 로컬 모델(Ollama)에 연결해, API 키 0개로 합계출산율을 조회하고 차트까지 그리는 흐름을 보여준다.
- 파일 쓰기 같은 위험 작업은 위험 등급(L0~L5)에 따라 승인 창이 뜨는 HITL 게이트로 막는다 — CSV 저장은 L4라서 사람이 Approve를 눌러야 실제로 저장된다.
- Spring AI 2.0에서 에이전트·MCP가 프레임워크 코어로 들어오면서, 원래 기능 둘러보기용이던 이 프로젝트가 자바 코드 없이 로컬 LLM 에이전트를 개발·테스트하는 데스크톱 워크벤치로 방향을 틀었다.

## 무슨 일이 벌어지나

사용자가 "합계출산율 보여줘"라고 던지면, 에이전트가 알아서 KOSIS를 검색하고 → 어떤 통계표를 쓸지 검증한 뒤 → 실제 데이터를 조회하고 → area 차트를 그린다. 데모에서는 2015년 1.20에서 2024년 0.73으로 떨어지는 곡선이 나온다. 같은 통계표를 재료로 12개국을 로즈 차트로 비교하고, 8개국의 2015년 대 2024년을 히트맵으로 얹는 것까지 이어진다. 여기까지는 조회·시각화라 위험이 낮은 작업이다.

분기점은 "요약을 CSV로 저장해줘"라고 했을 때다. 파일 쓰기는 시스템에 흔적을 남기는 작업이라 위험 등급 L4로 분류돼 있고, 그 순간 승인 창이 뜬다. 사람이 Approve를 눌러야만 파일이 실제로 저장되고, 거부하면 아무것도 쓰지 않는다. 이게 이 데모의 핵심 장치인 HITL(Human-in-the-Loop)이다. 조회는 자동으로 흘려보내되, 부작용이 생기는 지점에만 사람을 끼워 넣는 설계다.

또 하나 눈여겨볼 점은 모델이 전부 로컬(Ollama)에서 돈다는 것이다. 프롬프트와 조회한 데이터가 외부 API로 나가지 않고, 그래서 쓴 API 키가 0개다. 공공 통계 데이터를 다루면서 데이터를 밖으로 흘리고 싶지 않은 상황과 잘 맞는 조합이다.

## Spring AI Playground가 실제로 해주는 것

에이전트를 직접 붙여보려는 개발자는 보통 세 가지를 각각 코드로 짜야 한다 — MCP 서버 연결, 요청에 맞는 툴 검색, 그리고 위험 작업을 막는 승인 게이트. Spring AI Playground는 이 흐름을 자바 코드를 쓰지 않고 데스크톱 앱에서 눌러보며 확인하는 데 초점을 맞춘 도구다. 저자 설명에 따르면 원래는 Spring AI 기능을 하나씩 클릭해보는 플레이그라운드였는데, Spring AI 2.0에서 에이전트와 MCP가 프레임워크 코어로 편입되면서 성격을 워크벤치 쪽으로 바꿨다고 한다.

구체적으로 제공하는 기능은 이렇다.

- **동적 툴 검색(Dynamic Tool Discovery)**: 필요한 도구를 요청에 맞춰 그때그때 찾아 연결한다.
- **위험도 기반 HITL 게이트**: 작업을 L0~L5로 등급화하고, 파일 쓰기처럼 위험한 축에 속하는 작업이면 승인 창을 띄운다. 승인과 거부가 각각 어떻게 처리되는지도 UI에서 확인할 수 있다.
- **MCP 프록시**: 이미 있는 MCP 툴에 대해서도 HITL을 UI에서 켜고 설정할 수 있다. 툴 서버 코드를 고치지 않고 승인 게이트를 얹는 셈이다.
- **Observability 대시보드**: 채팅, 툴 호출, 토큰, 비용, 리스크를 한 화면에서 본다.

그리고 이 모든 게 자바·스프링으로 에이전트, MCP 클라이언트/서버, HITL을 어떻게 구현했는지 코드로 열어볼 수 있게 돼 있다. no-code로 눌러보다가 궁금하면 밑단 구현을 참고하는 식이다.

## 왜 중요한가

에이전트를 실전에 붙일 때 가장 무서운 건 모델이 똑똑한지가 아니라, 부작용 있는 행동(파일 쓰기, 외부 전송, 결제 같은 것)을 자동으로 실행해버리는 순간이다. 이 데모가 보여주는 **위험도 등급(L0~L5) + 그 등급에 따라 자동/승인/차단을 가르는 HITL 게이트**는, 프레임워크에 종속되지 않는 재사용 가능한 에이전트 안전 패턴이다. "전부 사람이 승인" 같은 극단은 실용성이 없고 "전부 자동"은 위험한데, 그 사이를 작업 위험도로 나눈다는 접근이 핵심이다.

여기에 로컬 모델(프롬프트 유출 없음, API 키 0개)과 공공데이터 MCP가 붙는다는 점도 개발자·창업자 입장에선 유용한 조합이다. KOSIS 같은 실제 공공 통계 소스가 MCP 엔드포인트로 열리기 시작했다는 것 자체가, 별도 크롤러나 API 래퍼 없이 에이전트가 국가 통계를 재료로 쓸 수 있게 됐다는 신호다. 다만 KOSIS MCP는 국가데이터처 시범서비스라 엔드포인트가 바뀔 수 있고, Spring AI Playground는 이 서비스를 쓰는 독립 오픈소스라는 점은 감안해야 한다.

## 어떻게 써먹나

로컬에서 직접 확인해보고 싶다면 대략 이런 순서다.

1. Windows/macOS/Linux용 데스크톱 앱을 받아 설치한다.
2. Ollama로 로컬 모델(데모 기준 9B 규모)을 띄워 연결한다 — 프롬프트가 밖으로 안 나가고 API 키도 필요 없다.
3. KOSIS 같은 MCP 서버를 붙이고, 필요하면 MCP 프록시로 기존 툴에 HITL을 UI에서 설정한다.
4. 채팅으로 조회·시각화를 시켜보고, 파일 쓰기처럼 부작용 있는 작업에서 승인 창이 어떻게 뜨는지, 승인/거부가 어떻게 갈리는지 확인한다.

자기 서비스에 에이전트를 붙이기 전에 툴 검색·승인 게이트·관측을 코드로 짜기 전 단계에서 손으로 만져보는 용도, 또는 자바·스프링으로 이 셋을 어떻게 구현하는지 레퍼런스로 뜯어보는 용도로 적합하다.
