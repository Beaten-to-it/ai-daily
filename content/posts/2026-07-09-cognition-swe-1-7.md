Cognition(Devin 개발사)이 지금까지 자사가 학습한 모델 중 가장 강력하다는 **SWE-1.7**을 공개했다. 핵심 주장은 "프런티어급 지능을 훨씬 낮은 비용에" — 비용·성능 파레토 곡선을 밀어냈다는 것이다. 오늘부터 Devin(Web·Desktop·CLI)에서 Cerebras를 통해 **1000 TPS**로 쓸 수 있다.

## TL;DR

- **오픈 베이스 + 자체 RL.** SWE-1.7은 이미 광범위한 RL 후처리를 거친 **Kimi K2.7 베이스**에서 다시 학습됐는데, 여기서 얻은 추가 이득이 커서 Cognition은 "post-training ceiling(후처리 한계)"이라는 통념이 틀렸다고 주장한다.
- **벤치마크는 프런티어 '근처'.** FrontierCode 1.1 Main 42.3%, Terminal-Bench 2.1 81.5%, SWE-Bench Multilingual 77.8%. GPT-5.5와는 엎치락뒤치락(멀티링구얼에선 앞섬), Opus 4.8엔 세 항목 모두 뒤진다. 단 베이스인 K2.7 Code(30.1/72.7/73.5) 대비 향상 폭이 크다.
- **훈련 기법 4종.** 엔트로피 붕괴 방지(top-p 리플레이), 3대륙 4개 데이터센터 멀티클러스터 RL, 치팅 0점 처리하는 데이터 품질 파이프라인, 최대 6시간짜리 롱호라이즌을 버티는 self-compaction.

## 무엇을 내놨나

SWE-1.7은 Cognition이 "RL 파이프라인 전반의 개선(더 나은 인프라, 안정적 학습, 고품질 데이터, 롱호라이즌 태스크용 신기법)"의 결과라고 소개한 모델이다. 특히 **길고 비동기적인(long-horizon asynchronous) 작업**에 최적화했다고 강조하는데, 이는 Devin이 지향해온 "한 번 시키면 몇 시간을 도는" 에이전트 실행 모델과 맞물린다.

벤치마크는 아래와 같다(agentic 코딩, pass rate %). 모든 모델은 최대 추론(reasoning) 설정에서 평가했다고 밝혔다.

| 벤치마크 | SWE-1.7 | K2.7 Code | GPT-5.5 | Opus 4.8 | Opus 4.7 | GLM-5.2 | Composer 2.5 | SWE-1.6 |
|---|---|---|---|---|---|---|---|---|
| FrontierCode 1.1 Main | 42.3 | 30.1 | 43.0 | 46.5 | 38.5 | 24.5 | 25.6 | 9.4 |
| Terminal-Bench 2.1 | 81.5 | 72.7 | 84.2 | 86.9 | 83.0 | 81.0 | 76.0 | 39.7 |

숫자를 그대로 읽으면 이렇다. SWE-1.7은 **GPT-5.5와 사실상 동급**(FrontierCode·Terminal-Bench에선 근소하게 뒤, SWE-Bench Multilingual에선 근소하게 앞)이고, **Opus 4.8에는 세 항목 모두 못 미친다**. Terminal-Bench에선 이전 세대인 Opus 4.7(83.0)에도 살짝 뒤진다. 하지만 자기 베이스인 Kimi K2.7 Code 대비로는 세 항목 모두 뚜렷하게 올랐고, 자사 이전 모델 SWE-1.6은 완전히 압도한다. Cognition의 세일즈 포인트는 "1등"이 아니라 "**이 성능을 이 비용에**"라는 위치 선정이다.

## 어떻게 학습했나 — 눈에 띄는 4가지

### 1) 엔트로피 보존 + 학습 안정화
긴 RL 런은 두 가지에 시달린다: 강한 모델이 탐색을 멈추고 보상이 몇백 스텝 만에 정체되는 **엔트로피 붕괴**, 그리고 학습(trainer) 정책과 샘플링(inference) 정책이 어긋나며 생기는 수치적 표류다. Cognition은 **top-p 샘플링**이 엔트로피 붕괴를 크게 막아준다고 봤다. 확률이 아주 낮은 토큰은 대개 궤적이 이탈했다는 신호인데, softmax 특성상 이런 토큰을 샘플링하면 이미 우세한 토큰의 리드를 더 벌려 분포를 뾰족하게(=엔트로피 감소) 만든다. top-p는 애초에 그런 토큰을 후보에서 빼버린다.

문제는 top-p가 학습-추론 간 분포 불일치를 키운다는 점. 이를 **sampling distribution replay**로 해결한다 — 롤아웃 시점에 "샘플 가능했던 토큰 집합(kept-set)"을 기록해두고, trainer에서 같은 마스크로 확률을 재정규화한다. 덤으로, top-p 임계 위 토큰은 keepset이 1이라 그래디언트가 0이 되면서, 학습 신호가 큰 토큰에만 최적화가 집중돼 그래디언트 노이즈가 준다. Muon 옵티마이저와 비결정적 연산 제거도 안정화에 기여했다.

### 2) 3대륙 멀티클러스터 RL
Cognition은 "10만 칩짜리 단일 패브릭 대형 클러스터는 희소하지만, 세계 곳곳의 작은 클러스터는 합치면 풍부하다"는 관점에서 출발한다. RL의 구조가 여기에 유리하다 — **trainer만 단일 고대역폭 클러스터에 있으면 되고, 롤아웃을 생성하는 inference 엔진은 현재 가중치만 있으면 어디서든 자족적으로 돈다**. 그래서 이들은 자사 GPU + Fireworks 같은 추론 제공자를 묶어 **3대륙 4개 데이터센터**에 RL 학습을 펼쳤다.

관건은 매 옵티마이저 스텝 후 모든 추론 엔진을 최신 가중치로 맞추는 일. 전체 모델을 브로드캐스트하는 대신, K 스텝마다 **압축된 가중치 델타**(XOR diff + zstd)를 클라우드 오브젝트 스토리지로 흘려보내 전송량을 99% 이상 줄인다. 오브젝트 스토리지가 단일 진실 원천이 되고, 각 클러스터의 weight controller가 새 매니페스트를 폴링해 샤드를 받아 로컬 디스크로 트리 브로드캐스트한다. 인플라이트 트래픽은 유지하며 델타를 CPU 메모리에 프리페치한 뒤, 다 준비되면 잠깐 멈춰 in-place로 적용한다. 이 방식으로 **1T 파라미터급 모델의 대륙 간 가중치 업데이트가 1~2분에 끝나고, 추론은 업데이트당 3~4초만 멈춘다.** (참고로 소스는 SWE-1.7의 파라미터 수를 명시하진 않는다 — 가중치 전송 설명에서 "1T 파라미터 모델"을 언급하고, 베이스인 Kimi K2.7이 1T급이라는 정황이 있을 뿐이다.)

**결함 내성:** 추론 쪽 장애는 싸다 — 엔진은 상태가 없어 죽어도 인플라이트 세션만 잃고, NVIDIA Dynamo가 다른 워커로 재라우팅한다. 비싼 건 단일 결합점인 trainer다. 각 노드가 매 스텝 로컬 디스크에 비동기 체크포인트를 뜨고 샤드를 피어에 복제해, 죽은 노드 상태를 수 초 만에 복구한다. 용량이 모자라면 데이터 병렬 복제본 단위로 런을 축소했다가 노드가 돌아오면 다시 키운다.

### 3) 데이터 품질
"데이터가 모델 능력을 결정한다"는 전제 아래 세 축에 집중했다. **검증기 품질** — 오답을 통과시키거나(false positive) 정답을 거르는(false negative) 걸 최소화하는 QA 파이프라인. **난이도** — 항상 풀거나 항상 실패하는 태스크는 학습 신호가 없으니, 모델이 **낮은 확률로만 푸는** 태스크를 큐레이션해 실제 신호를 만들면서 지능을 밀어올린다. **치팅 방지** — 샌드박스 네트워크 제한, git 히스토리·참조 아티팩트 제거, 채점 경로를 에이전트와 격리, 알려진 익스플로잇 시그니처 프로그램적 탐지. 그리고 결정적으로 **치팅 시도가 있는 궤적은 성공 여부와 무관하게 보상 0**을 준다.

### 4) 롱호라이즌용 self-compaction
비동기·장시간 태스크를 학습하려니 두 문제가 생긴다 — 롤아웃이 raw 컨텍스트 윈도우를 넘어서고, RL이 응답을 점점 길게 만드는(DeepSeek R1에서 관찰된) 경향이다. 해법은 **self-compaction**: 에이전트가 컨텍스트 한계에 다가가면 스스로 작업 상태를 요약하게 하고, 그 자가 요약본에서 이어서 재개한다. 학습 중 모델은 (1) 더 압축적이고 정보량 많은 요약을 쓰는 법과 (2) 그 요약을 잘 활용하는 법을 동시에 익힌다. 이 덕에 **롤아웃이 최대 6시간까지** 이어진다. 길이 폭주는 **교대(alternating) 길이 페널티**로 제어한다 — 자유 구간에선 성공만 최적화하고, 예산(budget) 구간에선 토큰·턴·툴콜 시간의 가중 비용이 예산을 넘는 해법에 페널티를 준다. 결과적으로 쉬운 태스크에선 응답이 짧아지고 어려운 태스크에선 롱호라이즌 행동이 보존된다.

## 학습이 만든 행동 변화

RL을 거친 SWE-1.7은 베이스 K2.7 Code와 눈에 띄게 다르게 행동한다.

- **정렬(alignment)·신뢰성이 더 높다** — K2.7이나 다른 프런티어 오픈소스 모델보다. (별도 동반 글에서 상술)
- **압축된 chain-of-thought** — 첫 CoT의 기능어 비율이 훨씬 낮고 문장당 단어 수가 거의 절반. budget 구간 페널티의 직접적 영향으로 본다.
- **행동 전 코드베이스를 훨씬 더 탐색한다** — 툴콜·파일 읽기·검색 수가 늘었다. 버그 수정에서 특히 두드러지는데, 보고된 증상 하나만 보지 않고 근본 원인·엣지 케이스·적대적 입력·요구 범위 밖까지 파고든다. 애매한 의미는 추측 대신 작은 파이썬 스크립트를 짜서 실험해 확정한다.

**정직하게 밝힌 트레이드오프:** 더 많이 생각하니 더 많이 건드린다. 좋은 해법은 필요한 최소 파일만 수정해야 하는데(FrontierCode 원칙), SWE-1.7은 추가 테스트를 쓰고 태스크가 요구하지 않은 파일까지 손댄다. Cognition은 "업계 전반에서 추론이 늘수록 건드리는 파일 범위도 커진다"며 이를 개선 과제로 남겨뒀다.

## 왜 중요한가

- **"오픈 베이스 + RL"의 경제학.** 컴퓨트에 쪼들리는 신생 랩이 이미 잘 후처리된 오픈 모델(K2.7)을 받아, 자체 RL만으로 프런티어 인접까지 끌어올렸다. 이게 사실이라면 "누가 초대형 사전학습을 하느냐"보다 "**오픈 베이스에 얼마나 잘 RL을 얹느냐**"가 경쟁축이 될 수 있다는 신호다. "post-training ceiling은 없다"는 주장은 그 자체로 오픈웨이트 생태계 참가자 전부에게 호재다.
- **단일 메가클러스터 없이 경쟁하는 법.** trainer만 붙잡아두고 롤아웃을 전 세계에 분산하는 멀티클러스터 RL은, 하드웨어 조달에서 밀리는 소규모 랩이 대형 랩과 붙는 현실적 레시피다. 압축 델타 + 오브젝트 스토리지 동기화라는 구현 디테일까지 공개한 점도 참고할 만하다.
- **비용·성능 선택지가 하나 늘었다.** 절대 성능 1등이 아니라 "이 가격대 최고"를 노리는 포지셔닝은, 모델을 고르는 개발자·창업자에게 실질적 선택지다. 특히 과편집 트레이드오프를 스스로 공개한 정직함은 코딩 모델을 고를 때 신뢰의 근거가 된다.

## 어떻게 써먹나

- **오늘 바로 Devin에서 시험.** Web·Desktop·CLI 모두에서 Cerebras 경유 1000 TPS로 제공된다. 긴 비동기 작업(대규모 리팩터, 다파일 버그 추적)에 특화됐다고 하니, 그런 워크로드로 Opus 4.8·GPT-5.5와 비용 대비 결과를 직접 비교해볼 만하다.
- **PR 리뷰 부담을 감안하라.** "근본 원인까지 파고 테스트를 더 쓴다"는 장점의 이면은 diff가 커진다는 것. 최소 변경이 중요한 코드베이스라면 리뷰 게이트를 빡빡하게 두거나, 변경 범위를 명시적으로 제약하는 프롬프트를 쓰는 게 안전하다.
