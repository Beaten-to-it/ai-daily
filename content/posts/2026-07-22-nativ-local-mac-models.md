## TL;DR

- **Nativ**은 Apple Silicon Mac(M1 이상)에서 오픈 AI 모델을 계정·구독·클라우드 없이 로컬 실행하는 **MIT 라이선스 오픈소스 앱**이다. MLX-VLM을 관리하는 Prince Canuma가 만들었고, Google·Cohere·Liquid AI 오픈 모델을 골라 쓰며 하드웨어에 맞는 모델을 추천받을 수 있다.
- MLX-VLM과 M 시리즈 통합 메모리·Metal에 맞춰 최적화돼 텍스트·비전·비디오·코드·오디오를 처리하고, **단일 로컬 엔드포인트**로 Claude Code·Codex·OpenCode·Pi·Hermes 같은 코딩 에이전트를 붙일 수 있다. 초당 토큰 수·메모리 압력·발열·첫 토큰 지연을 실시간으로 보여준다.
- Hacker News 반응은 갈렸다 — "프런티어" 표현이 과장(실제로는 파레토 프런트)이라는 지적, LM Studio·Open WebUI·oMLX 같은 **기존 경쟁자를 없는 셈 친다**는 비판, MLX vs llama.cpp 성능이 하드웨어별로 엇갈린다는 일화적 보고가 나왔다.

## 무엇인가

Nativ은 "실제 모델을 Mac에서 그대로 돌린다"를 표방하는 macOS 네이티브 앱이다. 클라우드도, 별도 변환 계층도 없이 Apple Silicon(M1+)에서 오픈 가중치 모델을 내려받아 구동한다. 선별된 라이브러리에서 Google·Cohere·Liquid AI의 오픈 모델을 고르거나, 자기 Mac 사양에 맞는 모델을 추천받는다. 전체 모델 라이브러리는 Hugging Face에서 확인할 수 있다.

채팅 인터페이스는 스트리밍 응답, 메시지별 성능 지표, Markdown·코드 구문 강조, 이미지 입력을 지원한다. 눈에 띄는 건 **실시간 성능 계측**이다. 초당 토큰 수, 메모리 압력, 발열 상태, 첫 토큰 생성 시간(TTFT)을 그때그때 보여줘, 로컬 추론이 이 하드웨어에서 실제로 쓸 만한지를 감으로가 아니라 숫자로 판단하게 해준다.

기술 스택은 MLX-VLM 기반이다. M 시리즈의 통합 메모리와 Metal에 맞춰 조정돼 LLM 채팅, 이미지 캡션, 비디오 요약, 코드 자동완성, 음성 변환·생성까지 다중 모달을 커버한다. 계정·크레딧·구독이 필요 없고, 사용자 데이터를 팔지 않으며, 프롬프트를 학습 데이터로 돌리는 다크 패턴이나 엔터프라이즈 등급, VC 로드맵을 두지 않는다고 명시한다. 데스크톱 앱·모델 로더·성능 차트를 포함한 전체 코드가 공개돼 열람·포크·PR이 가능하다.

개발자에게 실질적인 지점은 **로컬 엔드포인트 연동**이다. Nativ이 띄우는 단일 로컬 엔드포인트에 기존 코딩 에이전트(Pi, Codex, Claude Code, Hermes, OpenCode)를 연결해, 이 도구들이 클라우드 API 대신 Mac 위 로컬 모델을 백엔드로 쓰게 만들 수 있다.

## HN에서 나온 논점 (의견·논쟁)

앱 설명은 여기까지가 확정 사실이고, 아래는 Hacker News 토론에서 나온 **의견**이라 그대로 옮기기보다 걸러 읽어야 한다.

- **제작자 신뢰도**: 만든 사람이 MLX-VLM을 관리하는 Prince Canuma라는 점이 반가움으로 언급됐다. MLX-VLM은 Apple 기기에서 llama.cpp보다 빠른 추론을 낼 수 있어 LM Studio 등의 의존성으로 오래 쓰였고, 그의 MLX 작업물 품질이 유독 높았다는 평이다. 앱 대부분이 Swift로 작성돼 있어 이 추론 스택을 iPad·iPhone으로 이식하기 쉬워 보인다는 관측, 오디오·이미지 생성 전용 모델 지원이 곧 붙는다는 언급도 있었다.

- **"프런티어"라는 단어 논쟁**: 이게 가장 뜨거웠다. 한쪽은 "프런티어=지금의 Fable 같은 최상위 모델"인데 그런 모델은 막대한 RAM과 비싼 GPU가 필요해 Mac 로컬로는 못 돌린다며 표현이 과장이라 봤다. 다른 쪽은 여기서 프런티어는 **파레토 프런트**를 뜻한다고 반박했다 — 지능·가격·속도·활성 메모리 같은 여러 축에서, 한 지표를 개선하려면 다른 지표를 포기해야 하는 '자기 체급의 최선' 집합이라는 것이다. "오픈 가중치 소형 로컬 모델의 프런티어가 가장 흥미롭다"는 의견과, 그래도 일반 용법과 충돌해 혼동을 준다는 반대가 공존했다. **소스 자체가 결론을 내지 않았으니 여기서도 단정하지 않는다.**

- **기존 경쟁자를 없는 셈 친다는 비판**: "다른 로컬 앱이 없는 것처럼" 소개하는 랜딩 문구가 여러 코멘터의 반감을 샀다. LM Studio, Open WebUI, oMLX가 이미 유사 기능을 한다는 지적이다. 한 코멘터는 *"LM Studio는 Nativ 개발자가 공개한 코드 기반의 폐쇄 소프트웨어"*라고 주장했는데, 이건 느슨한 표현으로 봐야 한다 — 요지는 "LM Studio 등은 자기 소유가 아닌 오픈 엔진 위에 얹은 독점 셸이고, Nativ은 그 셸까지 오픈했다"는 차별화 주장이다. 진짜 차별점이 있긴 하나, 기존 오픈소스 경쟁 제품과 제대로 비교했어야 한다는 게 중론이었다.

- **MLX vs llama.cpp**: 엇갈렸다. M1 Max에서는 MLX 이점을 거의 못 봤고 오히려 llama.cpp의 GGUF가 나았다는 보고, MLX가 Qwen에서 자꾸 끊기고 반복해 llama.cpp로 옮기니 MTP 토큰 생성이 빨라졌다는 사례가 있었다. 반대로 Qwen 3.6 MoE에서는 측정 가능한 차이가 있었고 M3 이상 최신 하드웨어라면 이득이 더 클 수 있다는 관측도 나왔다. **일화적 보고라 한쪽으로 결론짓기 어렵다.** 또 mlx-vlm이 vLLM·sglang 대비 최신 샘플러(top-n-sigma 등) 지원이 약하다는 지적도 있었다.

## 왜 중요한가

로컬 온디바이스 AI 앱은 이미 여럿(LM Studio, Open WebUI, FullMoon 등) 있다. Nativ의 진짜 의미는 "또 하나의 로컬 챗 앱"이 아니라 **셸까지 완전 오픈된 MIT 스택**이라는 데 있다. 로컬 AI 도구 상당수가 오픈 추론 엔진(MLX, llama.cpp) 위에 폐쇄 UI를 얹는 구조인데, Nativ은 앱·모델 로더·성능 차트 전체를 공개해 포크·수정·재배포가 열려 있다. 데이터를 팔지 않고 프롬프트를 학습에 쓰지 않는다는 선언과 결합하면, 프라이버시·감사가능성이 중요한 개발자에게 신뢰 기반이 다르다.

또 하나는 **로컬 엔드포인트를 코딩 에이전트에 붙일 수 있다는 점**이다. Claude Code·OpenCode 같은 도구를 로컬 모델 백엔드로 돌리는 구성은, 반복적·저위험 작업을 API 비용 없이 처리하는 현실적 워크플로를 연다.

다만 마케팅 톤("아무도 안 하는데 우리만 오픈소스")은 기존 경쟁자를 무시한다는 역풍을 맞았고, "프런티어" 같은 단어는 Claude Code 사용자들이 남용한다고 느끼는 load-bearing 표현이 됐다. 소형 오픈 모델이 최상위 클라우드 모델과 동급이라는 인상은 경계할 필요가 있다.

## 어떻게 써먹나

HN 토론에서 나온, 소형 로컬 모델의 **실제로 검증된 용처**는 참고할 만하다(모두 코멘터들의 실사용 사례):

- **저위험 반복 작업**: 의존성 업데이트, 병합 충돌 해결, `--help`·Markdown·README 작성 같은 작업은 소형 모델로 충분하다. 실패해도 `git restore`로 되돌리거나 PR을 거부하고 더 좋은 모델에 다시 맡기면 되니 리스크가 낮다.
- **에이전트 메모리 추출**: Gemma 4를 로컬로 돌려 대화를 주제·출처·사실·개체로 쪼개 검색용 그래프에 넣는 용도. 채팅 에이전트로는 느려도 메모리 추출엔 잘 맞고, 매 턴의 클라우드 API 사용량을 줄여준다.
- **코딩 에이전트 백엔드**: 한 코멘터는 OpenCode에서 Qwen 3.6 27B가 생성한 코드를 프로덕션에 배포했다. 지식 범위는 Opus만 못해도, 프롬프트와 주변 코드만으로 변경을 추론할 수 있는 일반적 PR은 Sonnet급이라는 평. 단 권장 temperature·top-p, 과하지 않은 양자화, 최소 15만 토큰 문맥 같은 올바른 구성이 전제다.
- **텍스트 변환·요약·정보 추출·데이터 정제**: 이미 유료 모델을 구독 중이라면 프라이버시 외 큰 이득은 없을 수 있지만, 대규모 데이터 정제(예: 3090 두 장으로 1,000억 토큰 처리) 같은 배치성 작업엔 로컬이 경제적이다.

**하드웨어 판단**: HN에서는 M1 Max 64GB로도 상당수 모델을 돌릴 수 있다는 보고가 있었다. 동시에 "성능 낮은 모델을 로컬로 돌리려 2,000~3,000달러를 더 쓰느니 그 돈으로 클라우드 토큰을 사라"는 반론도 나왔다 — 프라이버시·오프라인·배치 처리가 목적이 아니라면 냉정히 비교할 대목이다.
