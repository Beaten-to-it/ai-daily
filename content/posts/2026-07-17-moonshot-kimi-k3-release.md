Moonshot이 자사 최고 성능 모델 **Kimi K3**를 공개했다. 헤드라인 숫자는 셋이다. **2.8조(2.8T) 파라미터**, **네이티브 비전**, **100만 토큰 컨텍스트**. Moonshot은 이를 "장시간 코딩·지식 작업·추론을 겨냥한 세계 최초의 공개 3T급 모델"이라고 소개한다. 다만 Moonshot 스스로도 종합 성능·사용자 경험은 Claude Fable 5, GPT 5.6 Sol에는 못 미친다고 선을 긋는다. 즉 "프론티어 3위권을 오픈웨이트로 밀어 올린" 발표로 읽는 게 정확하다.

## TL;DR
- **2.8조 파라미터 / 100만 토큰 / 네이티브 비전** 오픈웨이트 모델. 새 구조(KDA·AttnRes·Stable LatentMoE, 896개 중 16개 전문가 활성)로 K2 대비 스케일링 효율 약 2.5배. 지금 바로 Kimi.com·Work·Code·API에서 쓸 수 있고, **전체 가중치·기술 보고서는 7월 27일까지** 공개 예정.
- 킬러 데모는 벤치마크 점수가 아니라 **장시간 자율 작업**이다 — 48시간 만에 자기 구조용 칩을 설계(4mm²·100MHz·초당 8,700토큰↑)하고, GPU 컴파일러(MiniTriton)를 밑바닥부터 만들고, 숙련 연구자 1~2주짜리 천체물리 계산을 약 2시간에 재현했다고 주장.
- 성능은 Fable 5·Sol 다음(3위권)이고 Opus 4.8은 고르게 앞서는 수준. 가격은 **출력 $15 / 100만 토큰**으로 중국 오픈웨이트치곤 비싸며, DeepSeek처럼 판을 뒤집는 사건은 아니라는 게 커뮤니티의 냉정한 평가다.

## 무엇이 바뀌었나 — 구조와 스펙

Moonshot은 지난 12개월 중 9개월 동안 공개 모델 크기 상한을 자사가 갱신해 왔다고 밝히면서, K3에서 처음으로 3T급에 도달했다고 한다. 핵심은 단순히 파라미터를 키운 게 아니라 새 구조 세 가지를 얹은 것이다.

- **Kimi Delta Attention(KDA)**: 긴 시퀀스에서 어텐션을 효율적으로 확장하는 기반. 다만 기존 prefix caching과 충돌하는 문제가 있어, 이를 푸는 구현을 vLLM 커뮤니티에 기여하고 모델과 함께 공개한다고 한다.
- **Attention Residuals(AttnRes)**: 계층 표현을 균일하게 쌓는 대신 깊이 방향에서 필요한 표현만 선택적으로 가져오는 방식.
- **Stable LatentMoE**: MoE 희소성을 더 밀어붙여 **896개 전문가 중 16개만 활성화**. 여기에 라우터 분위수에서 전문가 배분을 직접 계산하는 Quantile Balancing, 헤드별 독립 최적화인 Per-Head Muon 등을 결합했다.

이 조합으로 **K2 대비 전체 스케일링 효율이 약 2.5배** 올랐다는 게 Moonshot의 주장이다. 인프라 쪽도 공격적이다. SFT 단계부터 양자화 인지 학습(MXFP4 가중치 / MXFP8 활성값)을 적용하고, 추론에는 64개 이상 가속기를 묶은 supernode 구성을 권장한다. 2.8조 파라미터짜리를 상업적으로 서빙하려면 그만한 인프라가 전제라는 뜻이기도 하다.

## 진짜 자랑거리 — 벤치마크가 아니라 '장시간 자율 작업'

이번 발표에서 눈길이 가는 대목은 점수표가 아니라, 최소한의 사람 개입으로 몇 시간~수십 시간을 스스로 돌리는 데모들이다. 원문에 나온 수치를 그대로 옮기면:

- **자기 구조용 칩 설계**: K3가 **48시간 연속 자율 작업**으로, 자기 아키텍처의 소형 모델을 구동할 칩을 설계했다. 오픈소스 EDA 도구 + Nangate 45nm 라이브러리로 설계·최적화·검증까지 마쳐, **4mm² 안에서 100MHz 타이밍 충족, 시뮬레이션상 초당 8,700토큰 이상 디코딩**, 146만 표준 셀·0.277MB SRAM·INT4 MAC 배열까지 포함했다고 한다. HN 댓글에서도 "모델이 모델용 칩을 만든" 이 항목을 가장 놀라운 개념 증명으로 꼽는다.
- **GPU 컴파일러 밑바닥 구현(MiniTriton)**: MLIR 위에 자체 타일 IR·최적화 패스·PTX 생성·런타임까지 일관된 컴파일러를 만들어, 일부 roofline 벤치마크에서 Triton·torch.compile과 비슷하거나 앞섰고 nanoGPT 학습도 안정적으로 수렴시켰다고 한다.
- **GPU 커널 최적화**: AttnRes 커널의 순전파+역전파를 **283.6ms → 114.4ms**로 줄이고, MLA-512 커널을 처음부터 짜서 **517.8 TFLOPS**(H200 이론상 BF16 최고치의 절반 초과)를 달성했다는 식의 구체 수치를 제시한다. 이 구간에서 K3는 Opus 4.8·GPT 5.6 Sol을 앞섰다고 밝힌다.
- **계산과학**: 천체물리의 I–Love–Q 보편 관계 재현을 **약 2시간**에 끝냈다고 주장하며, 숙련 연구자 기준 통상 1~2주 작업이라고 비교한다. 20편 이상 논문 교차검증, 300개 이상 상태방정식 평가, 3,000줄 이상 Python + 인터랙티브 대시보드 생성이 포함됐다.

여기에 Three.js WebGPU 기반 절차적 3D 오픈월드 게임 제작, 42년치 AI ASIC 산업을 120회 이상 재귀적 자체 개선으로 분석한 인터랙티브 사이트, 391개 중력파 사건을 20개 이상 하위 에이전트로 병렬 분석한 사례까지 붙였다. **자율성의 지속 시간과 도구 조율**을 세일즈 포인트로 잡았다는 게 명확하다.

## 벤치마크 — 3위권, 그리고 읽을 때 주의할 점

수치는 모두 추론 노력 max 기준이고, 벤치마크마다 KimiCode/Claude Code/Codex 등 서로 다른 에이전트 하네스를 썼다. Moonshot 자체 평가이므로 그대로 믿기보단 방향성으로 보는 게 맞다.

- **코딩**: DeepSWE 67.5, Program Bench 77.8, Terminal Bench 2.1 88.3, FrontierSWE 81.2. Program Bench·SWE Marathon에선 표 내 최고점. 다만 Terminal Bench는 GPT 5.6 Sol(88.8)에 근접했을 뿐이고, FrontierSWE는 Fable 5(86.6)보다 낮다.
- **에이전트**: GDPval-AA v2에서 **1,668 Elo**로 Fable 5·Sol 다음, Opus 4.8(1,600)보단 위. BrowseComp·DeepSearchQA·Automation Bench 등에선 표 내 최고를 기록했다.
- **추론/지식**: GPQA-Diamond 93.5(Sol 94.1에 근접), HLE-Full 43.5(Fable 5의 53.3보다 뒤).
- **비전**: OmniDocBench 91.1로 표 내 최고, MMMU-Pro 81.6.

패턴이 보인다. **코딩·에이전트·문서 이해에선 최상위권이거나 1등을 찍지만, 순수 추론(HLE 등) 종합에서는 프론티어 두 모델에 뚜렷이 밀린다.** Moonshot 스스로 인정한 "3위권"과 일치한다.

## 가격과 이용 방법

- **API 가격(100만 토큰당)**: 캐시 적중 입력 **$0.30**, 캐시 미적중 입력 **$3**, 출력 **$15**. 모델 식별자는 `kimi-k3`. Mooncake 분리형 추론 구조를 쓰며 코딩 작업 캐시 적중률이 90%를 넘는다고 한다.
- **접근 경로**: 앱/Kimi.com(Agents), Kimi Work 3.1.0+, Kimi Code 터미널(`/model`로 선택), API. 출시 시 최대 추론 강도가 기본이고 낮음/높음 모드는 추후 추가 예정.

## 한계 — 벤더가 직접 명시한 것들

Moonshot이 스스로 밝힌 제약이 오히려 실무자에겐 중요하다.

- **사고 기록에 민감**: K3는 이전 사고 기록을 보존하는 방식으로 학습됐다. 에이전트 하네스가 과거 사고 내용을 다시 넘기지 않거나, 다른 모델로 돌던 세션을 K3로 중간 전환하면 **생성 품질이 크게 불안정**해질 수 있다. → 검증된 Kimi Code를 쓰고 세션 중간 모델 전환을 피하라는 권고.
- **과도한 선제 행동**: 장시간·고난도 작업에 맞춰 학습돼, 사소하거나 모호한 상황에서 사용자를 대신해 예상치 못한 결정을 내릴 수 있다. 행동 범위를 좁혀야 하는 앱이면 시스템 프롬프트나 `AGENTS.md`에 제약을 더 명시하라고 한다.

## 왜 중요한가

1. **오픈웨이트가 프론티어 3위권까지 붙었다.** 1등은 여전히 클로즈드(Fable 5·Sol)지만, 가중치를 공개(예정)하는 모델이 코딩·에이전트·비전 일부에서 최상위와 오차 범위 안에 들어왔다. 자가호스팅 여지가 있는 팀에겐 선택지가 실질적으로 늘었다.
2. **경쟁 축이 '점수'에서 '자율 지속 시간'으로 이동 중.** 48시간 칩 설계, 컴파일러 밑바닥 구현 같은 데모는 단발 응답 품질이 아니라 **긴 세션을 무너지지 않고 끌고 가는 능력**을 파는 것이다. 에이전트 제품을 만드는 쪽이라면 이 축을 벤치마킹 기준에 넣어야 한다.
3. **다만 'DeepSeek 모먼트'는 아니다.** 커뮤니티의 냉정한 반박이 설득력 있다 — DeepSeek가 충격이었던 건 비용이 10배 저렴했기 때문인데, K3는 Sol 대비 약 2배 저렴한 수준이라 **토큰 효율 차이와 오차 범위에 가깝다**. 게다가 출력 $15는 사실상 Sonnet급 가격이라 "중국 오픈웨이트=저렴"이라는 통념과도 어긋난다. 실질 비용은 결국 같은 작업에 몇 토큰을 태우느냐(추론 효율)로 갈린다.

## 어떻게 써먹나

- **긴 에이전트 작업(대형 리포지토리 리팩터, 터미널 도구 조율, 시각 피드백 루프)**을 돌린다면 지금 API(`kimi-k3`)나 Kimi Code로 파일럿해 볼 값어치가 있다. 단 **세션 중간 모델 전환 금지**를 반드시 지켜라(사고 기록 민감성 때문).
- **비용 검증은 점수가 아니라 실제 토큰으로.** 캐시 적중 $0.30 vs 미적중 $3의 격차가 크고 코딩 캐시 적중률이 90%+라니, 캐시 친화적으로 프롬프트를 구성했을 때의 실측 단가를 뽑아 Sol/Sonnet과 같은 작업으로 비교하라. Simon Willison의 펠리컨 SVG 테스트처럼 출력 1.6만 토큰(대부분 추론 토큰)에 25센트가 나왔다는 사례가 "출력·추론 토큰이 곧 비용"임을 잘 보여준다.
- **행동 범위 제어가 필요한 프로덕션**이면 `AGENTS.md`/시스템 프롬프트에 제약을 명시적으로 박아 두라 — 기본값이 max effort + 선제적 판단이라 그대로 두면 과잉 행동할 수 있다.
- **데이터 취급 주의**: 개인/일반 계정으로 API를 쓰면 사용 데이터가 학습에 활용될 수 있다는 지적이 있다(제한하려면 별도 기업 계약 필요). 민감 코드·데이터를 넣기 전 약관을 확인하라.

*(위 벤치마크·성능 수치는 대부분 Moonshot 자체 평가이며, 전체 가중치·기술 보고서 공개(7월 27일 예정) 전까지는 제3자 검증이 제한적이라는 점을 감안할 것.)*
