## 무엇이 있었나

OpenAI Python SDK가 동기·비동기 HTTP 통신에 사용하는 기본 라이브러리를 HTTPX에서 Pydantic이 관리하는 HTTPX2로 변경했다. 일반적인 `OpenAI()` 및 `AsyncOpenAI()` 사용 방식과 API 호출, 응답 모델, 스트리밍 인터페이스는 유지되며, `openai` 패키지를 설치하면 HTTPX2가 의존성으로 함께 설치된다.

주요 환경 변화는 TLS 인증서 검증 방식이다. 기존 `certifi` 인증서 묶음 대신 운영체제의 인증서 저장소를 사용하므로, 시스템 CA가 없는 최소형 컨테이너나 사내 TLS 검사 프록시를 쓰는 환경에서는 인증서 구성을 점검해야 한다.

HTTPX 기반 사용자 지정 클라이언트, 이벤트 훅, 테스트 및 계측 도구를 사용하는 코드는 HTTPX2 호환 여부를 확인하고 필요하면 이전해야 한다. 기존 HTTPX 클라이언트를 주입하는 호환 경로도 제공되지만 장기 지원을 전제로 한 방식은 아니다.

## 왜 중요한가

OpenAI SDK를 기본 설정으로 사용하는 애플리케이션은 코드 변경이 크지 않을 가능성이 높다. 그러나 기업 네트워크나 컨테이너 환경에서는 인증서 저장소 차이로 배포 후 연결 오류가 발생할 수 있어 사전 검증이 필요하다.

또한 SDK가 간접 설치하던 `httpx`에 의존한 코드가 있다면 별도의 직접 의존성을 선언해야 한다. HTTP 요청을 가로채는 테스트 도구나 사용자 지정 전송 계층을 운용하는 국내 개발팀은 HTTPX2 지원 여부를 CI와 실제 배포 환경에서 함께 확인할 필요가 있다.

## 확인 범위

이번 내용은 GeekNews에 정리된 변경 사항을 바탕으로 확인했다. 기본 클라이언트 전환, 운영체제 인증서 저장소 사용, 사용자 지정 HTTPX 코드의 이전 필요성과 임시 호환 경로가 확인된 범위다. HTTPX2의 세부 버전, 전환 일정, 호환 경로의 종료 시점은 제시된 자료에서 확인되지 않았다.
