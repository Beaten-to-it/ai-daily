## 무엇이 있었나

AWS가 Amazon Bedrock AgentCore Evaluations에서 서로 다른 AI 에이전트 프레임워크를 공통 방식으로 평가하는 구조를 공개했다. 특정 SDK에 평가 체계를 종속시키지 않고, OpenTelemetry와 OpenInference 규약에 따라 수집한 실행 추적 데이터를 바탕으로 에이전트의 응답과 도구 호출 과정을 재구성하는 방식이다.

평가에는 사용자 요청과 최종 답변을 담은 최상위 실행 구간, 개별 모델 호출 구간, 도구 실행 구간이 핵심 데이터로 쓰인다. LangGraph, LlamaIndex, OpenAI Agents SDK, Google ADK, Claude Agent SDK, Strands Agents가 지원 대상에 포함되며, 정해진 계측 규약과 스코프 이름을 따르는 다른 프레임워크도 일반 경로를 통해 연결할 수 있다.

평가 방식은 두 가지다. 온디맨드 평가는 CI/CD와 회귀 시험에서 예상 답변이나 도구 호출 경로를 기준으로 결과를 검사하는 데 적합하다. 온라인 평가는 실제 운영 트래픽 일부를 지속적으로 표본 추출해 품질을 관찰한다. GoalSuccessRate, Correctness, Helpfulness 같은 기본 평가기와 사용자 정의 LLM 심사 평가기를 조합할 수 있다.

## 왜 중요한가

여러 에이전트 프레임워크를 시험하거나 함께 운용하는 조직은 프레임워크마다 별도의 평가 도구를 구축해야 하는 부담을 줄일 수 있다. 공통 관측 표준을 중심으로 평가 데이터를 맞추면 개발 단계의 회귀 시험과 운영 환경의 품질 감시를 유사한 기준으로 연결하기도 쉬워진다.

한국 기업과 개발팀에는 프레임워크 선택과 품질 관리 체계를 어느 정도 분리할 수 있다는 점이 의미가 있다. 다만 실제 도입 전에는 메시지 내용이 CloudWatch 데이터 소스에 포함되는지, 세션 식별자가 올바르게 기록되는지, 실행 종료 전에 추적 데이터가 전송되는지를 확인해야 한다. 특히 기존 관측 구성에서는 실행 구간과 메시지 기록이 서로 다른 로그 그룹에 저장될 수 있어 데이터 소스 설정이 빠지면 응답 품질 평가가 실패할 수 있다.

## 확인 범위

AWS가 2026년 8월 26일 공개한 기술 게시물에서 지원 구조, 필수 추적 데이터, 대상 프레임워크, 온디맨드·온라인 평가 방식과 구성상 주의점을 확인했다. 프레임워크에 구애받지 않는다는 설명은 OpenTelemetry 또는 OpenInference 규약, 인식 가능한 스코프 이름, 세션 식별자와 메시지 데이터가 갖춰졌을 때를 전제로 한다.

이번 자료는 AWS가 자사 서비스의 동작과 예제를 설명한 글이다. 독립 기관의 비교 평가 결과나 실제 환경에서의 비용·지연 시간·평가 정확도 수치는 제시되지 않았으므로, 서비스 간 성능 우위까지 확인된 것은 아니다.
