## 무엇이 있었나

LangChain이 1.4.0 알파 2 프리릴리스를 공개했다. 이번 버전에는 MCP 서버를 LangChain 에이전트의 도구로 연결하는 공식 어댑터 `langchain.mcp`가 알파 형태로 처음 포함됐다.

새 `MCPAdapter`는 URL, 로컬 스크립트, 프로세스 내부의 FastMCP 서버, 여러 서버를 정의한 구성 파일, 기존 `fastmcp.Client` 등을 연결 대상으로 받을 수 있다. 연결 방식은 FastMCP가 판별하며, 어댑터가 검색한 도구는 LangChain의 `create_agent`에 전달할 수 있다.

인증과 캐싱, 시간 제한, 각종 처리기는 FastMCP 클라이언트에서 설정한다. 여러 MCP 서버를 한꺼번에 연결하면 서버 이름이 도구 이름 앞에 붙어 충돌을 방지한다. 서버가 도구 실행 중 추가 입력을 요구하는 ‘elicitation’ 기능은 선택 사항이며, 활성화하면 LangGraph의 인터럽트로 사람의 응답을 받을 수 있다.

## 왜 중요한가

MCP 기반 도구를 LangChain 에이전트에 붙이려는 개발자는 별도 변환 계층을 직접 구현해야 하는 부담을 줄일 수 있다. 특히 인증 방식이나 전송 계층을 FastMCP에 맡기면서 LangChain에서는 하나의 어댑터 진입점을 제공한다는 점이 핵심이다.

여러 업무 시스템을 에이전트 하나에 연결하는 국내 개발 환경에서도 서버별 도구 이름 구분과 개별 인증 설정은 통합 복잡도를 낮추는 데 도움이 될 수 있다. 기존 방식과 최신 방식의 MCP 서버를 각각 연결할 수 있다는 점도 점진적으로 시스템을 전환할 때 유용하다.

다만 여러 서버를 단일 구성으로 묶으면 가장 오래된 서버가 사용하는 프로토콜 세대에 전체 연결이 맞춰질 수 있다. 최신 프로토콜 전용 기능이 필요하다면 구형 서버를 별도 어댑터로 분리해야 한다.

## 확인 범위

GitHub에 게시된 `langchain==1.4.0a2` 릴리스 설명에서 버전 상태, 설치 대상, `MCPAdapter`의 연결 방식과 주요 기능을 확인했다. 실제 운영 환경에서의 성능과 안정성, 개별 MCP 서버와의 호환성은 이 자료만으로 확인되지 않았다.

이번 배포판은 정식 1.4.0이 아닌 알파 프리뷰다. LangChain 측도 정식 출시 전 인터페이스가 변경될 수 있다고 밝혔으므로, 운영 도입 시 API 변경 가능성을 고려해야 한다.
