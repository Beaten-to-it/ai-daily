## 무엇이 있었나

LLM을 실제 에이전트로 운영하는 데 필요한 실행 환경을 통합한 오픈소스 프로젝트 ‘TrueForge’가 소개됐다. 모델 호출뿐 아니라 도구 사용, 샌드박스, 실행 승인, 컨텍스트와 세션 관리까지 에이전트 실행 루프 전반을 다룬다.

TrueForge는 내장 채팅 화면과 HTTP API, TypeScript SDK, 애플리케이션용 UI SDK를 제공한다. OpenAI·Anthropic·Gemini 및 OpenAI 호환 API를 연결할 수 있으며, MCP 서버와 `SKILL.md` 형식의 스킬, 샌드박스를 카탈로그에 등록해 여러 에이전트에서 활용하도록 구성됐다.

원격 MCP 인증과 OAuth 흐름, 사용자 승인, 하위 에이전트, 도구 지연 로딩, 컨텍스트 압축 등도 지원한다. 코드와 파일 작업은 필요할 때 생성되는 Daytona 샌드박스에서 격리하고, 비밀정보는 에이전트가 아닌 하네스 측에서 관리한다.

개인용 로컬 모드는 단일 프로세스와 SQLite로 실행할 수 있지만 로그인 기능이 없어 로컬호스트 외부에 공개해서는 안 된다. 팀·운영 환경에는 Postgres와 Redis를 사용하는 Docker Compose 또는 Helm 배포 방식이 제시됐다. 프로젝트는 MIT 라이선스로 공개됐으며 `npx @truefoundry/trueforge@latest` 명령으로 시작할 수 있다.

## 왜 중요한가

에이전트 개발은 모델을 호출하는 코드만으로 끝나지 않는다. 도구 권한과 사용자 승인, 인증정보 보호, 실행 격리, 대화 상태 저장, 여러 모델 연결 같은 운영 요소를 함께 설계해야 한다. TrueForge는 이 기능들을 하나의 하네스로 제공해 시제품을 실제 서비스로 확장할 때 필요한 기반 작업을 줄이려는 프로젝트다.

국내 개발팀에도 의미가 있다. 특정 모델 공급자에 종속되지 않는 구성을 검토할 수 있고, MCP와 스킬을 공용 카탈로그로 관리해 여러 에이전트에 재사용할 수 있기 때문이다. 로컬 실험과 팀 배포 구성이 구분돼 있다는 점도 단계적인 도입에 유용하다. 다만 로컬 모드를 외부에 노출하지 말라는 보안 제약은 반드시 고려해야 한다.

## 확인 범위

GeekNews에 게시된 프로젝트 소개와 기능 요약을 바탕으로 확인했다. 프로젝트의 실제 구현 완성도, 각 기능의 세부 제약, 운영 환경에서의 성능과 보안 수준은 이 자료만으로 독립 검증하지 않았다.
