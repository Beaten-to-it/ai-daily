## 무엇이 있었나

AWS가 여러 지식 기반을 오가며 답을 찾는 기업용 에이전틱 검색 참조 아키텍처를 공개했다. 이 구성은 Amazon Bedrock Managed Knowledge Base와 Amazon Bedrock AgentCore를 결합하고, 전체 인프라를 네 개의 AWS CloudFormation 스택으로 배포한다.

사용자 질문을 받은 에이전트는 주제에 맞는 지식 기반을 선택한 뒤 AgentCore Gateway의 MCP 도구를 통해 검색을 요청한다. Managed Knowledge Base의 `AgenticRetrieveStream` API는 질문을 하위 질의로 나누고 반복 검색한 뒤, 근거와 출처가 포함된 응답을 생성한다. 검색 결과가 부족하면 에이전트가 다시 검색하는 구조다.

AWS는 이 과정에 지식 기반 상태, 문서 수집 결과, 검색 품질, 게이트웨이 호출, OpenTelemetry 추적, 토큰 사용량, 답변 평가 등 일곱 계층의 관측 기능을 포함했다. 필요할 때 실행하는 평가와 실제 세션 일부를 자동 채점하는 온라인 평가도 함께 제공한다.

예제는 금융과 기상 자료를 각각 별도 지식 기반에 넣어 의미 기반 라우팅을 시연한다. AWS에 따르면 관리형 지식 기반은 문서 수집부터 저장·색인·검색, 임베딩과 재순위화까지 서비스가 담당하므로 별도의 벡터 데이터베이스를 운영할 필요가 없다.

## 왜 중요한가

기업용 RAG가 단일 검색을 넘어 여러 데이터 영역을 판단하고 반복적으로 조회하는 단계로 발전하면서, 답변뿐 아니라 에이전트의 판단 과정과 비용을 추적하는 기능도 중요해지고 있다. 이번 아키텍처는 검색 경로, 호출 지연, 토큰 소비, 답변의 충실도와 도구 선택 정확도를 한 배포 단위 안에서 살펴볼 수 있는 구현 사례다.

한국 기업은 인사·재무·IT처럼 분리된 사내 지식 영역을 각각 독립된 지식 기반으로 유지하면서 질문에 따라 적절한 영역을 선택하는 구조에 참고할 수 있다. 다만 온라인 평가는 표본으로 선택된 세션마다 LLM 기반 평가를 실행하므로 트래픽과 표본 비율에 따라 비용이 늘어난다. AWS 예제의 평가 표본 비율 100%는 실험용 설정이며, 실제 운영에서는 예산과 내부 정책에 맞춰 조정해야 한다.

## 확인 범위

AWS가 2026년 8월 31일 공개한 기술 안내에서 아키텍처 구성, 배포 방식, 관측 계층과 평가 방법을 확인했다. 소개된 성능과 평가 점수는 금융·기상 예제 자료를 사용한 AWS 샘플 결과이며, 일반적인 기업 환경에서 동일한 품질이나 비용 효율을 보장하는 독립 검증 결과는 아니다. 실제 도입 시에는 지원 리전과 모델 접근 권한, IAM 구성, 예상 트래픽, 평가 비용을 별도로 확인해야 한다.
