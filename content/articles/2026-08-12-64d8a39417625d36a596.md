## 무엇이 있었나

NVIDIA가 AI 에이전트의 작업 단계마다 적합한 모델을 선택해 연결하는 오픈소스 도구 ‘NeMo Switchyard’를 소개했다. 요청의 성격과 모델 성능, 비용, 지연시간, 시스템 부하 등을 고려해 여러 전문 모델과 고성능 모델 사이에서 작업을 배분하는 방식이다.

NeMo Switchyard는 특정 모델 제공업체에 종속되지 않는 SDK를 기반으로 한다. 모델의 논리적 이름과 실제 제공업체·엔드포인트를 분리해, 배포 모델이나 공급자가 바뀌어도 라우팅 로직을 유지할 수 있도록 설계됐다. OpenAI·Anthropic·Responses API 형식의 요청을 처리하는 참조 서버도 제공한다.

지원 방식은 별도 학습 없이 사용하는 LLM 분류기, 작업 단계별 라우터, 상향 전환 라우터와 실제 워크로드 데이터로 조정하는 학습형 라우터로 나뉜다. 세션 상태와 이전 도구 실행 결과를 이후 판단에 활용하거나, 필요에 따라 상태를 저장하지 않는 구성도 가능하다.

NVIDIA가 공개한 협력사 평가에서는 비용 절감 가능성도 제시됐다. LangChain은 145개 다중 턴 과제로 구성된 내부 평가에서 두 모델을 함께 사용한 결과, 고성능 모델만 이용한 기준보다 비용이 74% 줄었고 정확도는 약 6%포인트 낮아졌다고 밝혔다. Cognition의 코딩 과제 평가에서는 단계별 라우팅이 고성능 모델 대비 정확도 차이를 2.8%포인트 이내로 유지하면서 평균 비용을 약 28% 낮춘 것으로 보고됐다.

## 왜 중요한가

AI 에이전트는 분류, 추론, 도구 호출, 반복 작업처럼 성격이 다른 단계를 연속해서 수행한다. 모든 요청을 최고 성능 모델에 보내면 비용과 응답시간이 커질 수 있고, 저비용 모델만 쓰면 복잡한 단계에서 품질이 떨어질 수 있다. 모델 라우팅은 이 간극을 작업 단위의 동적 선택으로 조정하려는 접근이다.

국내 기업과 개발팀에는 모델 공급자를 하나로 고정하지 않고 품질·비용·운영 조건에 따라 조합할 수 있다는 점이 의미가 있다. 특히 호출량이 많은 고객지원, 개발 자동화, 사내 업무 에이전트에서는 모델 선택 정책과 실제 절감 효과를 측정할 수 있는 운영 계층이 비용 관리 수단이 될 수 있다.

다만 라우터 자체가 추가 판단과 상태 관리를 요구하므로, 도입 효과는 업무별 성공 기준과 오류 허용 범위, 지연시간, 모델 가격을 함께 측정해야 확인할 수 있다.

## 확인 범위

NeMo Switchyard의 구조와 지원 기능, 라우팅 방식, 협력 사례는 NVIDIA Developer가 공개한 기술 블로그 내용을 기준으로 확인했다. 기사에 제시된 성능과 비용 수치는 LangChain과 Cognition의 특정 평가 환경에서 나온 결과로, 모든 모델이나 실제 서비스에서 동일하게 재현된다고 볼 수는 없다. 독립적인 제3자 검증 결과와 국내 환경에서의 운영 성능은 이번 자료만으로 확인되지 않는다.
