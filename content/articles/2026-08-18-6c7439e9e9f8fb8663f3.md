## 무엇이 있었나

AI 에이전트가 제안한 작업의 실행 여부를 모델 외부에서 판단하는 오픈소스 프로젝트 ‘Agent Control Plane(ACP)’이 GitHub에 공개됐다. 모델이 도구나 시스템을 직접 조작하지 않고 정형화된 작업 요청만 제출하면, 별도의 정책 엔진과 실행기가 서명된 정책을 기준으로 위험도·대상·권한을 다시 확인해 실행, 보류 또는 거부하는 구조다.

이 설계는 프롬프트 인젝션 자체를 탐지하거나 차단하는 대신, 공격에 영향을 받은 모델도 현실 세계에 직접 변화를 일으킬 수 없도록 실행 권한을 분리하는 데 초점을 맞춘다. 고위험·비가역 작업에는 해당 요청의 해시에 연결된 복수의 승인과 재검증 절차를 요구한다.

저장소에는 명세와 Python 참조 구현, Dafny 형식 검증 자료, 공격·변이 테스트, Docker 기반 시연 환경이 포함돼 있다. 프로젝트 측은 검증 스크립트로 형식 증명과 테스트 결과를 로컬에서 재현할 수 있다고 설명한다.

## 왜 중요한가

기업이 AI 에이전트에 결제, 배포, 고객정보 반출, 연구 데이터 공유 같은 권한을 부여하면 모델의 판단 오류가 곧 실제 사고로 이어질 수 있다. 특히 문서나 고객 문의에 숨은 지시가 에이전트의 자격증명과 결합될 경우, 정상 권한을 이용한 잘못된 작업으로 나타나 기존 침입 탐지만으로 구분하기 어렵다.

ACP가 제시한 접근법은 모델의 신뢰성을 실행 안전성의 전제에서 제외한다. 모델 출력은 명령이 아니라 제안으로만 취급하고, 실제 권한은 별도의 정책과 사람의 승인으로 결정한다. 국내에서도 금융·제약·의료·클라우드 운영처럼 되돌리기 어렵거나 규제 대상 데이터를 다루는 에이전트 시스템을 설계할 때 참고할 만한 통제 모델이다.

## 확인 범위

GitHub 저장소에 ACP의 명세, 참조 구현, 검증 자료와 재현 절차가 공개돼 있다는 점을 확인했다. 다만 테스트 통과 수치와 시뮬레이션 결과는 프로젝트 작성자가 제시한 내용이며, 이번 기사 작성 과정에서 검증 스크립트를 별도로 실행해 재현하지는 않았다.

저장소도 현재 근거의 중심은 Python 참조 구현이며 Rust·TypeScript 서비스 대부분은 실행 가능한 제품이 아닌 스캐폴드라고 명시한다. 독립적인 적대적 보안 검토 역시 아직 완료되지 않았다. 따라서 ACP는 평가 가능한 보안 아키텍처와 실험 구현으로 보는 것이 적절하며, 현 상태를 실제 운영 환경에 바로 배포할 수 있는 완성품으로 해석해서는 안 된다.
