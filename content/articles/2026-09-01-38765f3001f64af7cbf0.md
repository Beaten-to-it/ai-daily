## 무엇이 있었나

AWS가 기업 내 AI 에이전트와 도구, 스킬을 한곳에서 등록·검색·관리하는 ‘AWS Agent Registry’를 정식 출시했다. 조직별로 흩어진 에이전트 자산의 소유자와 검토 상태, 수명주기를 추적하고 중복 개발을 줄이는 것이 목적이다.

Agent Registry는 관리자가 전체 자원과 정책을 다루는 거버넌스 영역과, 승인된 자원만 사용자가 검색하는 디스커버리 영역을 분리한다. 등록 대상은 MCP 서버와 그 구성 요소, A2A 에이전트 카드, 마크다운 기반 에이전트 스킬, JSON 형식의 사용자 정의 자원이다. 의미 기반 검색과 정확한 명칭 검색을 지원하며 콘솔·CLI·API 및 CI/CD 파이프라인을 통한 등록도 제공한다.

관리자는 OAuth 또는 IAM 인증, 접근 정책과 승인 절차를 레지스트리 인스턴스별로 구성할 수 있다. 제출된 자원은 초안, 승인 대기, 승인 또는 거부, 사용 중단 상태로 관리되며 AWS CloudTrail이 작업 이력을 기록한다. Amazon EventBridge를 이용해 보안 검사나 사람의 검토를 포함한 조직별 승인 절차와 연계할 수도 있다.

AgentCore Runtime과 AgentCore Gateway에서 실행되는 에이전트 및 MCP 서버를 AWS Organizations 범위에서 자동 탐지하는 기능도 포함됐다. 승인된 자원은 검색 API뿐 아니라 MCP 서버 형태로도 제공돼 호환 IDE나 자동화된 에이전트가 프로그램 방식으로 찾을 수 있다.

## 왜 중요한가

국내 기업에서도 여러 부서가 각자 AI 에이전트를 만들기 시작하면 같은 기능을 반복 개발하거나, 관리되지 않는 ‘섀도 에이전트’가 늘어날 가능성이 있다. 중앙 레지스트리는 어떤 자원이 운영 중이고 누가 책임지며 보안 검토를 거쳤는지 확인할 기준점을 제공한다.

특히 금융·공공·제조처럼 개발·검증·운영 환경의 분리와 감사 추적이 중요한 조직에는 검색 편의성보다 접근 통제와 승인 이력을 함께 제공한다는 점이 의미가 있다. 다만 AWS도 단일 레지스트리의 가시성과 복수 레지스트리의 격리 수준 사이에 운영상 절충이 필요하다고 설명한다.

서비스는 미국 동부 버지니아 북부, 미국 서부 오리건, 유럽 아일랜드, 아시아태평양 도쿄와 시드니 리전에서 제공된다. 한국 리전은 발표된 지원 지역에 포함되지 않았다.

## 확인 범위

AWS가 2026년 8월 31일 공개한 공식 블로그 게시물을 바탕으로 정식 제공 상태, 주요 기능, 지원 자원과 출시 지역을 확인했다. 가격은 사용량 기반이며 AWS 프리 티어가 제공된다고 안내됐지만, 구체적인 요율은 제시된 자료에서 확인하지 않았다.

보안·취약점 평가 신호, 중복 분석, 세분화된 검색 가시성, AWS 외부 자원 자동 탐지, 의존성 그래프와 공개 레지스트리 등은 향후 계획으로 소개된 기능이다. 현재 제공 기능과 혼동해서는 안 된다. 게시물에 실린 고객·파트너의 효과 평가는 각 기업의 진술이며, 독립적인 성능 검증 결과나 정량 비교 자료는 아니다.
