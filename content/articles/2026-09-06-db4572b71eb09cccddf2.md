## 무엇이 있었나

AWS가 9월 4일 NVIDIA Cosmos 3와 Amazon SageMaker HyperPod를 이용해 피지컬 AI 모델을 반복적으로 개선하는 인프라 구축 방법을 공개했다. 실제 데이터를 수집하고 합성 데이터로 보강한 뒤, 모델을 추가 학습하고 시뮬레이션으로 평가하는 과정을 하나의 운영 체계로 연결하는 기술 안내다.

핵심은 여러 작업이 지속적으로 유지되는 GPU 자원 풀과 저장소를 공유하도록 구성하는 것이다. AWS는 EKS 기반 HyperPod에서 데이터 생성·추가 학습·평가 작업을 실행하고, S3와 FSx for Lustre로 데이터와 체크포인트를 함께 사용하는 구조를 제시했다. Cosmos 3 모델 계열은 미래 장면 생성, 영상에서 행동 추정, 로봇 행동 결정 등 서로 다른 역할을 맡는다.

예제에는 공개 DROID 데이터를 활용한 로봇 행동 정책 학습과 두 종류의 시각 인식 모델 학습이 포함됐다. AWS는 NVIDIA H200 GPU 8개를 탑재한 p5en.48xlarge 노드에서 세 작업을 실행했다고 설명했다. 장애 복구와 체크포인트 재개, 분산 학습 통신 검증 방법도 다뤘다.

## 왜 중요한가

국내 로봇·제조·자율주행 개발팀이 참고할 지점은 개별 모델의 성능뿐 아니라 반복 학습 과정 전체의 자원 효율이다. 데이터를 생성할 때와 학습·평가할 때 각각 별도 클러스터를 준비하면 자원 대기와 데이터 이동이 운영 부담으로 이어질 수 있다. 이 안내는 여러 단계를 같은 인프라에 배치하는 구체적인 구성 사례를 제공한다.

AWS는 비용 효율을 판단할 기준으로 예약한 GPU 시간당 실제 파이프라인 진척도를 뜻하는 ‘GPU goodput’을 강조했다. 다만 공유 자원 구성이 얼마나 유리한지는 작업별 GPU 수요, 저장소 접근 방식, 장애 복구 시간에 따라 달라진다. 글에서도 일회성 미세조정에는 임시 관리형 학습 작업으로 충분할 수 있다고 구분했다.

## 확인 범위

제공된 AWS 기술 글에서 아키텍처, 참조 장비, 학습 예제와 운영 설정을 확인했다. 실행 결과는 AWS의 설명이며, 이번 기사에서 코드 실행이나 성능 재현을 수행하지는 않았다.

입력 본문은 성능 측정 방법을 설명하는 7절 도중에 끊겨 있다. 따라서 이후에 예고된 생성·평가 절차의 상세 내용은 확인하지 못했다. 자율주행 추가 학습은 직접 다룬 예제가 아니며, 비용 절감률이나 실제 로봇의 성공률 개선도 제공된 범위에서 확인되지 않는다. 저장소 대역폭 수치 역시 글에서 실측값과 구분한 문서상 상한이다.
