## 무엇이 있었나

엔비디아가 대규모 언어 모델(LLM)의 정확도를 유지하면서 추론 속도를 높이기 위한 추론적 디코딩 설계 지침을 공개했다. 추론적 디코딩은 작은 초안 모델이 여러 후보 토큰을 먼저 생성하고, 큰 목표 모델이 이를 한 번에 검증하는 방식이다. 목표 모델이 승인한 토큰만 결과에 반영하므로 승인 기준을 완화하지 않는 한 일반적인 순차 디코딩과 같은 출력 시퀀스를 얻을 수 있다는 설명이다.

엔비디아는 초안 길이를 무조건 늘리는 것보다 배치 크기, 어텐션 구조, 하드웨어 활용률, 토큰 승인 길이, 초안 생성 비용을 함께 고려해야 한다고 강조했다. 특히 어텐션 연산이 지배적인 환경에서는 하나의 KV 헤드를 공유하는 쿼리 헤드 수를 `G`라고 할 때 초안 길이 `D`의 출발점으로 `128/G - 1`을 제안했다. 이보다 긴 초안을 사용한다면 `G × (1 + D)`가 128의 배수가 되도록 맞춰 어텐션 커널의 타일 낭비를 줄이는 방안도 제시했다.

초안 생성 방식으로는 외부 소형 모델, EAGLE-3, MTP, DFlash, DSpark, 접미사·n-그램 기반 기법을 비교했다. 각 방식은 토큰 승인 성능뿐 아니라 학습 비용, 서비스 시 메모리, 순차 연산 횟수에서 차이가 난다. 엔비디아는 승인 길이가 길다고 반드시 실제 속도 향상이 큰 것은 아니며, 현실적인 요청과 여러 작업 영역을 반영한 SPEED-Bench로 승인 길이를 측정하고 TensorRT-LLM 같은 고성능 추론 프레임워크로 초안 생성 부담을 함께 평가할 것을 권했다.

## 왜 중요한가

국내에서 LLM 기반 검색, 코딩 보조, 요약, 에이전트 서비스를 운영하는 기업에는 모델 정확도를 낮추지 않고 응답 지연과 처리량을 개선할 수 있는 구체적인 최적화 기준이라는 점에서 의미가 있다. 같은 추론적 디코딩 기법이라도 모델 크기와 구조, GPU 운용 방식, 실제 요청의 문맥 길이에 따라 결과가 달라질 수 있어 단순한 기법 도입보다 모델·소프트웨어·하드웨어를 함께 설계해야 한다는 메시지다.

특히 낮은 지연 시간이 중요한 서비스에서는 많은 후보 토큰을 만드는 것보다 승인 증가분이 초안 생성 비용을 충분히 상쇄하는지 확인해야 한다. 목표 모델을 미세조정하면 출력 분포와 내부 표현이 달라져 기존 초안 모델의 승인 성능이 떨어질 수 있으므로, 모델을 갱신한 뒤 실제 서비스 작업으로 다시 측정하고 필요하면 초안 모듈도 재학습하거나 정렬해야 한다.

## 확인 범위

이 기사는 엔비디아가 공개한 기술 블로그의 설명과 해당 글에 제시된 실험·권고를 바탕으로 작성했다. 초안 길이 공식과 타일 크기 128에 관한 기준은 글에서 다룬 현재 GPU 및 벤치마크 커널 조건에 기반하므로 모든 하드웨어와 추론 환경에 그대로 적용되는 보편적 최적값으로 볼 수는 없다. SPEED-Bench 사례의 결과 역시 특정 모델, 작업 분할, 문맥 길이에 관한 것으로, 실제 성능 향상은 대상 모델과 프롬프트, 배치 크기, 서빙 구성에서 별도로 검증해야 한다.
