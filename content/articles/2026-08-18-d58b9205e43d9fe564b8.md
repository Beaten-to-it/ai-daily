## 무엇이 있었나

연구진이 ReAct 방식의 대규모언어모델(LLM) 에이전트가 행동을 실행하고 환경의 응답을 기다리는 시간을 추가 추론에 활용하는 프레임워크 ‘세컨드 소트(Second Thought)’를 제안했다. 별도의 학습 없이 적용하는 추론 단계 기법이다.

이 방식은 에이전트가 한 차례의 사고를 마치는 순간 보조 추론 분기 네 개를 생성한다. 주 실행 흐름이 행동과 관찰을 처리하는 동안 보조 분기에서 다음 단계에 활용할 사고를 병렬로 생성하고, 환경의 관찰 결과가 도착하면 이를 다시 합친다. 추가 추론을 주 실행 흐름의 순차 디코딩 경로 밖에서 수행하는 것이 핵심이다.

논문 초록에 따르면 연구진은 에이전트 벤치마크 3종과 추론 LLM 3종을 조합한 9개 조건에서 실험했다. 모든 조건에서 평균 작업 턴 수가 감소했으며, 6개 조건에서는 주 실행 흐름의 디코딩이 최대 43% 줄었다. 해당 6개 조건의 평균 감소 폭은 약 20%였다. 다른 1개 조건에서는 디코딩 양이 사실상 달라지지 않았다.

성공률 지표인 Pass@1은 9개 조건 중 7개에서 통계적으로 유의미한 변화가 없었다. 유의미한 차이가 나타난 나머지 2개 조건에서는 각각 12.4%포인트와 10.2%포인트 상승했다. 같은 연산 예산을 주 실행 흐름에 직접 투입한 대조군과 비교할 수 있었던 4개 조건에서는 세컨드 소트가 모두 더 높은 Pass@1과 더 적은 순차 디코딩을 기록했다고 연구진은 보고했다.

## 왜 중요한가

LLM 에이전트는 외부 도구나 소프트웨어를 호출할 때 응답을 기다려야 한다. 기존 ReAct 구조에서는 이 대기 구간에 숙고가 멈추지만, 세컨드 소트는 그 시간을 다음 판단을 준비하는 데 사용한다. 같은 수준의 작업을 더 적은 순차 처리로 끝낼 수 있다면 도구 호출이 잦은 업무 자동화 시스템의 응답 지연을 줄이는 데 도움이 될 가능성이 있다.

특히 국내 기업이 고객 지원, 개발 보조, 사내 업무 자동화 등에 에이전트를 도입할 때는 정확도뿐 아니라 처리 시간과 추론 비용도 중요한 운영 지표다. 이번 연구는 연산량을 단순히 늘리는 대신, 대기 시간과 병렬 처리를 활용해 에이전트의 실행 구조를 효율화할 수 있다는 방향을 제시한다.
