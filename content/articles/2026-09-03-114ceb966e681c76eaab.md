## 무엇이 있었나

기업용 통합 플랫폼 업체 부미(Boomi)가 AWS의 AI·클라우드 서비스를 활용해 개발 문서를 자동으로 생성하는 ‘부미 스크라이브(Boomi Scribe)’의 구조와 활용 사례를 공개했다.

부미 스크라이브는 통합 프로세스가 담긴 XML 파일에서 단계와 연결 관계를 추출하고, 이를 방향성 비순환 그래프(DAG) 형식으로 변환한다. 이후 Amazon Bedrock을 통해 Anthropic의 Claude Haiku 4.5에 입력해 프로세스 개요와 다이어그램, 메타데이터, 업무 맥락, 단계별 기능 설명을 생성한다.

이 시스템은 이전 버전과 현재 버전의 DAG도 비교해 추가·수정·삭제된 구성 요소를 보여준다. 생성된 문서와 메타데이터는 Amazon S3에 저장되며, DynamoDB가 내부 데이터 저장소 역할을 맡는다. AWS Lambda는 파일 분석부터 문서 생성과 버전 비교까지 전체 흐름을 조정하고, Amazon SageMaker AI는 사용자 의도 분류 모델을 구축하고 관리하는 데 쓰인다.

작성된 문서는 부미의 작업 화면과 Boomi GPT에서 확인할 수 있으며 PDF와 HTML 형식으로 내려받거나 클립보드에 복사할 수 있다. AWS가 소개한 부미 사례에 따르면 문서 작성 시간은 최대 85% 줄었고, 고객별로 하루 수백 개의 프로세스를 처리할 수 있도록 설계됐다.

## 왜 중요한가

복잡한 업무 시스템을 연결하는 통합 프로세스는 담당자가 바뀌거나 버전이 누적될수록 구조와 변경 이유를 파악하기 어려워진다. 문서가 실제 구현과 어긋나면 장애 분석과 인수인계가 지연되고, 감사나 규제 대응 과정에서도 공백이 생길 수 있다.

부미 스크라이브 사례는 생성형 AI에 원본 파일을 바로 맡기는 대신, 먼저 프로세스를 구조화된 그래프로 바꾼 뒤 문서를 생성하는 방식을 보여준다. 국내 기업도 레거시 시스템이나 여러 SaaS를 연결하는 환경에서 이런 접근을 활용하면 문서 작성 부담을 줄이고 변경 이력을 더 체계적으로 관리할 수 있다.

다만 자동 생성 문서는 운영 절차와 규정 준수의 근거로 쓰이기 전에 정확성 검토가 필요하다. 특히 모델이 작성한 업무 맥락이나 단계 설명은 원본 구성 정보만으로 확정하기 어려운 의미를 포함할 수 있으므로 사람의 확인 절차를 두는 것이 중요하다.

## 확인 범위

AWS와 부미 관계자가 공동 작성한 AWS ML 블로그 게시물에서 시스템 구성, 처리 흐름, 제공 기능과 성과 수치를 확인했다. 문서화 시간 최대 85% 절감과 처리 규모는 게시물에 제시된 부미 사례 기준이며, 독립적인 성능 평가나 비용·오류율 자료는 원문에 포함되지 않았다. 실제 효과는 프로세스 복잡도, 입력 데이터 품질, 검토 절차와 운영 환경에 따라 달라질 수 있다.
