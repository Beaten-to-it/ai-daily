## 무엇이 있었나

AI 에이전트가 Gmail, Slack, GitHub, Notion, Stripe 같은 외부 서비스를 이용할 때 필요한 도구와 인증 정보, 실행 권한을 한곳에서 관리하는 TypeScript 라이브러리 ‘Corsair’가 소개됐다. MCP로 에이전트에 연결하거나 SDK를 애플리케이션에 직접 통합할 수 있으며, 필요한 서비스별 패키지만 설치해 등록하는 구조다. 지원되지 않는 API는 자체 플러그인으로 확장할 수 있다.

Corsair는 API 키와 OAuth 토큰을 내부에서 불러와 호출하고, 에이전트에는 실행할 메서드와 결과만 전달한다. 권한 정책은 모든 작업을 허용하는 `open`부터 읽기만 허용하는 `readonly`까지 네 가지 모드를 제공한다. 통합 서비스 전체에 적용한 정책과 별도로 특정 API의 권한도 재정의할 수 있다.

승인이 필요한 작업은 즉시 실행하지 않고, 사용자가 내용과 매개변수를 검토할 수 있는 10분 만료 승인 링크를 만든다. 승인 요청은 에이전트가 접근할 수 없는 데이터베이스에 보관되며, 상태가 승인으로 바뀌어야 실행된다. 테넌트별 자격 증명과 데이터 저장소, 권한 판단을 분리하는 다중 테넌시와 봉투 암호화 방식의 자격 증명 저장도 지원한다. 라이선스는 Apache-2.0이다.

## 왜 중요한가

AI 에이전트가 실제 업무 도구와 연결될수록 편의성뿐 아니라 오발송, 데이터 삭제, 자격 증명 노출 같은 위험도 커진다. Corsair는 에이전트가 할 수 있는 작업을 서비스와 API 단위로 제한하고, 민감한 실행에는 사람의 승인을 끼워 넣는 공통 계층을 제공한다는 점에서 의미가 있다.

국내 기업이 사내 메일·협업 도구와 AI 에이전트를 연결할 때도 최소 권한, 사용자 승인, 테넌트 분리 같은 통제 장치를 애플리케이션마다 따로 구현하는 부담을 줄일 가능성이 있다. 특히 에이전트가 인증 정보나 별도의 직접 호출 경로에 접근하지 못하도록 시스템을 설계해야 승인 절차가 실질적인 보호 장치로 작동한다.

## 확인 범위

이 기사는 GeekNews에 공개된 Corsair 소개 내용을 토대로 기능과 구성 방식을 정리했다. 권한 모드, 승인 링크의 만료 시간, 다중 테넌시, 암호화 방식, 플러그인 구조와 라이선스는 해당 자료에서 확인했다. 실제 운영 환경에서의 보안성, 지원 서비스 범위, 성능과 안정성은 이 자료만으로 검증하지 않았다.
