## 무엇이 있었나

AWS는 Amazon Bedrock AgentCore Runtime에 호스팅한 모델 컨텍스트 프로토콜(MCP) 서버를 Amazon Quick의 채팅 에이전트와 Flows에 연결하는 구현 절차를 공개했다.

제시된 구성에서는 AgentCore Gateway가 두 서비스를 잇는 보안 연결 지점으로 작동한다. Amazon Quick에서 Gateway로 들어오는 요청은 Amazon Cognito를 이용해 인증·인가하고, Gateway가 AgentCore Runtime의 MCP 서버를 호출할 때는 AgentCore Identity와 OAuth 2.0을 사용한다.

구축 과정은 MCP 서버 배포, Gateway와 양방향 인증 구성, Amazon Quick의 MCP 커넥터 등록, 채팅 에이전트 또는 Flow에서의 동작 시험 순으로 진행된다. AgentCore Runtime을 이용하면 세션 격리, 장시간 실행, 영구 파일 시스템, 인증과 관측성 등을 갖춘 서버리스 환경에서 MCP 서버를 운영할 수 있다는 것이 AWS의 설명이다.

## 왜 중요한가

이 방식은 기업이 이미 개발한 도구나 전문 에이전트를 표준화된 MCP 인터페이스로 제공하고, Amazon Quick의 업무용 에이전트에서 다시 활용할 수 있게 한다. 용도마다 별도 커넥터를 만들거나 같은 기능을 반복 구현해야 하는 부담을 줄일 수 있다는 의미다.

국내 기업이 AWS 환경에서 사내 데이터 조회나 업무 자동화용 AI 에이전트를 구축할 때도 참고할 만하다. 특히 사용자 인증과 서비스 간 인증을 분리하고, 공개 네트워크 대신 비공개 VPC 연결을 선택할 수 있어 조직의 접근 통제 요건에 맞춘 설계를 검토할 수 있다. 다만 실제 도입 전에는 Amazon Quick 구독, 서비스 이용 가능 리전, IAM 권한, 모델 접근 권한과 예상 비용을 별도로 확인해야 한다.

## 확인 범위

AWS가 공개한 기술 안내에서 구성 요소, 인증 흐름, 필수 조건과 단계별 연동 절차를 확인했다. 예제는 Python 3.10 이상, AgentCore SDK와 MCP 라이브러리, Docker 실행 환경 등을 전제로 하며 Amazon Quick은 Author 이상 구독을 요구한다.

이번 내용은 AWS가 제공한 구현 예제와 권장 구성에 관한 것으로, 실제 운영 환경의 성능·비용·보안 적합성이나 다른 클라우드 및 MCP 구현체와의 비교 결과까지 입증하는 자료는 아니다. 서비스 사양과 지원 범위는 이후 변경될 수 있다.
