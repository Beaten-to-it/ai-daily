## 무엇이 있었나

AWS가 Amazon Nova Forge에서 다중 턴 강화 미세조정에 사용할 맞춤 보상 함수를 설계하고 운영하는 방법을 공개했다. 다중 턴 학습은 한 번의 답변이 아니라 도구 호출, 코드 실행, 오류 복구 등 여러 단계로 구성된 전체 수행 경로를 평가한다.

AWS가 소개한 방식에서 Nova Forge는 그룹 상대 정책 최적화(GRPO)를 사용한다. 같은 입력에서 생성된 여러 수행 결과를 보상 점수로 비교해 모델을 갱신하기 때문에, 그룹 안에서 점수 차이를 만들지 못하는 보상 항목은 가중치가 높아도 학습에 기여하지 않는다.

예시 실험은 불완전한 개발 요청을 받은 Amazon Nova Lite 2.0이 코드를 바로 추측하지 않고 먼저 확인 질문을 하도록 훈련하는 과제였다. 보상은 숨겨진 단위 테스트의 통과율, 코딩 전 질문 여부, 즉시 추측에 대한 감점, 반복 행동에 대한 감점을 합산했다. AWS는 원하는 행동을 최종 정답 여부와 지나치게 결합하면 초기 학습 단계에서 신호가 사라질 수 있다고 설명했다.

모델이 만든 코드를 채점할 때는 자격증명과 네트워크 접근을 차단하고, 실행 시간·메모리·프로세스 수를 제한해야 한다고 권고했다. 임의의 결과 조작을 막기 위한 실행별 무작위 표식과 실제 테스트 수 검증도 제시했다.

## 왜 중요한가

다중 턴 AI 에이전트의 성능은 모델 자체뿐 아니라 무엇을 보상하도록 설계했는지에 크게 좌우된다. 전체 보상이나 손실 그래프가 정상적으로 보여도 특정 평가 항목의 점수가 모든 결과에서 같다면, 그 항목은 사실상 학습에서 제외될 수 있다.

국내 기업이 상담, 개발 자동화, 업무 실행 에이전트를 맞춤 학습할 때도 같은 문제가 발생할 수 있다. 최종 성공 여부만 평가하면 초기에 보상이 지나치게 희소해지고, 질문 횟수나 대화 길이 같은 중간 지표를 과도하게 강조하면 실제 과업 완수보다 지표를 공략하는 행동이 강화될 수 있다.

따라서 보상 항목별 평균뿐 아니라 같은 입력에서 생성된 결과 사이의 표준편차와 학습 기여도를 따로 관찰할 필요가 있다. 생성 코드나 도구 실행을 평가 과정에 포함한다면 보상 설계와 함께 격리 실행 환경도 필수적인 운영 요소가 된다.

## 확인 범위

AWS ML 블로그에 공개된 기술 설명과 사례를 기준으로 확인했다. 해당 글은 보상 함수 구성, Amazon Nova Forge의 BYOO 환경, GRPO 학습 신호, 생성 코드 실행 시 보안 조치와 실제 학습에서 발견한 보상 붕괴 사례를 다룬다.

다만 예시 코드는 출발점으로 제시된 것이며, 모든 작업에 그대로 적용할 수 있는 범용 설정은 아니다. 게시물에 언급된 질문 행동의 변화도 특정 과제와 학습 구성에서 관찰된 사례이므로 다른 모델이나 업무에서 동일한 결과를 보장하지 않는다.
