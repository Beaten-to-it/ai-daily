## 무엇이 있었나

AWS가 아마존 베드록 기반 검색 증강 생성(RAG) 시스템의 입력 토큰과 추론 비용을 줄이는 ‘질의 인식 압축’ 방식을 소개했다. 검색된 문서를 최종 답변 모델에 모두 전달하는 대신, 소형 모델이 사용자 질문과 관련된 원문 구간만 추려 낸 뒤 주 모델이 이를 바탕으로 답변하는 구조다.

AWS가 제시한 구현 예시는 AWS Lambda에서 아마존 베드록 Converse API를 두 차례 호출한다. 먼저 Claude Haiku가 검색 문맥을 압축하고, 이어 Claude Sonnet이 선별된 근거로 최종 답변을 만든다. 출처 식별자를 유지하고 문장을 요약하거나 바꾸지 않은 채 필요한 구간을 추출하도록 설계해 인용의 추적 가능성도 확보한다.

AWS는 50만 건이 넘는 문서와 500개 질문을 이용한 자체 평가에서 압축 방식이 주 모델에 전달되는 토큰을 기준 대비 12%로 줄이고, 전체 비용을 67% 수준으로 낮췄다고 밝혔다. 재순위화와 압축을 함께 적용했을 때는 토큰이 10%, 비용이 64% 수준으로 감소했다. 종합 품질은 각각 기준의 97.5%와 97.6%였으며, 지연 시간은 19%와 12% 늘었다.

## 왜 중요한가

기업용 RAG는 검색 누락을 줄이기 위해 여러 문서 조각을 가져오는 경우가 많다. 이 문맥을 고성능 모델이 매번 전부 처리하면 서비스 이용량이 늘수록 입력 토큰 비용도 커진다. 질의 인식 압축은 기존 검색 구조를 유지하면서 주 모델이 읽는 문맥만 줄일 수 있다는 점에서 비용 최적화 수단이 될 수 있다.

특히 규정·정책 문서, 고객지원 지식 기반, 사내 운영 문서처럼 긴 자료에서 일부 조항이나 절차를 찾는 업무에 적합할 가능성이 크다. 불필요한 문맥을 덜 전달하면 근거 밖 내용을 생성할 여지도 줄일 수 있다. 다만 압축용 모델 호출이 추가되므로 응답 속도가 중요한 서비스에는 실제 트래픽과 문서로 비용·품질·지연 시간을 함께 검증해야 한다.

## 확인 범위

구조, 구현 예시와 평가 수치는 AWS가 공개한 기술 블로그에서 확인했다. 평가는 9종의 기업 데이터 출처로 구성된 하나의 말뭉치와 특정 질문 분포, 모델 조합을 대상으로 수행됐다. 따라서 다른 문서 구성이나 검색 방식, 모델, 리전, 가격 조건에서도 같은 절감률과 품질이 재현된다고 단정할 수 없다.

AWS 역시 배포 전 대표 질의로 기준 방식과 압축 방식을 비교하고 정확성, 완전성, 인용 정확도, 근거 충실도에 대한 허용 기준을 정할 것을 권고한다. 모델 가격과 지원 리전은 달라질 수 있으므로 실제 도입 시점의 조건을 별도로 확인해야 한다.
