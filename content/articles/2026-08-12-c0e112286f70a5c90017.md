## 무엇이 있었나

AWS가 기업 환경에서 Claude Code와 Claude Desktop을 통제·운영하기 위한 ‘Claude apps gateway’의 프로덕션 참조 배포 방안을 공개했다. 게이트웨이는 개발자용 Claude 애플리케이션과 Amazon Bedrock 또는 Claude Platform on AWS 사이에 배치되는 자체 호스팅형 관리 계층이다.

참조 아키텍처는 AWS Fargate에서 상태 비저장 컨테이너로 게이트웨이를 실행하고, Amazon RDS for PostgreSQL에 로그인 세션과 사용자별 지출 기록을 저장한다. 내부 Application Load Balancer와 Route 53 프라이빗 호스팅 영역을 이용해 사설망에서 접근하도록 구성하며, Bedrock 호출에는 게이트웨이 태스크의 IAM 역할을 사용한다.

주요 기능은 OIDC 기반 통합 인증, 사용자 그룹별 모델·도구 접근 정책, 개인별 사용량 측정, 여러 리전·서비스 간 장애 조치, 사용자별 지출 한도 집행이다. 사용자가 요청을 보내면 게이트웨이가 신원과 그룹을 확인한 뒤 정책과 비용 한도를 적용하고 지정된 추론 서비스로 전달한다. 사용량 지표는 OpenTelemetry를 통해 CloudWatch, Datadog, Splunk, Grafana 등 호환 백엔드로 보낼 수 있다.

AWS는 단일 팀부터 다중 계정 환경까지 다섯 가지 배포 유형도 제시했다. 개발 도구는 게이트웨이로 관리하되 운영 애플리케이션은 Bedrock을 직접 호출하는 혼합형 구성도 포함됐다.

## 왜 중요한가

기업이 Claude 기반 개발 도구를 조직 전체에 도입할 때 인증 정보 배포, 퇴사자 접근 차단, 팀별 모델 권한, 비용 귀속을 하나의 지점에서 관리할 수 있다는 점이 핵심이다. 특히 사용자별 비용 한도를 추론 요청 전에 적용할 수 있어 AWS 계정 단위 비용 관리 도구를 보완한다.

다만 비용 한도는 토큰 수와 정가를 기준으로 계산한 추정치여서 실제 청구액과 같지 않다. 데이터베이스 장애 시 기본 설정에서는 비용 통제가 열림 상태로 실패해 추론이 계속되므로, 엄격한 예산 통제가 필요한 조직은 요청 차단 설정을 검토해야 한다. Bedrock과 다른 서비스 사이의 장애 조치는 계약 조건이나 데이터 처리 지역을 바꿀 수 있어 국내 기업도 보안·컴플라이언스 검토가 필요하다.

## 확인 범위

AWS ML 블로그에 공개된 참조 아키텍처와 기능, 운영상 주의사항을 기준으로 확인했다. 실제 가용 모델, 서비스 지원 지역, 요금, 조직별 계약 조건은 배포 시점과 계정 구성에 따라 달라질 수 있다. 게이트웨이가 산출하는 비용은 통제용 추정치이며, 최종 비용은 Bedrock 호출 로그나 AWS Cost and Usage Report로 대조해야 한다.
