## 무엇이 있었나

Cursor가 자체 코드 호스팅 기능인 ‘Origin’을 모든 유료 플랜에 얼리 베타로 공개했다. 엔터프라이즈 조직은 관리자가 사용하지 않도록 설정할 수 있다.

사용자는 Cursor의 Codebase 탭에서 Origin 저장소를 만들거나 기존 GitHub 저장소를 연결할 수 있다. GitHub와 동기화한 경우 코드 탐색·검색·가져오기는 Origin의 사본을 이용하지만, 변경 사항 전송은 GitHub로 이뤄지며 GitHub가 원본 저장소 역할을 유지한다.

Origin은 저장소별 풀 리퀘스트 생성과 검토, 댓글, 병합 기능을 제공한다. GitHub 저장소와 연결된 풀 리퀘스트의 댓글과 반응도 양방향으로 동기화된다. Cursor 에이전트는 저장소 코드에 관한 질문에 답하거나 코드를 수정하고, 풀 리퀘스트 갱신과 브랜치 전송까지 수행할 수 있다.

배포·CI 연동으로는 Vercel, Depot, Buildkite가 제공된다. Vercel은 풀 리퀘스트별 미리보기 배포를 지원하며, Depot과 Buildkite는 기존 GitHub Actions 워크플로 실행에 활용할 수 있다.

## 왜 중요한가

Origin은 Cursor가 코드 편집 도구를 넘어 저장소 호스팅, 코드 리뷰, 자동화 에이전트, 배포와 CI를 한곳에 묶는 개발 플랫폼으로 확장하고 있음을 보여준다. 국내 개발팀도 GitHub를 원본으로 유지하면서 Cursor의 코드 탐색과 에이전트 기능을 함께 시험할 수 있다는 점에서 도입 장벽이 비교적 낮다.

다만 저장소 사본이 Cursor에 동기화되는 구조이므로 기업이나 규제 산업의 개발 조직은 사용 전에 소스 코드 보관 위치, 접근 권한, 조직 정책과 보안 요건을 별도로 검토할 필요가 있다.

## 확인 범위

GeekNews에 정리된 공개 내용에서 Origin의 얼리 베타 제공 범위, GitHub 동기화 방식, 풀 리퀘스트 기능, 에이전트 지원 및 외부 서비스 연동을 확인했다. 베타 종료 일정, 정식 출시 시점, 별도 요금, 데이터 보관 지역과 세부 보안 정책은 제시된 내용만으로 확인되지 않는다.
