## 무엇이 있었나

Zed가 개발자와 코딩 에이전트가 코드와 대화 맥락을 공유하며 작업하는 별도 애플리케이션 ‘Delta’의 비공개 베타를 시작했다.

핵심 기반인 DeltaDB는 참여자의 대화와 작업 트리를 실시간으로 복제하고, 커밋 사이에서 발생한 코드 변경과 논의를 함께 기록한다. 기존 Git 저장소와 커밋·푸시 방식은 유지되므로 Delta를 사용하지 않는 팀원도 일반적인 Git 작업 흐름을 이어갈 수 있다.

사용자는 대화나 코드의 특정 줄에 댓글을 연결할 수 있다. 코드가 수정된 뒤에도 해당 구현이 나온 배경과 논의 맥락을 추적하고, 같은 자리에서 에이전트에게 설명이나 수정을 요청할 수 있도록 설계됐다. 참여자별 로컬 코드 사본과 클라우드 러너, 브라우저 환경 사이의 동기화도 지원하며, 외부 에이전트 연동의 첫 대상으로 Claude Code가 소개됐다.

Delta는 기존 Zed 편집기에 기능을 바로 추가하는 대신 대화 스레드를 중심으로 새로 개발됐다. 브라우저판 역시 별도의 간소화된 웹 앱이 아니라 Rust 애플리케이션을 WebAssembly로 컴파일하고 WebGL로 렌더링하는 방식이다. Zed는 향후 DeltaDB를 기존 편집기에도 도입할 계획이다.

## 왜 중요한가

코딩 에이전트의 활용 범위가 개인 단위의 코드 생성에서 팀 단위 검토와 인수인계로 넓어지고 있다는 점을 보여준다. Delta가 제시한 방식은 완성된 diff만 검토하는 데서 나아가, 코드가 만들어진 대화와 결정 과정까지 협업 대상으로 삼는다.

한국 개발 조직에서도 에이전트가 작성한 코드의 의도를 확인하거나 중단된 작업을 다른 구성원이 이어받을 때 도움이 될 수 있다. 특히 긴 에이전트 응답이나 대규모 변경 사항의 정확한 위치에 피드백을 붙이는 기능은 반복적인 설명 비용을 줄일 가능성이 있다.

다만 모든 개발 과정을 실시간으로 공유하는 방식이 실제 팀 문화에 적합한지, 장기간 축적된 대화가 간결한 명세·ADR·코드 리뷰를 대신할 수 있는지는 별개의 문제다. GeekNews에 소개된 외부 반응에서도 협업 맥락 보존의 효용과 기록 과잉에 대한 우려가 함께 제기됐다.

## 확인 범위

GeekNews에 게시된 제품 소개 요약과 함께 수록된 반응을 바탕으로 Delta의 공개된 기능, 설계 방향, 비공개 베타 개시 사실을 확인했다. 실제 베타의 안정성, 성능, 보안·권한 관리 방식, 가격, 정식 출시 일정과 DeltaDB의 Zed 통합 시점은 이 자료만으로 확인되지 않는다. 사용자 반응은 제품에 대한 평가와 전망이므로 확인된 제품 사양과 구분해 서술했다.
