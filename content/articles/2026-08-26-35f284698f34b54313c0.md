## 무엇이 있었나

NVIDIA가 대규모 언어 모델(LLM) 추론 엔진의 프로세스 장애에 빠르게 대응하는 ‘섀도 엔진 복구’를 NVIDIA Dynamo의 프리뷰 기능으로 공개했다. 같은 GPU에 초기화를 마친 대기 엔진을 두고, GPU Memory Service(GMS)를 이용해 활성 엔진과 가중치 메모리를 공유하는 방식이다. 활성 프로세스가 종료되면 대기 엔진이 가중치를 다시 불러오지 않고 서비스를 이어받는다.

NVIDIA는 B200 노드에서 NVFP4로 양자화한 GLM-5.2를 두 워커로 운영하다 한 워커를 강제 종료하는 실험을 진행했다. 회사가 공개한 결과에 따르면 두 번째 워커가 다시 요청을 처리하기까지 콜드 재시작은 283초, 섀도 엔진 복구는 7.3초가 걸렸다. 장애 이후 첫 토큰 생성 시간 중앙값은 23.815초에서 1.311초로, 사용자당 디코딩 속도 중앙값은 초당 12토큰에서 46토큰으로 개선됐다.

## 왜 중요한가

LLM 서비스는 엔진 프로세스가 중단되면 모델 가중치 적재, 커널 컴파일, CUDA 그래프 캡처 등을 반복해야 해 복구가 수분까지 지연될 수 있다. 이 시간 동안 남은 워커에 트래픽이 몰리면 응답 지연과 서비스 수준 목표 위반 가능성이 커진다. 섀도 엔진 방식은 가중치를 HBM에 중복 저장하지 않으면서 복구에 필요한 초기화 작업 상당 부분을 미리 끝내, GPU 메모리 부담과 장애 전환 시간을 함께 줄이는 접근이다.

다만 현재 기능은 소프트웨어 프로세스 장애를 대상으로 한다. 하드웨어·노드·다중 노드 장애는 기존 재스케줄링 방식으로 처리해야 한다. 또한 승격된 대기 엔진은 빈 KV 캐시로 시작하므로 전환 직후 첫 토큰 생성 시간이 일시적으로 늘어날 수 있다.

## 확인 범위

기능 구조, 지원 조건과 성능 수치는 NVIDIA가 공개한 기술 블로그의 설명과 자체 벤치마크 결과를 기준으로 확인했다. 실험은 B200 노드, GLM-5.2, TP=8, 최대 컨텍스트 20만 토큰 등 특정 구성에서 수행됐으므로 다른 모델이나 하드웨어에서도 같은 수치가 재현된다고 단정할 수 없다.

현재 프리뷰의 주요 백엔드는 vLLM이다. Kubernetes 1.34 이상에서 Dynamic Resource Allocation을 활성화하고 NVIDIA GPU DRA 드라이버를 설치해야 한다. KV 캐시의 GMS 공유는 아직 지원되지 않으며, NVIDIA는 지원 범위 확대와 캐시 상태 승계를 개발 중이라고 밝혔다.
