## 무엇이 있었나

AWS가 Amazon SageMaker Python SDK v3의 스크립트 모드를 활용해 자체 모델을 학습하고 배포하는 방법을 공개했다. 새 SDK는 프레임워크별 학습 클래스를 `ModelTrainer`로 통합하고, 기존 모델 및 예측기 중심의 배포 방식을 `ModelBuilder`로 재구성했다.

핵심은 로컬 코드 디렉터리와 실행 명령 또는 추론 진입점을 지정하는 `SourceCode` 객체다. SageMaker는 작업을 시작할 때 이 코드를 컨테이너에 동기화한다. 이에 따라 학습 코드를 수정할 때마다 컨테이너 이미지를 다시 만들 필요가 없으며, 사용자는 자체 제작 이미지와 AWS 딥러닝 컨테이너, 제3자 이미지 가운데 필요한 실행 환경을 선택할 수 있다.

AWS는 두 가지 종단 간 사례를 제시했다. 첫 번째는 당뇨병 데이터로 scikit-learn 랜덤 포레스트를 학습한 뒤 DJL Serving 기반 실시간 엔드포인트에 배포하는 흐름이다. 두 번째는 `ml.g5.12xlarge` 인스턴스의 A10G GPU 4개와 Hugging Face Accelerate를 이용해 Stable Diffusion 3.5 Medium을 LoRA 방식으로 미세 조정하는 사례다. 두 작업 모두 `ModelTrainer`, `ModelBuilder`, `SourceCode`라는 같은 구성 요소를 사용한다.

SDK v3는 `Compute`, `InputData`, `OutputDataConfig`, `StoppingCondition` 같은 구조화된 설정 객체도 제공한다. 예제에는 S3 기반 데이터 및 모델 산출물 관리, 반복 학습을 위한 웜 풀, 선택적 MLflow 추적, AWS Secrets Manager를 이용한 Hugging Face 토큰 처리도 포함됐다.

## 왜 중요한가

이번 개편은 모델 코드와 컨테이너 실행 환경을 분리해 개발 반복 속도와 운영 일관성을 높이는 데 의미가 있다. 국내 기업과 개발팀도 하나의 API 패턴으로 전통적인 표 형식 머신러닝부터 다중 GPU 생성형 AI 학습까지 다룰 수 있어, 프레임워크마다 다른 SageMaker 클래스를 익히고 유지하는 부담을 줄일 수 있다.

자체 컨테이너를 유지해야 하는 조직에는 시스템 패키지와 CUDA 라이브러리를 직접 통제하면서도 알고리즘 변경 때마다 이미지를 재빌드하지 않아도 된다는 점이 유용하다. 반대로 컨테이너 운영을 최소화하려는 팀은 배포 단계에서 AWS가 제공하는 기존 이미지를 활용할 수 있다.

다만 예제를 실행하려면 SageMaker와 S3 권한이 있는 AWS 계정 및 IAM 역할, SDK v3, ECR에 등록된 학습 이미지와 S3 버킷이 필요하다. 실시간 엔드포인트와 GPU 학습 인스턴스 등은 비용이 발생할 수 있으므로 사용 후 관련 리소스를 삭제해야 한다.

## 확인 범위

AWS가 게시한 기술 안내에서 SDK v3의 클래스 구성, 코드 주입 방식, 사전 요구 사항과 두 예제의 설정을 확인했다. 기사에 나온 학습 성능, 개발 시간 단축 폭 또는 비용 절감 효과를 비교하는 정량 자료는 제시되지 않았다. 따라서 실제 성능과 비용은 모델, 데이터, 인스턴스, 리전 및 운영 구성에 따라 별도로 검증해야 한다.
