## 무엇이 있었나

AI 코딩 에이전트가 세션이나 도구를 바꿔도 프로젝트 관련 기억을 이어갈 수 있도록 설계된 로컬 메모리 서비스 ‘memnest’가 공개됐다. Rust로 개발된 서비스가 로컬 환경에서 동작하며, Claude Code와 Codex를 비롯한 MCP 지원 도구가 같은 저장소와 인터페이스를 이용하는 구조다.

메모리는 SQLite에 원본으로 저장된다. 정확한 문자열 검색에 유리한 BM25 색인과 의미가 비슷한 표현을 찾는 벡터 색인을 함께 운용하며, 임베딩 모델도 로컬에서 실행한다. 별도의 LLM 호출이나 메모리 조회용 API 키는 요구하지 않는다고 개발자는 설명했다.

의도적으로 저장한 결정·선호·교정 정보와 민감정보를 가린 대화 기록은 분리해 보관한다. 자격증명은 검색 대상에서 제외하고 암호화된 저장소에 넣으며, 자격증명으로 추정되는 문자열은 기록 과정에서 가린다.

공개된 벤치마크에 따르면 한국어 평가 항목의 recall@1은 0.976이지만, 결과를 반환하지 않아야 하는 질의를 판별하는 정확도는 0.200에 그쳤다. 개발자는 관련성이 낮은 기억을 걸러내는 후보 기각 기능을 현재의 주요 약점으로 지목했다. 프로젝트는 MIT 라이선스로 제공된다.

## 왜 중요한가

코딩 에이전트를 장기간 활용하면 서비스 구성, 기술 선택의 배경, 과거 오류의 해결법 같은 맥락을 매번 다시 전달해야 하는 문제가 생긴다. memnest는 특정 에이전트에 종속되지 않는 공통 로컬 저장소를 제안해, 도구를 교체하더라도 프로젝트 지식을 계속 활용할 가능성을 보여준다.

데이터와 임베딩 처리를 로컬에 두는 설계는 코드와 개발 기록을 외부 서비스에 보내는 데 부담을 느끼는 개인·조직에도 의미가 있다. 특히 한국어 검색 성능을 별도 평가하고 실패 사례까지 공개했다는 점은 국내 개발자가 실제 적용 가능성과 한계를 판단하는 데 도움이 된다.

다만 검색 재현율이 높더라도 무관한 결과를 제대로 거부하지 못하면 오래되거나 잘못된 기억이 작업에 섞일 수 있다. 따라서 중요한 설계 결정이나 보안 관련 정보를 맡기기 전에는 검색 결과의 정확도와 민감정보 처리 방식을 실제 환경에서 검증할 필요가 있다.
