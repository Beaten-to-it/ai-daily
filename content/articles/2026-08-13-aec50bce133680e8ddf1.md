## 무엇이 있었나

영국 기업용 소프트웨어 업체 OneAdvanced가 고객 데이터가 영국 밖으로 나가지 않도록 설계한 생성형 AI 서비스를 AWS 런던 리전에 구축했다. 회사는 원하는 모델이 당시 해당 리전의 AWS 관리형 서비스에서 제공되지 않자, Llama 4 Maverick과 Llama Guard 4를 Amazon SageMaker AI에서 직접 운영하는 방식을 택했다.

이 서비스에는 Strands Agents SDK와 Amazon ECS를 기반으로 만든 업무별 AI 에이전트 50여 개가 포함됐다. 의료·법률·인사·교육·마케팅 등 여러 분야를 지원하며, 첫 에이전트 개발 이후 3주 만에 50개 이상으로 확대됐다. 비개발자도 화면에서 역할과 입력 양식, 도구, 시스템 프롬프트를 설정할 수 있는 노코드 제작 기능도 마련했다.

문서 검색에는 Amazon S3, Aurora PostgreSQL과 pgvector를 조합한 자체 RAG 시스템을 사용했다. 개인 문서와 조직 공용 문서를 분리하고, 검색 결과의 출처를 이용자에게 보여주도록 구성했다. Llama Guard 4는 주 모델에 요청이 전달되기 전에 유해 콘텐츠 여부를 검사한다.

OneAdvanced는 이 시스템이 2025년 7월부터 운영 중이며, 사용자 질의와 응답을 저장하거나 모델 학습에 이용하지 않는다고 밝혔다.

## 왜 중요한가

이번 사례는 규제 산업에서 AI 도입의 핵심 조건이 모델 성능뿐 아니라 데이터의 저장 위치, 접근 권한, 운영 통제권이라는 점을 보여준다. 필요한 모델을 특정 지역의 관리형 서비스로 이용할 수 없을 때 자체 호스팅으로 데이터 주권 요건을 충족한 사례이기도 하다.

한국에서도 의료·금융·공공 분야처럼 민감정보와 망·지역 규제가 중요한 조직이라면 참고할 만하다. 다만 자체 모델 운영에는 고성능 GPU 인프라와 배포·확장 역량, 안전성 검사, 문서 접근 통제까지 함께 필요하다. 빠른 에이전트 개발과 엄격한 데이터 통제를 동시에 달성하려면 모델 선택보다 전체 운영 구조를 먼저 설계해야 한다는 의미가 있다.

## 확인 범위

AWS가 OneAdvanced와 공동 작성한 기술 사례를 바탕으로 구축 방식과 회사가 공개한 운영 결과를 확인했다. 에이전트 수, 개발 기간, 데이터 처리 방침, 운영 개시 시점과 성능 달성 여부는 해당 글에 제시된 내용이다. 독립적인 감사 자료나 실제 고객별 성능 지표, 비용, 장애 이력은 제공되지 않아 검증 범위에 포함하지 않았다.
