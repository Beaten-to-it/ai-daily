## 무엇이 있었나

사이버보안 자산 인텔리전스 기업 Axonius가 Amazon Bedrock AgentCore를 기반으로 고객별 전용 AI 에이전트 환경을 구축했다. 여러 고객이 하나의 실행 환경을 공유하는 방식 대신, 기존 SaaS 구조에 맞춰 고객마다 별도의 AgentCore 런타임과 네트워크 인터페이스를 두는 격리형 모델을 선택했다.

각 사용자 세션은 독립된 마이크로VM에서 실행된다. 고객 데이터가 필요할 때는 단기 JWT를 이용해 해당 사용자가 원래 접근할 수 있는 범위에서만 Axonius API를 호출하도록 설계했다. 인증 정보는 에이전트 상태에 저장하지 않고 별도 헤더로 전달하며, 고객 시스템과의 통신에는 사설 AWS 네트워크를 사용한다.

아키텍처에는 Amazon Bedrock Knowledge Bases와 Guardrails, CloudWatch, VPC Lattice 등이 포함됐다. CloudWatch와 IAM 역할 태그로 고객별 토큰 사용량과 비용을 추적하고, 설정한 예산을 넘으면 IAM 거부 정책으로 추가 모델 호출을 차단할 수 있게 했다. AWS에 따르면 Axonius는 자체 기반 시설을 개발할 때 예상한 8주 대신 10일 만에 운영 환경을 마련해 출시 준비 기간을 75% 단축했다.

## 왜 중요한가

기업용 AI 에이전트는 모델 성능뿐 아니라 고객별 데이터 격리, 기존 권한 체계 연동, 사설 네트워크 연결, 비용 통제가 함께 해결돼야 한다. 특히 민감한 고객 정보를 다루는 국내 보안·금융·B2B SaaS 사업자에게는 공유형 런타임의 효율성과 고객별 전용 환경의 격리 수준 사이에서 어떤 구조를 택할지가 중요한 설계 과제다.

이번 사례는 고객별 전용 런타임을 선택하면 격리와 권한 구조가 단순해지는 대신, 고객 수만큼 환경을 배포·관찰·갱신해야 한다는 운영 부담이 생긴다는 점도 보여준다. 따라서 국내 기업이 같은 방식을 검토할 때는 자동 프로비저닝과 중앙 관측 체계, 서비스 할당량, 고객별 비용 관리까지 함께 설계할 필요가 있다.

## 확인 범위

AWS ML 블로그에 공개된 Axonius 구축 사례와 아키텍처 설명을 기준으로 정리했다. 고객별 런타임 구성, 세션 격리, JWT 기반 권한 전달, 사설 연결 및 비용 통제 방식은 해당 글에서 확인된다. 개발 기간과 단축률은 AWS와 Axonius가 제시한 수치이며, 독립적인 성능 평가나 보안 감사 결과는 본 자료만으로 확인되지 않는다.
