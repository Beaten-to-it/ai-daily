## 무엇이 있었나

GitHub가 Copilot의 기업용 결제 방식과 서비스 정책, 코드 리뷰 기본 설정을 순차적으로 바꾼다.

우선 2026년 9월 1일부터 신용카드나 PayPal로 결제하는 신규 Copilot Business·Enterprise 고객의 가입을 다시 받기 시작한다. 새로 배정하는 좌석은 사용자가 Copilot에 접근하기 전에 좌석별 결제가 필요하다. 기존 고객에게는 10월 1일부터 다음 결제 주기 시작 시 배정된 모든 좌석에 요금이 선불 청구된다. 다만 제품 가격 자체는 바뀌지 않으며, 결제 주기 도중 추가한 좌석에는 기존처럼 남은 기간을 기준으로 일할 계산이 적용된다. 좌석을 회수해도 일할 환불은 제공되지 않는다.

이르면 9월 28일부터 github.com과 GitHub Mobile의 Copilot Chat, Copilot 클라우드 에이전트가 하나의 경험과 정책으로 통합된다. 통합 기능은 출시 후 기본 활성화되며, github.com의 Copilot은 에이전트 세션 방식으로 완전히 전환된다. 이에 따라 채팅 데이터 보존 기간도 기존 28일에서 계정 존속 기간으로 변경된다. 통합 정책을 거부하면 출시 이후 github.com과 GitHub Mobile에서 Copilot을 이용할 수 없게 된다.

같은 날 Copilot 코드 리뷰의 `Default` 노력 수준은 `Lite`에서 `Balanced`로 바뀐다. 기존 설정을 유지하려는 조직과 저장소는 9월 28일 전에 기본값 대신 `Lite`를 명시적으로 선택해야 한다.

## 왜 중요한가

국내 기업과 개발 조직은 비용뿐 아니라 데이터 보존과 접근 정책도 함께 점검해야 한다. 특히 신용카드나 PayPal로 기업용 Copilot을 결제하는 조직은 좌석 배정 시점과 선불 청구 방식이 예산 및 계정 관리 절차에 미칠 영향을 확인할 필요가 있다.

통합 정책은 채팅 데이터의 보존 기간을 크게 바꾸므로, 보안·개인정보·내부 개발정보 관리 기준과 맞는지 검토해야 한다. 관리자가 통합 정책을 비활성화하면 웹과 모바일 Copilot 접근 자체가 중단될 수 있다는 점도 운영상 중요하다.

코드 리뷰에서 `Balanced`가 기본값이 되면 별도로 설정하지 않은 조직과 저장소의 리뷰 동작 및 사용량에 영향을 줄 수 있다. 현재 `Lite` 수준을 전제로 운영 중이라면 변경일 전에 조직·저장소 설정을 확인해야 한다.

## 확인 범위

GitHub Changelog가 2026년 8월 28일 발표한 향후 변경 사항을 기준으로 확인했다. 결제 변경은 결제 수단이 신용카드 또는 PayPal인 Copilot Business·Enterprise 고객을 대상으로 설명돼 있으며, 다른 계약·청구 방식에 대한 적용 여부는 이 발표만으로 확인되지 않는다.

통합 경험의 출시는 9월 28일보다 이르지 않다고 안내됐으므로 실제 시행일은 늦어질 수 있다. 구체적인 데이터 관리 조건, 지역별 법적 영향, 고객별 청구 금액은 각 조직의 계약과 GitHub 설정·문서를 추가로 확인해야 한다.
