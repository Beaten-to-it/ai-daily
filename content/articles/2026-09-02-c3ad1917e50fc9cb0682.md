## 무엇이 있었나

오픈소스 AI 에이전트 플랫폼 ‘오픈클로(OpenClaw)’가 시스템 전반을 재설계한 2.0 버전을 공개했다. 기사에 따르면 933명의 개발자가 참여해 1만6000건 이상의 풀 리퀘스트를 반영했으며, 설치와 메시징, 세션 관리, 모델 연동, 자동화, 브라우저, 네이티브 앱, 플러그인, 보안 체계를 폭넓게 손질했다.

브라우저 기반 ‘컨트롤 UI’는 대화와 파일, 승인 요청, 실시간 작업을 한 화면에서 다루도록 개편됐다. 기사에 소개된 모의 환경 테스트에서는 자바스크립트 요청이 140회에서 45회로 감소하고 초기 구동 시간이 약 1.6초에서 575밀리초로 줄었다.

세션 저장 방식은 파일 기반에서 SQLite로 바뀌었고, 다른 사용자가 실시간 작업에 참여하거나 맥락을 이어받을 수 있는 공유 클라우드 세션도 추가됐다. 다만 이 협업 기능의 권한 설정은 완전한 테넌트 격리나 독립적인 보안 경계를 보장하지 않는다고 명시됐다.

보안 측면에서는 게이트웨이의 기본 연결 범위를 로컬 루프백으로 제한하고, 알 수 없는 다이렉트 메시지 발신자에게 페어링 코드를 요구하도록 했다. 외부 접근과 도구 실행 범위, 네트워크 노출, 브라우저 제어, 플러그인 허용 목록을 검사하는 보안 감사 명령도 도입했다. 프롬프트 인젝션 위험에 대응하기 위해 도구 실행 정책과 명시적 승인, 샌드박싱을 결합하는 구조도 강조했다.

## 왜 중요한가

오픈클로 2.0은 AI 에이전트 경쟁의 초점이 모델의 답변 성능뿐 아니라 실제 업무를 안전하게 실행하고 장시간 상태를 유지하는 기반 구조로 이동하고 있음을 보여준다. 여러 모델과 로컬 실행 환경, 외부 서비스를 연결하는 개방형 플랫폼은 특정 사업자에 대한 종속을 줄일 수 있지만, 연결 범위가 넓어질수록 권한 관리와 데이터 보호의 중요성도 커진다.

한국의 개발자와 기업 이용자에게는 SQLite 기반 세션 관리, 통합 작업 화면, 실행 전 승인 및 보안 감사 기능이 실무 도입 가능성을 판단할 주요 요소다. 동시에 공유 세션이 완전한 보안 격리를 뜻하지 않는다는 설명을 고려해, 조직에서 사용할 때는 계정·게이트웨이·플러그인의 신뢰 경계를 별도로 설계할 필요가 있다.

## 확인 범위

이 글은 AI타임스가 보도한 오픈클로 2.0의 공개 내용과 기사에 제시된 개발 규모, 성능 시험 결과, 기능 및 보안 설명을 바탕으로 작성했다. 성능 수치는 모의 환경에서 측정된 결과이므로 실제 기기와 네트워크, 구성에 따라 달라질 수 있다. 업데이트의 전체 변경 내역과 보안 효과, 공유 세션의 구체적인 격리 수준은 이 출처만으로 독립 검증하지 않았다.
