## 무엇이 있었나

AWS가 데이터 파이프라인 구축을 지원하는 에이전트형 데이터 운영 플랫폼 ‘ADOP(Agentic Data Operations Platform)’의 참조 아키텍처를 공개했다. Amazon Bedrock과 AI 코딩 도구를 활용해 메타데이터 생성, 데이터 품질 검사, ETL 변환, 의미 계층 정의, 워크플로 오케스트레이션 등 Bronze·Silver·Gold 계층 전반의 작업물을 생성하는 방식이다.

ADOP의 핵심은 AI 에이전트를 개발 단계에서만 사용하고, 사람이 검토한 PySpark·SQL·Airflow DAG·권한 정책 등의 결정론적 산출물을 CI/CD를 통해 운영 환경에 배포하는 구조다. 기본 설계에서는 운영 중인 데이터 파이프라인이 모델을 호출하지 않아 실행 결과와 비용을 예측하고 감사를 수행하기 쉽도록 했다.

조직의 기술 표준과 설계 원칙은 ‘아키텍처 계약’과 의사결정 엔진에 반영된다. 각 하위 에이전트는 도구 사용 규칙, Cedar 권한 정책, 불변 조건, 규제 관련 프롬프트 등의 통제를 받는다. 에이전트의 의도와 도구 선택, 결과, 비용은 AgentTrace로 추적해 Amazon CloudWatch나 OpenTelemetry 저장소로 보낼 수 있다.

## 왜 중요한가

국내 기업도 새로운 데이터 원천을 연결할 때 ETL 작성부터 품질 규칙, 권한 및 규제 검토까지 반복적인 작업을 수행한다. ADOP가 제시한 방식은 이 과정을 자연어 기반 온보딩 흐름으로 표준화하면서도, 생성된 코드를 사람이 검토하고 기존 배포 절차를 거치게 한다는 점에서 주목할 만하다.

특히 금융·의료처럼 규제 요구가 큰 분야에서는 AI가 운영 환경에서 직접 판단하도록 두기보다 개발 단계에서 초안을 만들고 정적 산출물만 배포하는 접근이 비용 관리와 감사 대응에 유리할 수 있다. Claude Code, Kiro, Cursor, Codex 등 서로 다른 코딩 도구를 같은 아키텍처 계약 아래에서 운용할 수 있다는 점도 조직 차원의 AI 개발 거버넌스와 연결된다.

다만 AI가 생성한 마스킹 규칙이나 보존 정책, 접근 통제는 인증된 규제 준수 구현이 아니다. AWS 역시 엔지니어의 필수 검토와 법무·개인정보·컴플라이언스 조직의 별도 검증을 요구하고 있다.

## 확인 범위

AWS가 공개한 기술 블로그의 아키텍처 설명, 적용 사례, 보안 및 책임 있는 AI 지침을 확인했다. ADOP는 완제품 서비스라기보다 AWS 샘플 저장소를 바탕으로 조직별 표준을 구성하는 참조 아키텍처다.

AWS는 후속 데이터 원천의 온보딩 기간이 크게 줄어들 수 있다고 설명하지만, 구체적인 고객 사례나 독립 검증된 성능 수치는 제시하지 않았다. 따라서 제목에 언급된 ‘수 시간’ 수준의 단축 효과를 일반적인 성과로 단정할 수 없으며, 실제 결과는 데이터 복잡도와 조직의 아키텍처 계약, 검토 절차에 따라 달라질 수 있다.
