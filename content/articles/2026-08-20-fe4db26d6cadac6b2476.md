## 무엇이 있었나

NVIDIA가 서로 다른 기관의 원본 데이터를 한곳에 모으지 않고 비전·언어 모델을 공동 학습하는 NVIDIA FLARE 기반 워크플로를 소개했다. 서버가 학습 라운드와 업데이트 집계를 조율하고, 각 참여 기관은 데이터 전처리와 모델 학습을 로컬 환경에서 수행하는 구조다.

FLARE는 대형 객체를 별도로 전송하는 외부화 기능, 텐서 스트리밍, 디스크 기반 집계를 지원한다. 네트워크로 주고받을 모델 업데이트가 크거나 여러 참여자의 업데이트를 서버 메모리에 동시에 올리기 어려울 때 통신 및 메모리 부담을 낮추기 위한 기능이다. NVIDIA는 FLARE 2.8.0에서 PyTorch FedAvg 업데이트를 임시 safetensors 파일로 저장해 필요할 때 불러오는 텐서 디스크 오프로딩도 지원한다고 설명했다.

William & Mary와 NVIDIA가 공동 개발한 FedUMM 사례도 공개됐다. 이 방식은 BLIP 계열 백본을 고정한 채 각 클라이언트가 LoRA 어댑터만 학습하고, 서버는 어댑터 업데이트만 집계한다. 공개된 8개 클라이언트 실험에서는 클라이언트당 라운드 통신량이 전체 모델을 교환할 때의 28.6GB에서 0.094GB로 감소했다. VQA v2 점수는 전체 모델 FedAvg보다 0.7점 높았으며, VQA v2와 GenEval 모두 중앙집중식 기준 성능의 약 97%를 유지했다고 NVIDIA는 밝혔다.

## 왜 중요한가

의료·금융·제조처럼 개인정보, 영업비밀 또는 기관별 보안 정책 때문에 데이터를 중앙 서버로 이전하기 어려운 분야에서는 연합학습이 대안이 될 수 있다. 이번 사례는 멀티모달 모델에서도 원본 데이터를 각 기관에 둔 채 협업 학습을 구성하는 구체적인 방법을 제시한다.

특히 학습 가능한 어댑터만 교환하는 방식은 회선과 서버 자원이 제한된 환경에서 도입 장벽을 낮출 가능성이 있다. 전체 모델 업데이트가 필요한 경우에도 스트리밍과 디스크 오프로딩을 조합할 수 있어, 국내 기업과 연구기관이 참여 기관 수와 모델 규모에 맞춰 시스템을 설계하는 데 참고할 만하다.

다만 연합학습이 데이터 이동을 줄인다고 해서 개인정보 보호나 보안이 자동으로 보장되는 것은 아니다. 실제 적용 전에는 외부 반출이 허용되는 모델 구성 요소와 지표, 업데이트 집계 방식, 장애 대응 절차를 명확히 정하고 별도의 보안·개인정보 보호 검증을 거쳐야 한다.

## 확인 범위

NVIDIA Developer가 공개한 기술 설명과 그 안에 제시된 FedUMM 실험 결과를 확인했다. 해당 평가는 최대 16개 모의 참여 기관, 합성 데이터 분할, VQA v2와 GenEval 등 공개 범용 벤치마크를 사용했다. 따라서 실제 기관 간 운영 환경이나 의료 분야 성능을 입증한 결과로 볼 수 없으며, 공식적인 개인정보 보호 보장도 제시되지 않았다. 통신량과 성능 수치는 NVIDIA가 소개한 특정 8개 클라이언트 실험 조건의 결과로, 다른 모델·데이터·네트워크 환경에 그대로 적용된다고 단정할 수 없다.
