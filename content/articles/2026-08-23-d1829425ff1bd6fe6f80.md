## 무엇이 있었나

AWS는 Amazon Bedrock AgentCore Gateway를 중심으로 기업이 AI 에이전트의 내부 도구 접근을 단계적으로 관리하는 방법을 공개했다. 개별 MCP 설정 파일에 자격증명과 접속 정보가 흩어질 때 발생하는 비밀정보 확산, 정책 불일치, 감사 공백, 비용 추적 한계, 미승인 도구 도입을 주요 문제로 꼽았다.

AWS가 제시한 도입 과정은 네 단계다. 첫 단계인 ‘연결’에서는 게이트웨이를 단일 진입점으로 두고 인증 정보와 접속 기록을 중앙화한다. ‘통제’ 단계에서는 사용자별 권한 정책과 개인정보 필터링, 사용자 동의 절차를 적용한다. ‘카탈로그’ 단계에서는 승인된 도구를 조직 구성원이 검색하고 등록할 수 있게 하며, 온프레미스와 외부 SaaS까지 연결 범위를 넓힌다. 마지막 ‘강화’ 단계에서는 사설 연결, 장애 전환, 운영 대시보드, 사용하지 않는 도구의 폐기 절차를 추가한다.

이 구조에는 AgentCore Identity를 통한 인증·자격증명 관리, AgentCore Policy의 세부 권한 통제, Amazon Bedrock Guardrails의 민감정보 보호, AWS Agent Registry의 도구 검색·관리 기능이 함께 활용된다. AWS는 모든 조직이 처음부터 전체 구성을 도입하기보다 실제 보안 및 운영 문제가 나타나는 시점에 다음 단계로 확장할 것을 권고했다.

## 왜 중요한가

기업용 AI 에이전트는 답변 생성에 그치지 않고 데이터베이스 조회, 배포, 환불과 같은 실제 업무 도구를 호출할 수 있다. 이때 개발자 PC마다 접속 자격증명과 정책을 따로 관리하면 누가 어떤 데이터와 기능에 접근했는지 신속하게 파악하기 어렵다.

이번 접근법은 국내 기업에도 AI 에이전트 도입의 핵심 과제가 모델 성능뿐 아니라 접근권한, 개인정보 보호, 감사 기록, 장애 대응이라는 점을 보여준다. 특히 금융·공공·의료처럼 규제와 내부통제가 중요한 분야에서는 사용자와 에이전트의 권한을 구분하고, 도구 호출 단위로 정책을 적용하며, 모든 결정을 기록하는 구조가 실서비스 전환의 중요한 조건이 될 수 있다.

다만 AWS 서비스 중심의 참조 아키텍처이므로 기존 클라우드 구성, 사내 인증 체계, 데이터 위치와 규제 요건을 고려해 적용 범위와 비용을 별도로 검토해야 한다.

## 확인 범위

AWS가 2026년 8월 21일 게시한 기술 안내에서 AgentCore Gateway 기반의 4단계 거버넌스 모델과 각 단계의 구성 요소, 적용 예시를 확인했다. 서비스 기능과 권장 구조는 AWS의 공식 설명을 기준으로 정리했다.

본문에 제시된 구축 기간, 비용 절감 효과, 금융사 도입 사례와 운영 성과는 해당 AWS 게시물의 설명이며 독립적인 제3자 자료로 교차 검증하지 않았다. 실제 리전별 제공 범위와 세부 사양은 달라질 수 있으므로 도입 시점의 공식 문서를 추가로 확인해야 한다.
