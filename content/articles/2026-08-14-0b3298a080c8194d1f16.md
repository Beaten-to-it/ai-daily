## 무엇이 있었나

AWS가 Amazon Bedrock AgentCore Browser Tool과 Strands Agents를 결합해 레거시 웹 애플리케이션의 업무를 자동화하는 참조 구현을 공개했다. 현대적인 API가 없는 시스템도 관리형 Chromium 브라우저를 통해 조작할 수 있도록 설계한 사례다.

AI 에이전트는 화면을 캡처해 시각 지원 기반 모델로 상태를 파악하고, 클릭·입력·스크롤 같은 다음 행동을 결정한다. Playwright와 Chrome DevTools Protocol을 이용하며, 예상하지 못한 화면이나 검증 절차가 나타나면 고정된 스크립트에만 의존하지 않고 새 상태를 다시 분석한다.

참조 아키텍처에는 격리된 브라우저 세션, IAM 접근 제어, Cognito 인증, S3 기반 기록 저장, CloudWatch 관측 기능이 포함됐다. 중요한 변경을 제출하기 전에는 작업을 일시 정지하고 운영자에게 확인을 요청하는 사람 개입 절차도 지원한다. AWS는 운영자용 React 화면과 Python 기반 에이전트, 프록시, AgentCore 런타임 등을 Terraform으로 배포하는 구성과 소스 코드를 함께 제시했다.

## 왜 중요한가

국내 금융·제조·유통·의료 현장에도 API 없이 웹 화면으로만 처리해야 하는 오래된 업무 시스템이 적지 않다. 이런 환경에서는 화면 구성과 요소 위치에 민감한 기존 RPA가 작은 UI 변경에도 중단될 수 있다. 화면의 의미를 해석하는 에이전트 방식은 이 같은 유지보수 부담을 줄일 가능성을 보여준다.

다만 실제 운영에서는 자동화율뿐 아니라 개인정보 처리, 내부망 연결, 모델의 오판, 권한 분리와 감사 기록을 함께 검토해야 한다. 특히 데이터 변경이나 승인처럼 되돌리기 어려운 단계에는 사람의 확인을 유지하는 설계가 중요하다. 이번 사례는 기존 시스템을 즉시 교체하지 않고도 에이전트 기반 자동화를 시험할 수 있는 기술적 청사진이라는 데 의미가 있다.

## 확인 범위

AWS가 2026년 8월 13일 게시한 기술 글에서 설명한 참조 구현의 구성과 동작을 확인했다. 격리 세션, 브라우저 프로필, 프록시 연결, 세션 기록, 사람 개입 절차와 Terraform 배포 방식은 해당 글에 제시된 내용이다.

보험 업무와 비용·처리량 관련 내용은 실제 고객 도입 성과가 아니라 AWS가 문제를 설명하기 위해 든 시나리오다. 따라서 생산성 향상 폭, 오류 감소율, 규제 충족 여부는 확인된 실증 결과로 볼 수 없다. 실제 적용 가능성과 성능은 대상 시스템의 인증 방식, 네트워크 환경, 화면 구조, 모델 선택 및 조직의 통제 절차에 따라 달라질 수 있다.
