## 무엇이 있었나

리누스 토르발스가 AI를 활용해 인텔 Xe GPU 드라이버의 메모리 경계 계산 오류를 추적했다. 이 버그는 16GiB Battlemage G21 시스템에서 압축 메타데이터용 CCS 영역 일부를 일반 VRAM으로 잘못 할당해, 검은 화면과 gdm 재시작 반복을 일으켰다.

문제의 함수는 CCS 시작 주소를 128KiB 단위로 올림해 계산했다. 그 결과 CCS가 사용하는 마지막 2KiB를 포함한 페이지가 VRAM 할당 풀에 노출됐고, 해당 위치에 배치된 Mesa VM의 레벨 3 페이지 테이블이 압축 하드웨어에 의해 손상됐다.

수정은 주소를 128KiB 단위로 올리는 대신 VRAM 페이지 크기인 4KiB 단위로 내리도록 바꾸는 것이었다. 코드상으로는 사실상 한 줄 변경이지만, 원인 규명에는 디버그 패치 24개와 커널 부팅 18회가 필요했다. AI는 디버그 코드 작성과 결과 분석을 지원했으며 최종 커밋 메시지도 작성했다.

## 왜 중요한가

이번 사례는 AI가 커널처럼 복잡한 저수준 소프트웨어의 디버깅에서도 반복적인 계측과 분석을 보조할 수 있음을 보여준다. 동시에 AI가 조사 도중 여러 차례 해결이 어렵다고 판단했다는 점은, 도구의 분석을 그대로 받아들이기보다 숙련된 개발자가 가설을 세우고 탐색 방향을 계속 통제해야 한다는 점도 드러낸다.

국내 리눅스 사용자와 GPU·커널 개발자에게는 작은 정렬 계산 오류가 페이지 테이블 손상과 로그인 화면 장애로 이어질 수 있다는 구체적인 사례다. 하드웨어 전용 메모리와 일반 할당 영역의 경계를 정할 때 실제 할당 단위에 맞춘 보수적인 계산과 유효한 assertion이 중요하다는 교훈도 제공한다.

## 확인 범위
