## 무엇이 있었나

허깅페이스가 3억5000만 매개변수 규모의 LiquidAI LFM2.5-350M을 구조화 출력 작업에 맞게 미세조정하는 실습 결과를 공개했다. 약 500개 학습 샘플과 TRL 라이브러리의 그룹 상대 정책 최적화(GRPO)를 이용해 100단계 학습한 뒤 IFStruct 벤치마크에서 평가했다.

동일한 llama.cpp 기반 평가 환경에서 전체 통과율은 기본 모델의 22.6%에서 미세조정 모델의 29.7%로 7.1%포인트 상승했다. JSON 통과율은 18.0%에서 31.9%로, 최상위 구조가 배열인 과제의 통과율은 16.6%에서 29.7%로 개선됐다. 반면 YAML 통과율은 27.2%에서 27.5%로 거의 변하지 않았다.

학습에는 출력 형식, 최상위 필드 수, JSON 스키마 준수 여부를 평가하는 세 가지 보상 함수가 사용됐다. 약 600만 개, 전체의 1.66%에 해당하는 매개변수만 LoRA 방식으로 학습했으며 무료 등급의 16GB GPU 환경에서 실행할 수 있도록 구성했다.

## 왜 중요한가

기업이 언어 모델을 업무 시스템에 연결하려면 답변 내용뿐 아니라 JSON 같은 지정 형식을 정확히 지키는 능력이 중요하다. 출력이 파싱되지 않거나 필수 필드가 빠지면 자동화 파이프라인에서 바로 오류로 이어질 수 있기 때문이다.

이번 사례는 범용 성능을 키우기보다 실제 사용 목적에 맞는 보상 신호를 설계하면 작은 모델도 제한된 비용으로 형식 준수 능력을 개선할 수 있음을 보여준다. 자체 인프라나 제한된 GPU 자원으로 AI 서비스를 개발하려는 국내 조직에도 소형 모델 최적화의 참고 사례가 될 수 있다. 다만 개선된 전체 통과율도 29.7%에 머물러, 검증 로직이나 재시도 같은 운영상 안전장치를 대체할 수준으로 보기는 어렵다.

## 확인 범위

수치와 학습 구성은 허깅페이스가 공개한 글에 제시된 실험 결과를 기준으로 확인했다. 평가는 2,000개 IFStruct 샘플과 동일한 로컬 서빙 구성을 사용한 비교이므로 해당 조건 안에서는 직접 비교할 수 있다.

다만 독립 기관의 재현 결과는 이 자료만으로 확인되지 않았다. 또한 사용된 학습 데이터는 IFStruct 평가 데이터와 분포가 다르고, 프롬프트 일부를 코드 블록 및 배열 출력 과제로 보강했기 때문에 다른 모델이나 실제 업무 데이터에서도 같은 폭의 개선이 나타난다고 단정할 수 없다.
