## 무엇이 있었나

AWS가 서로 다른 환경에 분산된 AI 에이전트와 도구를 공통 방식으로 찾을 수 있도록 설계된 개방형 규격 ‘Agentic Resource Discovery(ARD)’를 소개했다. ARD는 특정 제품이나 단일 레지스트리가 아니라, 각 레지스트리가 에이전트·MCP 서버·도구 등의 정보를 일관된 형식과 프로토콜로 제공하게 하는 상호운용 규격이다. Apache License 2.0으로 공개됐으며 AWS는 규격 개발 과정에 의견을 제공했다.

AWS는 이 규격이 자사의 Agent Registry를 보완할 수 있다고 설명했다. AWS Agent Registry는 조직이 에이전트와 관련 자원을 등록하고 검색하는 중앙 카탈로그로, 승인 절차, 의미·키워드 결합 검색, MCP 엔드포인트, IAM 또는 JWT 기반 접근 제어를 지원한다. ARD를 적용하면 자원을 다른 환경으로 이전하지 않고도 멀티클라우드, 온프레미스, SaaS에 있는 카탈로그 간 탐색 체계를 구성할 수 있다는 구상이다.

## 왜 중요한가

기업에서 AI 에이전트 활용이 늘어나면 모델 성능뿐 아니라 필요한 도구를 어디서 찾고, 누가 사용을 승인하며, 접근 권한을 어떻게 회수할지가 운영상의 핵심 과제가 된다. 환경마다 별도의 메타데이터 형식과 연결 방식을 사용하면 레지스트리 조합별로 전용 연동 장치를 개발해야 한다.

ARD가 여러 사업자와 도구에 채택될 경우 국내 기업도 클라우드와 사내 시스템에 흩어진 에이전트 자원을 공통 방식으로 검색하면서 관리 권한은 각 환경에 남겨둘 수 있다. 특히 MCP 기반 도구 생태계를 운영하거나 복수 클라우드를 사용하는 조직에는 자원 중복 등록과 개별 연결 유지 부담을 줄일 가능성이 있다. 다만 실제 효과는 규격의 채택 범위와 구현 간 호환성에 달려 있다.

## 확인 범위

AWS ML이 2026년 8월 24일 공개한 글을 바탕으로 ARD의 성격, 공개 라이선스, AWS Agent Registry의 주요 기능과 두 체계의 연계 구상을 확인했다. 교차 환경 탐색과 공개 카탈로그 연동에 관한 일부 내용은 AWS가 제시한 기대와 전망으로, 광범위한 상용 환경에서의 도입 성과나 상호운용성이 입증됐다는 의미는 아니다. 독립적인 성능 비교나 보안 검증 결과는 제시된 자료에서 확인되지 않았다.
