## 무엇이 있었나

AI 에이전트의 도구 사용 능력을 평가할 시나리오를 MCP 명세만으로 합성하는 연구 ‘Agent Seer’가 arXiv에 공개됐다. 사람이 작성한 예시나 실제 도구 접근, 도메인별 튜닝 없이 함수 이름과 설명, 매개변수 스키마에 담긴 의미를 활용하는 방식이다.

연구진이 제시한 파이프라인은 원시 스키마를 보강한 뒤 난이도가 구분된 시나리오와 가상의 도구 실행 결과를 생성하고, 이를 모의 데이터에 기반한 여러 차례의 대화로 확장한다. 서로 다른 분야의 MCP 명세 7개를 대상으로 도구 호출의 정확성과 대화 일관성을 평가했으며, 소형·중형 명세에서는 모든 도구를 포함하는 시나리오를 만들었다고 보고했다.

분석 결과 품질 차이와 가장 밀접한 요인은 도구 묶음의 크기보다 매개변수 스키마의 복잡성이었다. 불완전한 시나리오에서는 올바른 도구를 고르고도 인수 값을 부정확하게 지정하는 문제가 주요 실패 유형으로 나타났다.

## 왜 중요한가

AI 에이전트가 실제 업무에 투입되려면 도구 이름을 맞히는 수준을 넘어, 상황에 알맞은 값을 전달하고 여러 대화 단계에서 결과를 일관되게 이어가야 한다. 그러나 평가 사례를 사람이 일일이 만들면 전문지식과 시간이 많이 들고, API 변경을 벤치마크가 따라가기 어렵다.

Agent Seer의 접근이 재현된다면 MCP 서버 개발자는 명세 자체에서 평가 자료를 생성해 도구 변경에 맞춰 테스트를 갱신할 수 있다. 국내에서도 MCP 기반 사내 자동화나 에이전트 서비스를 구축할 때 초기 평가 데이터 제작 부담을 줄이는 방법으로 참고할 만하다. 특히 도구 선택 여부뿐 아니라 인수 값의 정확성을 별도로 측정해야 한다는 결과는 평가 지표를 설계할 때 중요한 시사점을 준다.

## 확인 범위

논문의 공개 초록과 arXiv 서지정보를 바탕으로 연구 목적, 방법의 구성, MCP 명세 7개를 사용한 평가 범위와 연구진이 보고한 주요 결론을 확인했다. 구체적인 데이터셋 구성, 도메인별 수치, 통계 분석 방법과 외부 환경에서의 재현성은 이 기사에서 별도로 검증하지 않았다. 따라서 성능과 확장성에 관한 내용은 독립적으로 입증된 일반적 사실이 아니라 논문 저자들이 보고한 연구 결과로 해석해야 한다.
