## 무엇이 있었나

AWS 내부 팀이 Amazon Bedrock 기반의 대시보드 콘텐츠 검증 시스템을 구축한 사례를 공개했다. 서버와 API, 데이터 파이프라인이 정상이어도 화면의 차트가 비거나 잘못된 수치를 표시하는 문제를 찾아내기 위한 시스템이다.

이 시스템은 시각적 이상과 수치 불일치를 병렬로 검사한다. 시각 검증에서는 대시보드 화면을 캡처한 뒤 Amazon Bedrock에서 제공되는 Anthropic Claude 모델로 빈 영역, 오류 상태, 누락된 시각 요소 등을 판별한다. 수치 검증에서는 대규모 언어 모델이 화면에서 지표와 단위를 읽어내고, 단위 변환·반올림·허용 오차를 포함한 최종 비교는 결정론적 코드가 수행한다.

AWS에 따르면 시각 검증 기능은 30일 동안 15만3천 건을 자동 검사해 802건의 콘텐츠 오류를 발견했다. 사용자 신고가 함께 접수된 사례는 발견 건수의 1% 미만이었다. 시간당 검사를 통해 탐지에 최장 72시간이 걸리던 상황도 1시간 이내로 줄였다. 별도로 운영된 수치 검증 기능은 6개월 넘게 매주 50~70개 데이터 지점을 검사했다.

시스템은 EventBridge, Lambda, Redshift, S3, CloudFront, Rekognition, CloudWatch 등 AWS 관리형 서비스를 조합한 5단계 구조로 설계됐다. 저장 전 화면의 문자와 숫자를 가리고, 확신이 낮은 판정은 자동 경고 대신 사람의 검토로 보낸다. 확인된 시각 오류는 담당자에게 Slack으로 알리며, 지속되는 문제는 티켓으로 전환한다.

## 왜 중요한가

기존 인프라 모니터링은 서비스의 가동 여부나 API 응답 상태를 확인하지만, 사용자가 실제로 보는 화면의 의미까지 보장하지는 못한다. 이번 사례는 BI 운영에서 화면 계층을 별도로 검증해야 한다는 점을 수치로 보여준다. 특히 대시보드 데이터를 바탕으로 AI가 경영 보고나 설명문을 생성한다면, 화면에 표시된 오류가 그대로 의사결정 정보로 번질 수 있다.

또한 생성형 AI의 역할을 의미 판단에 한정하고 정확한 계산과 판정은 일반 코드에 맡긴 설계가 주목된다. AWS 팀은 비교 작업을 결정론적 코드로 바꿔 판정의 일관성을 확보했으며, 이후 모델 개선으로 값 추출 단계의 재현율이 0.88에서 0.95로 높아졌다고 설명했다. 국내 기업도 AI 기반 품질 검사를 도입할 때 모델 성능만 보기보다 오탐 관리, 개인정보 차단, 사람의 검토 절차, 계산 로직의 분리까지 함께 설계할 필요가 있다.

## 확인 범위

이 기사는 AWS가 공개한 기술 사례와 자체 운영 결과를 토대로 작성했다. 제시된 검사 건수, 오류율, 탐지 시간 및 재현율은 AWS 내부 환경에서 측정된 수치이며, 외부 기관이 독립적으로 검증한 결과는 본문에서 확인되지 않는다. 비용, 모델별 세부 설정, 전체 오탐률과 다른 조직에서의 재현 가능성도 공개된 내용만으로는 판단하기 어렵다.
