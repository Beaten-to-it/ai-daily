## 무엇이 있었나

기업용 데이터베이스 환경에서 자연어를 SQL로 변환하는 모델의 성능을 평가하기 위한 ‘ESQ-Bench’가 공개됐다. 연구진은 기존 Spider·BIRD 같은 벤치마크가 단순화된 학술용 스키마와 오픈소스 SQL 방언에 치우쳐 실제 기업 환경의 복잡성을 충분히 반영하지 못한다고 지적했다.

ESQ-Bench는 Oracle을 중심으로 설계됐으며, 복잡도가 다른 3개 등급에 걸쳐 모델의 SQL 생성 능력과 실행 결과의 의미 불일치를 평가한다. 데이터셋에는 465개 테이블과 16만4,682개 행으로 구성된 6개 스키마, 검증을 거친 자연어 질문·SQL 쌍 550개가 포함됐다. 동일한 초기 데이터는 Oracle뿐 아니라 PostgreSQL, MySQL, SQL Server에도 구축됐다.

논문에 따르면 스키마 정보를 제공한 GPT-4o의 실행 일치율은 복잡도 등급이 올라갈수록 79.8%, 60.3%, 57.2%로 낮아졌다. Claude Sonnet 4.6은 같은 조건에서 87.4%, 74.9%, 68.7%를 기록했다. 로컬 Llama 3.2의 전체 실행 일치율은 550건 중 73건인 13.3%였다.

연구진은 실행 결과가 맞은 것으로 분류된 사례에서도 운영 기준상 ‘조용한 의미 불일치’가 73~99%에 이르렀다고 보고했다. 쿼리가 실행되고 일부 결과가 맞아 보이더라도 의도와 다른 의미를 담을 수 있다는 뜻이다.

## 왜 중요한가

NL2SQL은 비개발자가 자연어로 사내 데이터를 조회하도록 돕는 기술이지만, 기업용 시스템에서는 단순 실행 성공만으로 정확성을 보장하기 어렵다. 복잡한 테이블 관계와 제품별 SQL 문법, 업무 규칙이 결합되면 오류 없이 실행된 쿼리도 잘못된 의사결정으로 이어질 수 있다.

국내 기업도 Oracle을 비롯한 여러 관계형 데이터베이스를 함께 사용하는 경우가 많다. 이번 벤치마크는 모델 도입 평가에서 실행 성공률뿐 아니라 결과의 의미적 정확성, 데이터베이스 방언 간 일반화 능력, 복잡도에 따른 성능 저하를 함께 살펴야 한다는 근거를 제시한다.
