## 무엇이 있었나

Warp가 터미널에 내장했던 다중 모델 코딩 에이전트를 독립형 명령줄 도구인 ‘Warp Agent CLI’로 제공한다. 이에 따라 Ghostty와 iTerm2, VS Code 통합 터미널, Windows·macOS 기본 터미널 등에서도 Warp의 에이전트 기능을 사용할 수 있다.

이 도구는 에이전트와 셸 사이의 PTY 연결을 관리하는 멀티플렉싱 구조를 채택했다. 대화를 유지한 채 작업 디렉터리나 SSH 세션을 옮길 수 있고, Python·SQLite 같은 REPL과 vim, gdb, htop 등 대화형 터미널 프로그램도 에이전트가 다룰 수 있다는 설명이다.

작업 복잡도에 따른 모델 자동 선택과 사용자 정의 모델 라우팅도 지원한다. OpenAI 호환 엔드포인트를 연결할 수 있으며, 복잡한 작업은 여러 하위 에이전트나 Claude Code·Codex 같은 별도 실행 도구에 분배할 수 있다. 로컬에서 시작한 작업을 Warp의 클라우드 에이전트로 넘겨 웹에서 추적하고 조정하는 기능도 제시됐다.

## 왜 중요한가

코딩 에이전트가 특정 터미널 앱에 묶이지 않고 개발자가 이미 쓰는 환경으로 들어온다는 점이 핵심이다. 여러 저장소와 원격 서버를 오가는 개발자에게는 대화 맥락을 유지하면서 셸 상태와 대화형 프로그램까지 제어하는 기능이 작업 전환 비용을 줄일 가능성이 있다.

국내 개발팀 입장에서는 Windows와 macOS 터미널을 함께 지원하고, 자체 API 키나 OpenAI 호환 추론 환경을 연결할 수 있다는 점도 의미가 있다. 다만 셸 자동 판별의 정확도, 원격·클라우드 작업의 보안 구조, 비용 효율성은 실제 도입 전에 별도로 검토할 사안이다.

## 확인 범위

이 기사는 GeekNews에 게시된 Warp Agent CLI 소개 내용을 바탕으로 작성했다. 독립형 CLI의 지원 환경과 PTY 기반 세션 관리, 모델 라우팅, 다중 에이전트 조정, 클라우드 인계 기능이 소개된 사실을 확인했다.

GeekNews 페이지에 함께 실린 이용자 반응에는 Warp의 비대화와 성능, 입력 자동 판별 오류 등에 관한 비판도 포함돼 있으나, 이는 개별 사용자의 경험과 의견이므로 제품 전반의 검증된 성능으로 일반화하지 않았다. 실제 보안 설계와 기능별 안정성, 지원 모델 및 요금 조건은 이 자료만으로 독립 검증하지 않았다.
