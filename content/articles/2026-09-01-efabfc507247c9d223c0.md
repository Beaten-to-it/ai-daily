## 무엇이 있었나

AWS가 Amazon Bedrock Managed Knowledge Base를 활용해 기업 데이터 기반의 멀티테넌트 에이전틱 문서 채팅 서비스를 구축하는 참조 아키텍처를 공개했다. 사용자가 문서를 올리면 시스템이 이를 비동기로 분석·임베딩·색인하고, 준비된 자료를 대상으로 복합 질문을 여러 하위 질의로 나눠 검색한 뒤 출처가 표시된 답변을 생성하는 구조다.

이 아키텍처는 Amazon Cognito로 확인한 사용자 신원을 서버에서 추출해 각 문서의 `user_id` 메타데이터로 저장한다. 검색할 때도 같은 값을 명시적 필터로 적용해 이용자별 자료를 격리한다. 클라이언트가 전달한 사용자 식별값이나 질문에서 추론한 필터는 접근 통제 수단으로 신뢰하지 않는다는 원칙이다.

업로드와 색인 작업은 Amazon API Gateway, AWS Lambda, Amazon SQS로 분리한다. DynamoDB는 문서 처리 상태를 추적하고, S3는 인라인 한도를 넘는 파일의 임시 저장 등에 쓰인다. Managed Knowledge Base는 문서 분석과 임베딩, 색인, 순위 결정, 다단계 검색 및 응답 생성을 담당한다.

## 왜 중요한가

기업용 생성형 AI 서비스에서는 답변 품질뿐 아니라 고객이나 사용자 사이의 데이터 분리가 핵심이다. 특히 에이전트가 한 질문을 여러 검색 단계로 나눌 경우 모든 단계에 동일한 권한 필터가 적용돼야 한다. AWS가 제시한 방식은 인증된 신원에서 필터를 서버 측에서 만들고, 각 검색 단계에 이를 강제하는 설계 원칙을 구체화했다는 점에서 의미가 있다.

국내 기업이 사내 계약서, 보고서, 제품 설명서 등을 활용하는 문서 질의 서비스를 개발할 때도 참고할 수 있다. 공용 지식 기반을 사용하면 이용자마다 별도 검색 인프라를 만드는 부담을 줄일 수 있지만, 애플리케이션은 인증과 사용자별 필터, 대화 기록의 분리, 실패한 색인 작업의 재처리를 직접 책임져야 한다.

## 확인 범위

확인된 내용은 AWS가 공개한 참조 아키텍처와 운영 권고다. 여기에는 직접 문서 수집, 비동기 색인 상태 관리, 인증된 사용자별 메타데이터 필터, 에이전틱 다단계 검색, 대화 기록의 별도 저장 방식이 포함된다.

AWS가 제시한 색인 시간과 처리량 사례는 자체 시험 환경에서 관찰한 참고치이며 서비스 수준 보장이 아니다. 실제 성능과 비용은 문서 크기·형식, 리전, 부하, 선택한 모델과 구성에 따라 달라질 수 있다. 또한 이 글은 AWS가 설계한 예시를 설명한 것으로, 독립적인 성능 평가나 실제 기업 환경의 보안 검증 결과까지 확인한 것은 아니다.
