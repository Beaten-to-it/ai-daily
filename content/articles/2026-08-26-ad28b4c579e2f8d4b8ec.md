## 무엇이 있었나

NVIDIA가 CUDA 13.3과 함께 CUDA Python 1.0을 공개했다. 파이썬에서 CUDA 플랫폼을 이용할 수 있도록 NVIDIA가 공식 유지·관리하는 라이브러리와 도구를 하나의 공통 기반으로 정비한 것이 핵심이다.

주요 구성 요소는 파이썬 방식으로 CUDA 런타임을 다루는 `cuda.core 1.0.0`, CCCL 병렬 알고리즘을 제공하는 `cuda.compute 1.0.0`, CUDA C API와 일대일로 대응하는 `cuda.bindings 13.3.0`, 설치된 CUDA 구성 요소를 찾는 `cuda-pathfinder`, 수학 라이브러리 패키지 `nvmath-python 1.0`이다. 각 구성 요소는 하나의 통합 버전이 아니라 독립적인 출시 주기를 따른다.

이번 1.0 이정표에는 시맨틱 버저닝 정책도 도입됐다. 공개 API의 호환성을 깨는 변경은 주 버전에서 적용하고, 기능 추가와 버그 수정은 각각 부 버전과 패치 버전으로 구분한다. API를 없애기 전에는 대체 경로와 함께 사용 중단을 예고한다.

`cuda.core`는 장치와 스트림, 메모리 버퍼 같은 CUDA 자원을 공통 파이썬 객체로 제공한다. NVIDIA는 이를 바탕으로 서로 다른 GPU 라이브러리가 같은 자원과 실행 흐름을 공유하기 쉬워진다고 설명했다. GPU 연산 자원 분할을 위한 그린 컨텍스트, CUDA 프로세스 상태 체크포인트, 프로세스 간 GPU 메모리 공유 기능도 제공한다.

## 왜 중요한가

파이썬 개발자는 기존에도 PyTorch와 CuPy, RAPIDS 같은 상위 라이브러리로 GPU를 활용할 수 있었지만, 해당 라이브러리가 노출하지 않는 CUDA 기능이 필요하면 별도의 C++ 확장이나 자체 바인딩을 마련해야 하는 경우가 있었다. CUDA Python 1.0은 이 간극을 줄이고 파이썬을 CUDA 플랫폼의 공식 지원 경로로 자리매김하려는 발표다.

국내 AI·데이터 분석·고성능 컴퓨팅 개발자에게는 API 안정성과 라이브러리 간 상호운용성 개선이 실질적인 의미를 갖는다. GPU 버퍼와 스트림을 공통 기반에서 다룰 수 있다면 불필요한 데이터 복사나 자체 연동 계층을 줄일 여지가 있다. 알고리즘 호출은 `cuda.compute`, 사용자 정의 커널은 Numba 계열 도구, 저수준 제어는 `cuda.core`와 `cuda.bindings`처럼 필요한 단계에 맞춰 접근할 수도 있다.

다만 모든 CUDA Python 관련 도구가 1.0 안정성 보장을 받는 것은 아니다. Numba CUDA MLIR을 비롯한 일부 최신 커널 작성 도구는 아직 실험 단계이며 같은 시맨틱 버저닝 약속의 적용 대상이 아니다.

## 확인 범위

NVIDIA Developer가 공개한 기술 블로그에서 CUDA Python 1.0의 구성 요소, 버전 정책, 주요 기능과 설치 방향을 확인했다. 라이브러리 간 연동 간소화와 성능·의존성 개선에 관한 내용은 NVIDIA의 설명이며, 독립적인 성능 시험이나 실제 프로젝트별 호환성 검증 결과는 이번 확인 범위에 포함되지 않았다. 운영 환경에 적용할 때는 개별 패키지의 지원 상태와 드라이버 요건을 별도로 확인할 필요가 있다.
