## 무엇이 있었나

GitHub가 개방형 표준인 ‘에이전트 플러그인 1.0’을 VS Code, Copilot CLI, GitHub Copilot SDK와 Copilot 앱에서 정식 지원한다고 밝혔다. 모든 Copilot 요금제에서 이용할 수 있다.

이 표준은 에이전트 스킬과 MCP 서버 설정을 하나의 설치형 패키지로 묶는다. 호환 클라이언트마다 별도의 매니페스트와 디렉터리 구조를 관리하던 부담을 줄이고, 같은 플러그인을 여러 도구에서 활용하는 것이 목표다. 기존 방식으로 제작된 GitHub Copilot 플러그인도 그대로 지원돼 반드시 이전할 필요는 없다.

플러그인 개발자는 `plugin.json`에 스키마를 지정하고, 스킬과 MCP 설정을 각각 정해진 위치에 배치할 수 있다. Copilot 전용 에이전트·명령·규칙·훅 등은 별도 네임스페이스 디렉터리에 두어 다른 클라이언트와의 호환성을 유지한다.

기업 고객은 기존 관리형 설정을 통해 플러그인의 자동 설치와 차단, 허용 마켓플레이스 추가, 관리 대상 마켓플레이스 외 설치 제한 등을 적용할 수 있다. 플러그인에 포함된 MCP 서버는 별도의 MCP 허용 목록과 함께 통제할 수 있다.

## 왜 중요한가

여러 AI 코딩 도구를 함께 사용하는 국내 개발팀과 플러그인 제작자는 동일한 기능을 클라이언트별 형식으로 중복 포장하는 작업을 줄일 수 있다. 배포 절차나 사내 개발 규칙 같은 스킬을 MCP 도구 연동과 함께 관리할 수 있어, 에이전트 기능의 배포와 재사용도 단순해질 가능성이 있다.

기업 환경에서는 도구가 달라져도 기존 Copilot 관리 정책을 활용할 수 있다는 점이 중요하다. 다만 플러그인이 외부 명령이나 MCP 서버 연결을 포함할 수 있으므로, 도입 전에는 플러그인 출처와 서버 접근 범위를 함께 검토해야 한다.

## 확인 범위

GitHub가 2026년 8월 12일 공개한 변경 기록에서 지원 대상, 패키지 구조, 기존 플러그인 호환성 및 기업 관리 기능을 확인했다. 실제 클라이언트별 동작과 타사 에이전트에서의 호환성, 운영 환경의 보안 효과는 별도로 시험하지 않았다.
