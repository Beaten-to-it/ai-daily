## 무엇이 있었나

C 기반 추론 엔진 WASTE(Weight-Aware Streaming Tensor Engine)가 2.78조 매개변수 규모의 Kimi K3 오픈 가중치 모델을 소비자용 노트북에서 실행한 결과를 공개했다. 모델을 축소하지 않고 약 982GiB 컨테이너로 변환한 뒤, 자주 쓰는 부분만 메모리에 상주시키고 토큰마다 활성화되는 전문가 가중치를 NVMe에서 불러오는 방식이다.

공개된 측정에 따르면 Kimi K3는 4K 컨텍스트에서 최소 29.05GB RAM으로 열 수 있다. 다만 실제 권장 환경은 64GB MacBook Pro와 내부 SSD이며, 약 46GB의 메모리 예산에서 초당 0.45~0.62토큰의 생성 속도를 기록했다. 토큰 생성에 필요한 디스크 읽기와 연산을 겹치고 다음 계층에서 사용할 전문가를 미리 불러오는 방식으로 처리량과 캐시 적중률을 개선했다.

WASTE는 추론 과정에서 BLAS, CUDA, ONNX, Python을 요구하지 않으며 C11과 pthreads를 기반으로 동작한다. OpenAI 호환 HTTP 서버와 이미지 입력도 지원한다. 라이선스는 Apache 2.0이다.

## 왜 중요한가

이번 사례는 1TB에 가까운 초대형 희소 모델도 모든 가중치를 RAM에 올리지 않고 로컬에서 실행할 수 있음을 보여준다. 인터넷 연결이나 외부 데이터 전송 없이 모델을 구동할 수 있어 데이터 통제와 오프라인 활용 가능성을 탐색하는 실험으로 의미가 있다.

다만 초당 약 0.5토큰은 일반적인 대화형 서비스에 쓰기에는 매우 느리다. 내부 NVMe와 약 1TB의 변환 모델 저장공간이 필요하고, 원본 변환 과정에는 최대 1.42TB의 추가 공간도 요구된다. 메모리를 지나치게 많이 배정하면 운영체제 페이징 때문에 오히려 속도가 크게 떨어질 수 있다는 점도 확인됐다. 당장의 실용 제품이라기보다 초대형 MoE 모델을 제한된 하드웨어에서 구동하는 방법과 한계를 제시한 기술 실험에 가깝다.

한국 사용자가 Windows 환경에서 시험할 때는 특히 주의가 필요하다. Windows x86-64 빌드는 합성 데이터와 기본 실행 경로까지만 검증됐으며, 실제 Kimi K3 컨테이너를 이용한 대규모 실행과 Windows의 페이지 캐시 우회 동작은 아직 확인되지 않았다. MSVC와 Windows ARM64도 지원 대상이 아니다.

## 확인 범위

수치와 기능 설명은 GeekNews가 정리한 프로젝트 공개 자료를 기준으로 확인했다. 성능 측정은 주로 64GB MacBook Pro M5 Pro와 내부 SSD에서 이뤄졌으므로 다른 CPU, SSD, 운영체제에서도 같은 결과가 나온다고 단정할 수 없다.

29.05GB는 모델을 열기 위한 최소 RAM 수치이며 원활한 사용을 보장하는 권장 사양이 아니다. 초당 0.45~0.62토큰이라는 결과 역시 특정 메모리 예산과 저장장치 조건에서 측정된 범위다. 장기간 실행에 따른 SSD 내구성, 전력 비용, 실제 업무 품질에 관한 댓글의 평가는 검증된 프로젝트 결과와 구분해 기사 근거에서 제외했다.
