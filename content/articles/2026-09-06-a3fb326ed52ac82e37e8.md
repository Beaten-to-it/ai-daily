## 무엇이 있었나

인튜이트가 Amazon Bedrock을 활용해 구축한 재해복구 지원 도구 ‘EWOK Agent’의 운영 방식과 설계를 AWS 블로그에 공개했다. 게시글에 따르면 인튜이트 내부 팀들은 지난 8개월간 이 에이전트로 장애 발생 시 서비스를 다른 리전으로 전환하는 페일오버를 수행해 왔다.

엔지니어가 자연어로 복구를 요청하면 에이전트는 대상 서비스와 복구 절차를 찾고, 실행 준비 상태와 변경 제한 정책을 확인한다. 이후 기존 내부 복구 시스템인 EWOK을 통해 실행을 요청하고 진행 상황을 전달한다. 엔지니어는 중요한 판단과 승인에 참여한다.

설계의 핵심은 모델의 판단과 실제 인프라 조작을 분리한 것이다. 모델은 수행할 작업과 입력값을 선택하고, 인증과 API 호출은 별도의 실행 코드가 담당한다. 복구 지식은 입출력 형식과 절차를 명시한 ‘스킬’로 관리한다. 변경 동결 기간의 예외 처리나 파괴적·비가역적 단계에는 명시적인 사람의 승인을 요구한다고 설명했다.

## 왜 중요한가

여러 리전에 서비스를 운영하는 국내 기업에도 장애 대응은 인프라를 전환하는 기술만의 문제가 아니다. 담당자가 적절한 복구 절차를 찾고, 실행 조건과 예외 승인 요건을 빠짐없이 확인해야 한다. 이번 사례는 숙련자의 기억에 의존하던 절차를 구조화해 AI가 조율하도록 만드는 접근을 보여준다.

운영 시스템에 AI를 연결할 때 참고할 지점은 실행 권한과 검증의 배치다. 인튜이트는 모델에 자격증명을 맡기지 않고, 실행 계층에서 허용된 서비스와 리전을 검증하도록 구성했다고 밝혔다. 반복 횟수 제한, 중복 요청 제거, 연속 호출 차단과 감사 기록도 함께 적용했다. 이는 자연어 인터페이스를 추가하면서 기존 승인·통제 절차를 유지하려는 설계로 볼 수 있다.

## 확인 범위

확인 근거는 AWS와 인튜이트 관계자가 작성한 구축 사례다. 운영 기간과 보안 통제에 관한 설명은 해당 게시글의 보고이며, 독립적인 성능 시험이나 보안 검증 결과는 제시되지 않았다.

게시글의 ‘수시간에서 약 20분으로 복구 시간 단축’은 지원 대상 워크로드에서 기존 EWOK이 거둔 성과다. AI 에이전트 도입에 따른 추가 시간 단축이나 성공률 개선을 입증하는 수치로 해석할 수 없다. 에이전트의 정량적 효과와 실제 운영 비용은 공개된 자료만으로 판단하기 어렵다.

공개 내용은 아키텍처와 설계 패턴 중심이다. 코드 예시는 설명용 발췌이며, 완성된 실행 코드나 배포용 패키지는 제공되지 않는다. EWOK도 인튜이트 내부 시스템이므로 다른 기업이 적용하려면 자체 복구 API와 승인 체계에 맞춘 구현이 필요하다.
