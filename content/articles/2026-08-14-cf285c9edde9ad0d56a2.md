## 무엇이 있었나

다양한 형식의 문서를 텍스트와 표, 메타데이터, 구조화 데이터로 변환하는 오픈소스 프레임워크 ‘xberg’가 소개됐다. PDF와 이미지, 스프레드시트, 오디오·비디오, 웹 URL, 압축 파일, 소스 트리 등을 하나의 코어에서 처리하며, 101개 파일 형식과 15개 언어 바인딩, 6개 출력 형식을 지원한다고 개발 측은 설명한다. 한글 HWP·HWPX 문서에서도 텍스트를 추출할 수 있다.

주요 기능에는 여러 OCR 백엔드와 비전 언어 모델을 조합하는 폴백 체인, 문서 레이아웃·표 구조 인식, Whisper ONNX 기반 음성 전사, 압축 파일 내부의 중첩 문서 추출이 포함된다. 웹 문서 수집과 링크 크롤링도 지원한다.

소스 코드 분석에는 tree-sitter를 활용해 371개 프로그래밍 언어의 함수와 클래스, 임포트, 심볼 등을 추출한다. 이 밖에도 RAG용 청킹과 임베딩·검색, 개체명 및 키워드 추출, 번역, 개인정보 마스킹, 스키마 기반 JSON 추출 기능을 제공한다. 라이브러리와 CLI, REST API, MCP 서버 형태로 사용할 수 있으며 Docker와 Helm 배포도 지원한다. 라이선스는 MIT다.

## 왜 중요한가

문서 기반 AI 서비스를 구축할 때는 파일 형식 감지부터 OCR, 표 복원, 음성 전사, 웹 수집까지 서로 다른 도구를 연결해야 하는 경우가 많다. xberg가 제시한 통합 방식은 이러한 파이프라인의 구성과 운영 부담을 줄일 가능성이 있다.

특히 HWP·HWPX 지원은 국내 공공기관과 기업이 보유한 한글 문서를 검색·요약하거나 RAG 데이터로 전환하려는 개발자에게 의미가 있다. 로컬 모델과 호스팅 모델을 함께 선택할 수 있다는 점도 보안 요구나 비용 조건에 맞춰 배포 방식을 조정하는 데 유용할 수 있다.

## 확인 범위

이 기사는 GeekNews에 게시된 소개 내용을 바탕으로 작성했다. 지원 형식과 언어 수, 개별 기능 및 배포 방식은 해당 소개에서 확인했으나, 실제 문서별 추출 정확도와 처리 속도, OCR 품질, 운영 환경에서의 안정성은 독립적으로 검증하지 않았다. 도입 전에는 사용하려는 파일 형식과 언어, 표·레이아웃 복잡도에 맞춘 별도 테스트가 필요하다.
