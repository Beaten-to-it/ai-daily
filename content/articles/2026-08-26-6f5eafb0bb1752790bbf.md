## 무엇이 있었나

Vercel이 AI 에이전트가 만든 JavaScript와 TypeScript 코드를 애플리케이션 내부에서 격리 실행하는 `Run SDK`를 공개했다. 생성 코드는 워커 스레드 안의 새로운 QuickJS 컨텍스트에서 실행되며, Node.js 환경이나 네트워크에 직접 접근할 수 없다.

애플리케이션은 필요한 기능만 `hostFunctions`로 제공한다. 이에 따라 데이터베이스 접속 정보나 서비스 자격증명을 격리 환경에 넘기지 않고도 에이전트가 허용된 작업을 호출할 수 있다. 민감한 작업에서는 실행을 중단하고 인증이나 사람의 승인을 기다린 뒤 재개할 수 있다. 앞서 완료된 호스트 함수 호출 결과는 기록되므로 재개 과정에서 같은 작업을 반복하지 않는다.

실행 시간과 메모리, 경계를 오가는 데이터에도 제한을 설정할 수 있다. 각 호출에는 별도의 QuickJS 컨텍스트가 배정되며 동적 코드 평가가 비활성화되고 기본 프로토타입도 강화된다. Run SDK는 현재 Vercel AI SDK의 코드 모드 실행 계층에도 사용된다.

지원 환경은 Node.js 22.13 이상과 Bun이다. 운영체제 접근, 패키지 설치 또는 프로세스 수준 격리가 필요한 작업에는 별도 제품인 Vercel Sandbox가 권장된다.

## 왜 중요한가

에이전트가 여러 도구를 연달아 호출하고 결과를 가공하는 방식이 확산되면서, 생성 코드를 일반적인 `eval`로 실행할 때 발생하는 권한 노출이 중요한 위험으로 떠올랐다. Run SDK는 에이전트가 접근할 수 있는 기능을 업무 단위의 좁은 인터페이스로 제한해 애플리케이션의 내부 서비스와 비밀정보를 분리할 수 있게 한다.

한국 기업이 고객지원, 사내 업무 자동화, 결제·문서 처리 같은 에이전트를 구축할 때도 의미가 있다. 조회와 환불, 초안 작성과 게시처럼 위험 수준이 다른 작업 사이에 승인 절차를 넣고, 대기 중인 워커를 계속 유지하지 않아도 실행을 이어갈 수 있기 때문이다. 다만 실제 권한 검사는 신뢰 영역에 있는 호스트 함수가 담당하므로 SDK 도입만으로 접근통제 문제가 자동 해결되는 것은 아니다.

## 확인 범위

Vercel이 공개한 공식 발표에서 Run SDK의 실행 구조, 호스트 함수 방식, 중단·재개 기능, 자원 제한, 지원 런타임과 AI SDK 적용 사실을 확인했다. 보안 특성과 성능은 Vercel이 설명한 설계 범위에 근거하며, 독립적인 보안 감사 결과나 실제 운영 환경의 성능 수치는 해당 자료에서 확인되지 않았다.
