## 무엇이 있었나

허깅페이스의 Speech-to-Speech 프로젝트를 활용해 음성 활동 감지(VAD), 음성 인식(STT), 언어 모델의 답변 생성, 음성 합성(TTS)으로 이어지는 대화 파이프라인을 로컬 환경에 구축할 수 있다. 각 단계는 별도 스레드에서 실행되고 큐로 연결되는 스트리밍 구조를 채택해 응답 지연을 줄였다.

이 파이프라인은 OpenAI Realtime 호환 WebSocket API를 제공한다. 언어 모델 연결에도 OpenAI 호환 API를 사용해 호스티드 서비스뿐 아니라 HF Inference Providers, vLLM, llama.cpp 기반 자체 서버를 선택할 수 있다. 기본 구성에는 Parakeet TDT와 Qwen3-TTS가 포함되며, STT와 TTS 모델은 Whisper, Faster Whisper, Kokoro, Pocket TTS 등으로 교체할 수 있다.

브라우저·앱과 연결하는 실시간 모드와 컴퓨터의 마이크·스피커를 직접 사용하는 로컬 모드, PCM WebSocket 및 TCP Socket 방식이 제공된다. 음성 구간을 멀티모달 모델에 직접 전달하거나 별도 LLM 프록시를 통해 요약과 제목 생성 같은 부가 작업을 처리하는 구성도 가능하다. 프로젝트의 라이선스는 Apache-2.0이다.

## 왜 중요한가

음성 에이전트를 로컬에서 운영하면 모델과 하드웨어를 용도에 맞게 조합하고, 음성 데이터를 외부 서비스에 맡기지 않는 구성을 설계할 수 있다. 특히 OpenAI 호환 인터페이스를 지원한다는 점은 기존 클라이언트와 SDK를 활용하면서 실행 환경이나 모델 공급자를 바꿀 수 있다는 의미가 있다.

한국 개발자에게는 한국어 지원 여부와 품질을 구성 모델별로 따져보는 일이 중요하다. 전체 파이프라인이 특정 언어를 일괄 지원하는 것이 아니라 STT와 TTS 모델마다 지원 언어와 성능이 달라지기 때문이다. 실제 도입 전에는 한국어 인식률, 합성 음성 품질, 지연 시간, 필요한 GPU 자원을 별도로 검증해야 한다.

## 확인 범위

이 기사는 GeekNews에 정리된 프로젝트 소개를 근거로 작성했다. 파이프라인의 구성 방식, 지원 인터페이스와 모델 교체 가능성, 실행 모드 및 라이선스를 확인 범위에 포함했다. 다만 개별 모델의 한국어 성능, 하드웨어별 지연 시간과 자원 사용량, 대규모 운영 환경에서의 안정성은 제시된 자료만으로 확인되지 않았다.

자료에는 수천 대의 Reachy Mini 로봇에서 대화 백엔드로 운영되고 있다는 설명도 포함돼 있으나, 구체적인 배포 규모와 운영 지표는 별도 검증 자료가 제시되지 않았다.
