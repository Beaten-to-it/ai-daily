## 무엇이 있었나

AWS가 Amazon OpenSearch Service에서 MCP Apps를 지원한다고 발표했다. AI 에이전트가 로그와 추적, 지표 등을 조회하면 텍스트 요약과 함께 추적 워터폴, 서비스 토폴로지, 로그 패턴 같은 대화형 시각화가 AI 도구의 대화창에 표시되는 기능이다.

구성은 사용자 컴퓨터에서 실행되는 로컬 MCP 서버와 에이전트형 개발 도구, OpenSearch UI 애플리케이션을 연결하는 방식이다. 로컬 서버가 AWS 자격 증명으로 요청을 인증해 OpenSearch UI에 전달하면, 실제 데이터 조회 결과를 바탕으로 텍스트와 시각화가 함께 반환된다.

AWS는 OpenSearch 도메인과 서버리스 컬렉션, Amazon Managed Service for Prometheus 등을 데이터 소스로 제시했다. 경보 분류부터 로그·분산 추적·지표 조사, 서비스 맵, AI 에이전트 추적, 클러스터 상태 점검까지 관측성 업무의 여러 단계에 대응하는 도구도 소개했다.

## 왜 중요한가

핵심은 AI가 제시한 장애 원인 가설을 확인하려고 별도 관측성 화면을 열고 쿼리를 다시 실행하는 과정을 줄이는 데 있다. 운영자는 에이전트의 설명과 근거가 되는 시각화 결과를 같은 대화 흐름에서 비교할 수 있어, 장애 조사 중 발생하는 화면 전환과 맥락 손실을 줄일 수 있다.

한국 기업이 사내 개발 환경이나 로컬 에이전트를 활용해 AWS 시스템을 운영한다면, 데이터와 접근 정책을 기존 AWS 계정 안에서 관리하면서 관측성 절차를 AI 작업 흐름에 연결할 수 있다는 점도 의미가 있다. 다만 실제 장애 대응 시간 단축과 운영 효율은 데이터 구성, 권한 정책, 사용 도구의 MCP Apps 호환성에 따라 달라질 수 있다.

## 확인 범위

이번 내용은 AWS가 공개한 기술 소개와 설정 절차를 기준으로 확인했다. AWS는 Node.js 22 이상, OpenSearch UI의 Observability 워크스페이스, 지원 데이터 소스, `es:ESHttpGet` 및 `es:ESHttpPost` 권한 등을 주요 준비 사항으로 안내했다.

시각화가 실제 쿼리 결과를 기반으로 생성된다는 설명은 확인했지만, 성능 개선 폭이나 장애 해결 시간 단축 효과를 입증하는 독립적인 수치와 외부 검증 사례는 제시되지 않았다. 개별 IDE의 지원 범위와 설정 메뉴는 제품 업데이트에 따라 달라질 수 있다.
