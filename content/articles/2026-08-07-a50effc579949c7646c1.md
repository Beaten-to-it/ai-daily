## 무엇이 있었나

AWS가 Claude Code의 Amazon Bedrock 추론을 특정 AWS 리전 안에서만 처리하도록 제한하는 구성 방법을 공개했다. 핵심은 대상 리전에 따라 두 가지 경로를 선택하고, IAM의 `aws:RequestedRegion` 조건으로 다른 리전에서의 호출을 차단하는 것이다.

Mantle이 리전 내 추론을 지원하는 아일랜드·스톡홀름·도쿄·멜버른과 미국 내 일부 리전에서는 `AWS_REGION`을 지정해 단일 리전 라우팅을 적용할 수 있다. 런던 리전은 Mantle의 리전 내 전용 경로가 없어 기존 Bedrock 호출 방식과 애플리케이션 추론 프로파일을 함께 사용해야 한다. AWS가 소개한 런던 구성은 Claude Opus 4.6과 Sonnet 4.6을 대상으로 한다.

AWS는 설정 화면만 확인하는 데 그치지 않고 CloudTrail 기록으로 실제 처리 리전을 검증해야 한다고 설명했다. 기존 Bedrock 경로는 `InvokeModel`, Mantle 경로는 `CreateInference` 이벤트를 확인하며, 모든 호출의 `awsRegion`이 지정 리전과 일치하고 다른 리전에서는 관련 기록이 없어야 한다.

## 왜 중요한가

데이터의 저장 위치뿐 아니라 AI 프롬프트와 응답, 중간 처리 과정까지 특정 지역에 머물러야 하는 조직에는 실행 위치를 기술적으로 제한하고 감사 기록으로 입증하는 방법이 필요하다. 이번 구성은 별도의 중계 인프라를 구축하지 않고도 Claude Code 사용 경로에 리전 제한과 추적 가능성을 적용하는 방안을 제시한다.

한국 기업도 해외 법인이나 규제 산업의 개발 환경을 운영할 때 참고할 수 있다. 다만 단일 국가나 도시 단위의 처리가 필요하지 않고 EU 같은 지리적 범위만 충족하면, AWS가 기본 선택으로 권고한 교차 리전 추론이 처리 용량과 모델 접근성 측면에서 더 적합할 수 있다.

## 확인 범위

AWS ML 블로그에 공개된 구성 방식, 지원 리전과 모델, IAM 제한 조건, CloudTrail 검증 절차를 확인했다. 지원 리전과 모델 목록은 게시 시점 기준이며 AWS도 배포 전에 각 모델 카드에서 최신 가용성과 정확한 모델 ID를 다시 확인하라고 안내한다. 이 글은 해당 구성이 개별 조직에 적용되는 국내외 법률이나 규제 요건을 충족한다고 판단하지 않는다.
