## 무엇이 있었나

GitHub가 기업 관리형 설정에서 GitHub Copilot 클라이언트가 실행할 수 있는 모델 컨텍스트 프로토콜(MCP) 서버를 중앙 통제하는 기능을 정식 출시했다. 엔터프라이즈 관리자는 `copilot/managed-settings.json` 파일에 `allowedMcpServers`와 `deniedMcpServers` 항목을 추가해 승인된 서버는 허용하고 신뢰하기 어렵거나 규정을 충족하지 않는 서버는 차단할 수 있다.

정책은 원격 서버 URL, 로컬 실행 명령과 인수, 사용자가 지정한 서버 이름을 기준으로 MCP 서버를 식별한다. 다만 서버 이름은 사용자가 바꿀 수 있어 보안 통제 수단이 아닌 편의 기능으로만 제공된다. 잘못됐거나 검증할 수 없는 설정은 허용하지 않는 실패 폐쇄 방식이 적용되며, 여러 관리 계층에서 정책을 설정했다면 MCP 서버가 모든 계층의 조건을 통과해야 한다.

현재 이 정책은 GitHub Copilot 앱과 Copilot CLI, VS Code에서 적용된다. 설정하려면 소스 조직의 `.github-private` 저장소에 관리 설정 파일을 추가하고 기본 브랜치에 커밋해야 한다.

## 왜 중요한가

MCP 서버는 AI 도구가 외부 데이터와 기능에 접근하도록 연결하는 통로다. 기업에서 승인되지 않은 서버가 실행되면 내부 보안 정책이나 규제 준수 기준과 충돌할 수 있다. 이번 기능을 이용하면 개별 개발자의 설정에만 의존하지 않고 조직 전체에 공통된 허용·차단 기준을 적용할 수 있다.

특히 여러 팀과 개발 환경에서 Copilot을 운영하는 국내 기업에는 MCP 도입 범위를 중앙에서 관리할 수 있다는 의미가 있다. 서버 관리형 배포에서는 기본 정책을 유지하면서 팀별로 추가 허용·차단 목록을 정의하도록 설정할 수도 있어, 전사 기준과 팀별 필요를 함께 반영할 수 있다.

## 확인 범위

GitHub Changelog에 공개된 기능 설명과 적용 대상, 설정 방식이 확인됐다. 기능은 일반 제공 상태다. 다만 개별 요금제의 이용 조건, 클라이언트별 지원 버전, 기존 MCP 설정과의 세부 호환성은 제공된 자료에서 확인되지 않았다. 실제 도입 전에는 GitHub의 최신 관리형 설정 문서와 매처 구문을 추가로 확인할 필요가 있다.
