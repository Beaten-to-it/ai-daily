## 무엇이 있었나

AWS가 Amazon Bedrock AgentCore를 활용해 AI 주도 개발 수명주기(AI-DLC)를 구현하는 두 가지 참조 사례를 공개했다. AI가 설계와 구현, 검증 등 반복 작업을 맡되 주요 기술 결정과 결과 검토는 사람이 담당하는 구조다.

첫 번째 사례는 SQL 스키마를 분석해 Mermaid 형식의 개체 관계도(ER 다이어그램)를 자동 생성한다. Amazon S3에 SQL 파일이 올라오면 AWS Lambda가 AgentCore Runtime을 호출하고, 에이전트가 테이블·제약조건·외래 키 등의 메타데이터를 분석해 결과를 다시 S3에 저장한다. 실제 행 데이터는 읽지 않으며, 대규모 스키마는 여러 구간으로 나눠 처리한다.

두 번째 사례는 GitLab 파이프라인에서 전달된 Python 또는 Java 코드를 대상으로 보안 취약점과 의존성의 CVE 위험, 조직 정책 위반 여부를 분석한다. 코드 분석 에이전트와 정책·CVE 검사 기능을 분리하고, AgentCore Gateway와 MCP를 통해 각 도구를 연결했다. 분석 결과와 품질 점수, 권고 사항은 AgentCore Memory에 보관해 웹 대시보드에서 비교·조회할 수 있도록 구성했다.

AWS는 이와 함께 Kiro, OpenAI ChatGPT Codex, Claude Code 같은 로컬 개발 도구를 AgentCore 기반 클라우드 실행 환경과 연계하는 흐름도 제시했다. 요구사항 구체화와 코드 작성은 로컬 에이전트가 지원하고, CI/CD 단계의 보안 검증과 운영 자동화는 AgentCore가 담당하는 방식이다.

## 왜 중요한가

이번 사례는 AI 코딩 도구를 개인 개발자의 코드 생성 보조 수단에 머물게 하지 않고, 설계부터 배포 전 검증과 운영까지 이어지는 개발 절차에 편입하는 구체적인 방법을 보여준다. 특히 에이전트별 책임을 분리하고 사람이 중간 결과를 검토하도록 한 점은 기업 환경에서 자동화 범위를 통제하는 데 의미가 있다.

한국 기업도 데이터베이스 문서의 최신 상태 유지나 반복적인 보안 점검처럼 인력 소모가 큰 업무에 같은 패턴을 적용할 수 있다. 다만 실제 도입 때는 모델 출력만 신뢰하기보다 기존 코드 리뷰와 보안 심사를 유지하고, 접근 권한과 자격증명 관리, 추적 기록, 대용량 입력 처리 방식을 함께 설계해야 한다.

## 확인 범위

AWS ML이 공개한 기술 설명과 참조 구현의 구성, 처리 흐름, 권장 사항을 확인했다. 소개된 두 시스템은 AWS Samples 기반 구현 사례이며, 모든 조직이나 실제 운영 환경에서 동일한 성능과 보안 수준을 보장한다는 의미는 아니다. 품질 점수의 산정 정확도, CVE 탐지율, 처리 비용과 지연 시간, 대규모 운영 성과에 관한 독립 평가 수치는 원문에서 제시되지 않았다.
