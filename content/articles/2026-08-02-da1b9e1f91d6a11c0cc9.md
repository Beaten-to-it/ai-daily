## 무엇이 있었나

17,155줄에 이르던 Rust 데이터 접근 계층을 단계적으로 리팩터링한 실험에서, 동일한 기능 변경에 필요한 AI 코딩 에이전트의 입력 토큰이 15만9,564개에서 2만7,360개로 약 83% 감소했다.

전체 코드량은 거의 유지됐지만 관련 코드를 응집도 높은 모듈로 분리하면서 에이전트가 읽어야 할 파일 범위가 줄었다. 최종적으로 데이터 계층은 19개 Rust 파일로 나뉘었고, 최대 파일 크기는 3,695줄까지 작아졌다. 반면 출력 토큰과 실제 구현량은 큰 차이가 없었다.

실험에서는 매 단계마다 새로운 하위 에이전트에 같은 변경을 맡겨 이전 작업의 영향이 섞이지 않도록 했다. 다만 토큰 수는 송수신 문자 수를 바탕으로 근사했으며, 전체 리팩터링에는 사람의 구체적인 계획과 지시가 필요했다.

## 왜 중요한가

이번 사례는 리팩터링의 효과가 사람의 가독성뿐 아니라 AI 개발 비용과 작업 맥락에도 직접 나타날 수 있음을 수치로 보여준다. 코드 총량보다 작업에 필요한 최소 맥락을 얼마나 정확히 분리할 수 있는지가 에이전트 효율에 더 중요할 수 있다는 의미다.

한국 개발 조직에서도 생성형 AI가 작성하는 코드가 빠르게 늘어나는 만큼, 거대한 파일과 뒤섞인 책임을 방치하면 이후 변경 때마다 불필요한 토큰과 탐색 시간이 반복해서 발생할 수 있다. 다만 이 실험에서 계산한 변경 1회당 입력 비용 절감액은 약 0.397달러에 그쳤다. 따라서 경제성은 토큰 가격만이 아니라 변경 빈도, 디버깅 시간, 장애 대응, 사람의 이해도 개선까지 함께 평가해야 한다.

또한 AI가 좋은 구조를 자동으로 선택할 것이라는 기대에는 주의가 필요하다. 해당 사례에서는 중복 제거와 책임 분리, 파일 경계 설정을 사람이 단계적으로 안내해야 했으며, 단순히 파일을 잘게 나누는 것만으로 같은 효과가 보장되지는 않았다.

## 확인 범위

GeekNews에 게시된 요약과 실험 설명을 기준으로 작성했다. 83% 감소 수치는 특정 Rust 코드베이스에서 하나의 대표 변경을 반복한 결과로, 다른 언어·프로젝트·모델에서도 재현된다고 볼 수는 없다.

리팩터링 자체에 투입된 토큰과 인건비는 정확히 측정되지 않았고, 더 복잡한 기능이나 장기 유지보수에서도 절감 효과가 누적되는지는 확인되지 않았다. 토큰 측정 역시 실제 사용량 계측이 아니라 문자 수를 이용한 근삿값이라는 한계가 있다.
