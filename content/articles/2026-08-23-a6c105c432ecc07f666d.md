## 무엇이 있었나

파나소닉 항공전자(Panasonic Avionics Corporation)가 AWS 및 AWS 생성형 AI 혁신센터와 협력해 항공기 기내 엔터테인먼트·통신(IFEC) 시스템의 장애를 분석하는 멀티 에이전트 진단 체계를 구축했다.

이 시스템은 운항 데이터를 표준화해 저장한 뒤 성능 지표와 서비스 저하 징후를 분석한다. 이상이 감지되면 여러 진단 에이전트가 구성 간 상관관계, 시스템 상태, 로그 패턴을 병렬로 조사한다. 이후 Amazon Bedrock에서 구동되는 Anthropic Claude가 결과를 종합해 원인 가설과 영향 범위, 대응 우선순위를 담은 보고서를 만든다.

주요 구성 요소로는 Amazon S3와 Apache Iceberg 기반 데이터 레이크하우스, AWS Glue와 Amazon EMR의 데이터 처리 파이프라인, LangGraph 및 Strands Agents SDK를 활용한 Amazon SageMaker 기반 에이전트 실행 환경이 쓰였다. 과거 장애 사례는 Amazon RDS의 pgvector를 이용해 검색한다.

파나소닉 항공전자는 내부 시험에서 기존에 수시간 걸리던 수동 조사를 수분 단위의 자동 분석으로 줄였다고 밝혔다. 현재는 운영 중인 항공기군을 대상으로 매일 진단 보고서를 생성하며, 특정 적용 사례에서는 운영 효율이 20~40% 개선됐다고 설명했다.

## 왜 중요한가

이번 사례는 생성형 AI가 일반적인 질의응답을 넘어 복잡한 산업 설비의 이상 탐지와 원인 분석에 적용되는 흐름을 보여준다. 특히 서로 다른 설정을 가진 대규모 항공기 시스템에서는 단일 로그보다 여러 운항 데이터와 과거 정비 이력을 함께 살피는 일이 중요하다. 다수의 전문 에이전트를 병렬로 투입하면 반복적인 조사 시간을 줄이고 숙련자의 경험을 조직 전체에서 재사용할 가능성이 커진다.

한국의 항공·제조·통신 사업자에도 참고할 만한 지점이 있다. 시스템마다 다른 용어와 구성을 온톨로지로 정규화하고, 생성형 모델은 요약과 오류 추론에 제한적으로 활용하며, 실제 조치에는 사람의 승인을 남겼다는 점이다. 이는 산업 현장에서 AI 자동화의 속도뿐 아니라 설명 가능성과 통제 장치를 함께 설계해야 한다는 의미다.

## 확인 범위

기사에 제시된 아키텍처와 성과는 AWS가 소개한 파나소닉 항공전자의 내부 구축 사례를 기준으로 확인했다. 20~40%라는 개선 폭은 모든 운영 환경에 공통으로 적용되는 수치가 아니라 특정 사용 사례에서 측정된 결과다. 세부 평가 데이터와 측정 방법, 비용, 오류율은 공개된 내용만으로 독립 검증하기 어렵다.

진단 결과는 운영 데이터와 과거 사례에 근거하도록 설계됐으며 결정론적 업무 규칙으로 검증된다. 운영상 중요한 장애의 최종 대응은 엔지니어가 검토하고 승인한다. AWS 역시 데이터 특성과 운영 조건, 시스템 구성에 따라 실제 결과가 달라질 수 있다고 밝혔다.
