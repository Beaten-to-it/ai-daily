## 무엇이 있었나

깃허브 코파일럿의 실제 운영 환경에서 수집한 대규모 사용 기록을 분석한 논문이 공개됐다. 연구 대상은 2026년 6월 표본으로, 이용자 320만 명의 1,300만 세션에서 발생한 LLM 호출 7억6,100만 건과 토큰 95조 개를 포함한다.

분석 결과, 에이전트형 코딩은 사용자가 드문 간격으로 지시를 내리면 모델이 여러 차례 추론하고 도구를 실행하는 구조를 보였다. 한 번의 사용자 지시 안에서는 KV 캐시 적중률이 평균 90%였지만, 다음 지시로 넘어가면 55%로 낮아졌다. 모델 변경이나 컨텍스트 압축도 캐시 활용을 크게 떨어뜨리는 요인으로 관찰됐다.

연구진이 설계한 경량 예측기는 사용자가 다음 지시를 내리기 전까지 발생하는 전체 유휴 시간의 86~90%를 포착했다. 이를 바탕으로 컴퓨팅 자원을 선제적으로 재배치할 가능성도 제시했다.

## 왜 중요한가

코딩 에이전트는 질문 한 번에 답변 하나를 생성하는 일반 챗봇과 부하 구조가 다르다. 짧은 사용자 지시 뒤에 모델 호출과 도구 실행이 연속적으로 이어지고, 세션별 토큰 사용량과 작업 시간도 편차가 크다. 기존 챗봇 중심의 LLM 서빙 방식을 그대로 적용하면 캐시와 연산 자원을 비효율적으로 사용할 수 있다는 의미다.

국내에서 코딩 에이전트나 사내 개발 도구를 운영하는 기업에도 직접적인 시사점이 있다. 사용자 대기 구간을 예측해 자원을 조정하고, 모델 전환이나 컨텍스트 압축이 캐시에 미치는 영향을 함께 고려해야 응답 속도와 인프라 비용을 안정적으로 관리할 수 있다.
